# RGB 辅助眨眼剔除与分割归一化瞳孔指标实施计划

> 日期：2026-09-11  
> 状态：`implementation_plan_pending_validation`  
> 作用：在现有 NIR pupil-only（仅瞳孔）正式主线之外，新增 RGB（可见光视频）辅助眨眼伪迹控制与 `seg_pupil_fraction_within_pupil_iris` 候选指标。  
> 与既有文件关系：本文件保留 `NIR分析/1.3-分割归一化瞳孔指标与眨眼遮挡敏感性验证计划_20260910.md` 中的新指标定义，但以 RGB 逐次眨眼事件 + NIR QC（质量控制）的联合掩码替代原先仅依赖 NIR QC 代理的眨眼处理方案。原 `1.3` 的眨眼专项部分由本文件更新；原正式主指标和既有监督学习冻结规则不被本文件自动改写。

## 一、当前代码事实与本轮目标

当前 `Attention-Analysis/codex/formal-analysis-v2-portable` 的 NIR analysis-ready（分析就绪）正式连续轨道以 `pupil_geom_mean_diameter`（瞳孔椭圆两轴几何平均直径）为基础。逐眼先按 session×eye（场次×眼别）中心化，再构造 left/right/binocular（左眼/右眼/双眼）primary/strict（主/严格）轨道；`binocular_primary` 是当前主轨道。现有候选指标表另保留 `hard_pupil_fraction`（硬分割瞳孔比例）等候选，但没有生成本文件定义的分割归一化比例。

fullclass-final producer（正式 RITnet 生产器）的当前实现已经确认：RITnet 四分类为 background（背景）、sclera（巩膜）、iris（虹膜）、pupil（瞳孔）；`hard_*_fraction` 均由同一 `valid_source_mask`（真实来源有效像素掩码）中的类别像素数除以同一个 `analysis_valid_pixel_count` 生成，人工 replicate padding（复制填充）不进入科学分母。因此 `hard_pupil_fraction` 与 `hard_iris_fraction` 的分母语义一致，可以在下游安全构造本文件的新比例，而不需要重新运行 RITnet。

RGB 正式下游当前已经生成逐次 `algorithm_defined_blink_candidate`（算法定义眨眼候选事件），事件表保留 `start_unix_ms`、`end_unix_ms`、`duration_ms` 和 `blink_event_id`。当前事件检测基于双眼归一化 EAR（eye aspect ratio，眼睛纵横比）和时间连续性规则；但配置明确记录 `manual_visual_validation_performed: false`，因此现阶段应把 RGB 事件用于辅助眨眼掩码，并在正式放行前完成时间同步和最小事件有效性验证，不把它直接写成已验证的眨眼真值。

本轮有两个相连目标：

1. 用 RGB 逐次眨眼事件定位 NIR 中最容易受眼睑闭合/重新睁眼影响的时间段，再与 NIR 自身 QC 合并，得到逐帧 `combined_valid`（联合有效）掩码；
2. 新增 `seg_pupil_fraction_within_pupil_iris`，检验相对于当前几何平均直径，它能否在减少整体像素尺度影响的同时保留稳定的注意状态和行为信息。

## 二、新增分割归一化瞳孔指标

### 2.1 定义

新候选指标固定定义为：

\[
R_{seg}
=
seg\_pupil\_fraction\_within\_pupil\_iris
=
\frac{hard\_pupil\_fraction}
{hard\_pupil\_fraction+hard\_iris\_fraction}
\]

由于两个 fraction（比例）共享 `analysis_valid_pixel_count` 分母，该式在当前 fullclass-final producer 语义下等价于：

\[
R_{seg}
=
\frac{hard\_pupil\_pixels}
{hard\_pupil\_pixels+hard\_iris\_pixels}
\]

含义仅限于“RITnet 分出的 pupil+iris（瞳孔+虹膜）硬分类区域中，pupil（瞳孔）占多少面积”。它不是传统 PIR（pupil-to-iris ratio，瞳孔-虹膜直径比），不使用虹膜椭圆或虹膜直径，也不做平方根转换。

### 2.2 派生与有效性规则

逐帧计算必须满足：

1. `hard_pupil_fraction` 和 `hard_iris_fraction` 来自同一 session、phase、phase_segment、frame_idx、eye（场次、阶段、阶段分段、帧、眼别）行；
2. 两个字段均有限且位于 `[0,1]`；
3. 分母 `hard_pupil_fraction + hard_iris_fraction > 0`；
4. 来源帧已观测、RITnet 成功，且不是人为 interpolation-only（仅插值）记录；
5. 任一来源字段缺失时保持缺失，不做 0 填充，不跨帧或跨眼插补。

`R_seg` 是 segmentation-derived metric（分割派生指标），不应因为瞳孔椭圆拟合失败就自动判为无效。因此它需要独立于现有 `pupil_valid_primary` 的 segmentation-valid（分割有效）标记。建议新增：

- `rseg_valid_base`：来源可观测、RITnet 成功、两个 hard fraction 合法、分母大于 0、非 interpolation-only；
- `rseg_valid_strict`：`rseg_valid_base` 基础上，再排除当前 ROI/domain（感兴趣区/分析域）限制和 temporal anomaly（时序异常）记录；
- `qc_pupil_fragmented`、`analysis_valid_pixel_fraction`、valid-domain edge（有效域边缘）相关字段保留为单独 QC，不在本轮根据 Q1/Q2 或行为结果事后发明新阈值。

这样可以区分“RITnet 分割比例能算”与“椭圆几何能可靠拟合”两个不同的测量问题。

## 三、RGB + NIR QC 联合眨眼伪迹控制

### 3.1 基本原则

RGB 负责回答“什么时候发生了明显双眼闭合事件”，NIR QC 负责回答“这个时点的瞳孔分割/几何测量是否可信”。两者不互相替代。

每个场次生成：

```text
RGB blink candidate events
→ 时间同步与事件区间扩展
→ rgb_blink_mask

NIR source / RITnet / geometry / temporal QC
→ nir_qc_invalid

rgb_blink_mask OR nir_qc_invalid
→ combined_invalid
→ combined_valid
```

RGB 为双眼事件时，眨眼区间同时作用于同一场次的左右眼 NIR 帧；NIR 眼别特异 QC 仍分别保留。

### 3.2 时间同步必须先于剔除

RGB 与 NIR 都有 `unix_ms`，但字段同名不能代替同步验证。实现前必须逐 session（场次）审计：

1. RGB 与 NIR 录制时间范围是否重叠；
2. 公共实验阶段/探针等可核验锚点的时间差是否稳定；
3. 是否存在固定 offset（时间偏移）、漂移或中途重启；
4. 事件映射后的 nearest-frame delta（最近帧时间残差）分布；
5. 无法可靠同步的场次不得静默应用 RGB 眨眼掩码，应写入 failure/audit table（失败/审计表）并保留 NIR-only QC 轨道。

同步允许误差由相机采样间隔和实际时间残差预先确定，不依据 Q1、Q2、行为效应或模型性能调节。

### 3.3 眨眼前后污染区间

文献中的常见处理表明，眨眼本身之外还应处理闭眼前后因部分遮挡和重新睁眼产生的边缘伪迹。FocusWave 不直接照抄单一固定窗口，而采用先验候选窗口 + NIR 事件对齐 QC 冻结的方式。

预设三个候选：

| 方案 | RGB 事件前 | RGB 事件后 | 作用 |
|---|---:|---:|---|
| A | 50 ms | 50 ms | 接近经典 pupil gap 边缘剔除的保守下限 |
| B | 100 ms | 300 ms | 首选候选；覆盖闭眼前与重新睁眼后较长恢复段 |
| C | 200 ms | 200 ms | 对称较宽敏感性方案 |

正式冻结前只使用纯测量 QC 判断，不查看 Q1/Q2 或行为显著性：把所有 RGB blink onset/offset（眨眼开始/结束）对齐，观察 `pupil_geom_mean_diameter`、`R_seg`、有效率、瞬时变化速度和 NIR QC 在眨眼前后多久恢复到稳定范围。若方案 B 已覆盖主要边缘异常，则把 B 作为主清洗窗口，A/C 作为敏感性；若实际恢复明显不同，应在查看心理结果前记录并冻结新的技术窗口。

### 3.4 联合无效掩码

至少保存以下逐帧布尔字段：

- `rgb_blink_core`：位于 RGB 眨眼事件本身；
- `rgb_blink_buffered`：位于事件加前后缓冲的区间；
- `nir_source_invalid`：NIR 来源缺失/RITnet 失败；
- `nir_geometry_invalid`：几何轨道所需瞳孔拟合无效；
- `nir_temporal_invalid`：当前时序异常；
- `nir_roi_or_domain_flagged`：ROI/有效域边缘或填充相关 QC；
- `combined_invalid_geometry`：RGB buffered blink 或当前几何正式轨道无效；
- `combined_invalid_rseg`：RGB buffered blink 或 `R_seg` 自身分割轨道无效。

同时保留 reason code（原因编码），避免以后只看到一个 `valid=false` 而无法区分是眨眼、NIR 缺失、分割失败还是几何拟合失败。

## 四、窗口指标如何重新计算

### 4.1 不用插值计算正式 30 s 统计量

当前主窗口继续为 probe-pre 30 s（探针前 30 秒），10 s/20 s 按既有规则作为敏感性窗口。对 `pupil_geom_mean_diameter` 和 `R_seg` 均在 `combined_valid` 帧上重新计算：

- level（水平）：median（中位数）、mean（均值）；
- variability（变异性）：SD（标准差）、MAD（中位数绝对偏差）、IQR（四分位距）；
- trend（趋势）：当前稳健时间分箱斜率；
- dynamic QC（动态质量审计）：相邻变化 MAD、按秒变化率 MAD、高分位瞬时变化幅度等。

**用于正式 level/variability/trend 的帧不对眨眼缺口做线性、样条或其他插值。** 原因是插值会人为平滑序列并改变 SD、MAD、IQR 和动态变化，这与本研究要直接解释“瞳孔变异性”的目标冲突。

短缺口插值只允许用于轨迹图的连续视觉显示或单独的 time-course sensitivity（时间轨迹敏感性）分析，插值轨道必须独立命名，不能回流到正式窗口统计。

### 4.2 每个窗口新增眨眼/覆盖审计

每个 probe-pre 窗口至少输出：

- `rgb_blink_event_n`；
- `rgb_blink_core_duration_ms`；
- `rgb_blink_buffered_duration_ms`；
- `rgb_blink_masked_fraction`；
- `nir_qc_invalid_fraction`；
- `combined_invalid_fraction`；
- `combined_valid_fraction_geometry`；
- `combined_valid_fraction_rseg`；
- RGB/NIR 同步状态和最大/中位时间残差。

暂不根据这些覆盖率字段自动设新的 `<80%` 排除门槛；与项目现有质量筛选治理一致，先审计、报告和做敏感性分析，若以后需要硬阈值必须另行冻结。

## 五、需要比较的四条数据轨道

为了知道眨眼处理到底改变了什么，至少同时保留：

1. `original_nir`：当前既有 NIR 有效性逻辑；
2. `rgb_blink_only`：仅加入 RGB buffered blink 掩码；
3. `nir_qc_only`：强化 NIR QC、但不使用 RGB；
4. `rgb_plus_nir_qc`：本文件推荐主候选，即两者并集。

比较内容包括：有效帧比例、几何直径和 `R_seg` 的窗口水平/SD/MAD/IQR/趋势、左右眼一致性、primary/strict 轨道一致性，以及 Q1、Q2、行为关系的方向和不确定性。比较目的在于判断既有结果是否被少量眨眼/遮挡异常帧驱动，不按显著性选择最“好看”的清洗方法。

## 六、眨眼本身作为生理/行为变量的处理

RGB 眨眼不能只作为要删除的坏数据，因为眨眼率本身可能和 vigilance/attention（警觉/注意）变化有关。因此：

1. RGB 的 `blink_event_rate_per_min` 等眨眼指标继续作为独立 RGB 候选变量，不因其参与 NIR QC 而删除；
2. 在 NIR Q1/Q2 或行为关联敏感性模型中，可加入同窗口 `blink_event_n`、blink rate（眨眼率）或 blink duration burden（眨眼持续负荷）作为协变量，检查 NIR 关系是否独立于“只是更爱眨眼”；
3. 眨眼后数秒级的真实 blink-related pupil response（眨眼相关瞳孔反应）不通过扩大删除窗口直接处理。若后续事件对齐结果显示明显且系统性的数秒响应，再单独考虑 FIR deconvolution（有限脉冲响应去卷积）或事件回归敏感性分析。

## 七、代码实现落点

建议在 `Attention-Analysis/codex/formal-analysis-v2-portable` 的后续独立实现分支完成，不修改 RITnet producer 原始输出。

### 7.1 `R_seg` 派生

优先修改/扩展：

- `src/attention_pipeline/nir_analysis_ready/candidate_metrics.py`
- pupil-only candidate sidecar（仅瞳孔候选侧表）相关 tests（测试）

实现步骤：

1. 在 `adapt_session_rows()` 已保留的 `hard_pupil_fraction` 与 `hard_iris_fraction` 上计算 `seg_pupil_fraction_within_pupil_iris`；
2. 新增独立 segmentation-valid 合法性字段，不强制依赖 `pupil_fit_valid`；
3. 生成 raw/centered/robust-z（原值/中心化/稳健 z）版本时沿用 session×eye 内部标准化逻辑，但不要把中心化值解释为传统 PIR；
4. availability/QC manifest（可用性/质量清单）必须列出分母为 0、字段缺失、来源失败等不可计算原因；
5. 现有 `pupil_geom_mean_diameter`、`hard_pupil_fraction` 等输出在功能关闭或新字段加入后必须数值完全不变。

### 7.2 RGB 眨眼掩码与 NIR 对齐

建议新增独立模块，例如：

`src/attention_pipeline/nir_formal_analysis/rgb_blink_mask.py`

输入：

- RGB `*_blink_candidate_events.parquet`；
- NIR analysis-ready frame table；
- session identity/time fields；
- 预冻结的前后 buffer（缓冲）配置。

输出使用 sidecar（侧表）而不改写原 NIR producer：

- frame-level blink/QC mask；
- session-level synchronization audit（场次级同步审计）；
- failure table；
- probe-window blink burden（探针窗口眨眼负荷）与 clean coverage（清洗后覆盖率）。

### 7.3 配置

在 NIR 正式配置中新增独立段，示意：

```yaml
blink_artifact_control:
  source: rgb_algorithm_defined_blink_candidate
  active: true
  primary_pre_buffer_ms: 100
  primary_post_buffer_ms: 300
  sensitivity_buffers_ms:
    - [50, 50]
    - [200, 200]
  combine_with_nir_qc: union
  interpolate_for_window_statistics: false
  interpolation_for_visualization_only: true
  require_session_time_alignment_audit: true
```

最终字段名以实现代码为准，但配置必须让主窗口和敏感性窗口可追溯，不能硬编码散落在脚本中。

## 八、必须新增的 test（测试）

### 8.1 `R_seg` 契约测试

1. 已知 pupil/iris fraction 可得到手算结果；
2. 两者乘相同常数时 `R_seg` 不变；
3. pupil↔iris 类别边界转移会改变 `R_seg`，明确说明它不能自动抵消分割边界错误；
4. 分母为 0、NaN、Inf 时输出缺失/失败状态；
5. 不跨眼、不跨帧拼接；
6. `hard_pupil_fraction` 与 `hard_iris_fraction` 必须来自同一 analysis domain；
7. 新功能不改变既有几何直径和候选指标结果。

### 8.2 RGB–NIR 对齐与掩码测试

1. 已知 RGB event 区间能映射到正确 NIR `unix_ms` 帧；
2. buffer 前后边界精确；
3. 相邻/重叠眨眼区间自动 union（并集），不会重复计算 masked duration；
4. 左右眼同一时刻都收到 bilateral blink（双眼眨眼）事件掩码；
5. NIR 眼别特异 QC 仍只作用于对应眼；
6. 无 RGB、不同步 RGB 或事件文件缺失时明确降级为 NIR-only QC，并写审计状态，不静默删场次；
7. 不允许 RGB 眨眼掩码跨 session、跨 phase 错配；
8. 关闭新功能时原 NIR 正式输出完全回归一致。

## 九、数据验证与放行条件

本计划进入正式候选分析前需依次通过：

1. producer 代码契约：当前 fullclass-final 已确认 hard pupil/iris fraction 共享真实来源有效像素分母；
2. `R_seg` 单元/回归测试全部通过；
3. RGB–NIR session-level（场次级）时间同步审计通过，失败场次有明确状态；
4. RGB 眨眼事件与 NIR 眼睑遮挡/瞬时异常至少呈现合理事件对齐关系；必要时做小规模人工视频核查，但不要求重新训练 RGB 模型；
5. 预设 buffer 的冻结只依据眨眼周围测量恢复，不查看 Q1/Q2、行为显著性或预测性能；
6. `rgb_plus_nir_qc` 清洗后不会造成大规模不可用窗口，并明确报告数据损失；
7. SD、MAD、IQR 与趋势结论不应只由某一种清洗规则或极少数异常窗口决定；
8. `R_seg` 与几何平均直径的关系、冗余、视觉混杂、左右眼稳定性和注意/行为关联均完成候选验证后，才决定其是否进入后续监督学习特征冻结。

## 十、当前方法学定位

本文件确认可以实现 `R_seg`，且**不需要重新运行 YOLO 或 RITnet**；当前生产输出已经包含所需 hard pupil/iris fraction。需要重新执行的是下游 candidate materialization（候选物化）、RGB–NIR blink mask（眨眼掩码）对齐和受影响的 NIR window tables（窗口表）。

在验证完成前：

- `pupil_geom_mean_diameter` 继续是当前 NIR 连续正式主线；
- `R_seg` 为新增 candidate/sensitivity（候选/敏感性）指标；
- RGB 眨眼事件作为辅助伪迹定位，不作为已经人工验证的眨眼真值；
- RGB+NIR QC 联合清洗作为新的推荐候选预处理轨道，与原 NIR 轨道并行比较，不事后按心理学结果挑选规则。

## 十一、文献依据

眨眼导致的部分眼睑遮挡会在瞳孔序列边缘制造异常骤降/骤升。Kret & Sjak-Shie（2019）建议根据数据和设备经验过滤异常瞳孔变化，并将较长缺失段附近约 50 ms 的边缘样本视为可疑；其核心原则是先识别有效样本，再对连续轨迹做后续处理。Psychophysiology 的 pupillary measurement（瞳孔测量）方法建议总结指出，不少流程会使用眨眼/伪迹前后最高约 200 ms 的数据确定插值边界。关于 mind wandering（走神）的研究也使用过眨眼前 100 ms 到后 300 ms 的保守区间，以避免眼睑闭合和重新打开污染瞳孔变化速度。

这些文献用于限定候选范围，不替代 FocusWave 自身的事件对齐 QC；正式 buffer 仍应在不查看心理效应结果的前提下根据本数据的伪迹恢复范围冻结。

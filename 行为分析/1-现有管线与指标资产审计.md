## 五、Go/No-Go、d′、c、β计算契约

当前BB代码在Block层的计算口径是可追溯的：

1. `go = block[is_no_go == 0]`，`nogo = block[is_no_go == 1]`。
2. 命中数 `hits = sum(go.correct == 1)`，含义为正确Go；虚警数 `false_alarms = sum(nogo.commission == 1)`，含义为No-Go误按。
3. 命中率和虚警率均使用对数线性/极端比例校正：`(successes + 0.5) / (opportunities + 1.0)`。这避免了0和1输入直接进入正态分位数。
4. `d′ = z(H) − z(FA)`；`c = −(z(H) + z(FA))/2`，代码注释中`c<0`表示偏宽松、倾向按键；`β = φ(z(H))/φ(z(FA))`，作为辅助反应标准指标。
5. 当前Block层没有最低No-Go或Go机会数门控，只有机会数为0或率非有限时返回缺失。当前原始B1/B2的48个No-Go机会和384个非No-Go机会足以支持工程计算，但“可计算”不等于已完成正式可靠性验证。

本次代码试跑验证了极端比例修正：在384个Go全部命中、48个No-Go零误按时，命中率为0.998701、虚警率为0.010204，d′、c、β均为有限值；反向极端比例同样不产生无穷值。这个结果只验证函数行为，不构成样本结果。

周期bin和探针层没有调用该SDT函数，因此不能从现有输出声称它们已有d′、c、β。正式扩展时必须先声明每一聚合单位的Go机会数、No-Go机会数、最低门控、缺失状态和极端比例修正；低机会单位应留缺失并报告原因，而不是补成0或强行估计。

## 六、错误、遗漏、RT和探针资产

`commission`、`omission`、RT和预判按键在原始表中是分开的字段，历史Block实现也分别计算No-Go误按率、Go漏按率和正确Go RT。历史BBB资产还提供错误前RT轨迹、探针前后窗口和Q1/Q2图表结构，这些可以作为方法参考。

但当前BB代码仍有以下缺口：

- RT水平有均值、中位数和SD；RT-CV只在Block及周期bin使用计数门控20，探针前8个Go的CV没有同样的最低门。
- RT斜率只作为`rt_drift_mixedlm()`的试次模型参数，没有在探针前窗口、周期bin和场次层输出统一的稳健斜率字段。
- 当前BB没有ex-Gaussian以外的RT离散候选（例如IQR、MAD）在各尺度统一重算，也没有把错误前后轨迹形成标准化事件表。
- 探针Q1/Q2的原始编码会保留，但当前BB配置注释要求语义仍需由最终任务源冻结；Q1不得做1–4均值，Q2只能作为有序变量候选。历史BBB报告的标签文字和数值不能自动搬到当前正式队列。
- 当前中央行为结果卡使用的探针前30秒、10秒和20秒窗口与历史BB代码的“前8个正确Go”不是同一窗口定义，不能混称为同一指标。

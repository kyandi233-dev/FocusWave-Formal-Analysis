# 国赛报告

本目录用于撰写 FocusWave 新版国赛报告。历史报告仅作为已经核验的方法、设备信息、写作规范和结果来源；新版正文依据现行实验程序、分析方法和实际结果重新组织。

## 正文写作规则

报告采用心理学论文与科研竞赛报告语体，研究问题、心理学含义和测量逻辑优先于工程实现细节。正文遵循以下规则：

1. 只使用能够直接说明研究设计、测量方法、统计分析和科学结果的语言，不写项目管理、代码执行状态、开发标签或内部工作流程。
2. 不写实验地点、机构身份、采集日期、版本日期等与科学解释无关的信息。
3. 设备名称使用已有报告依据能够确认的真实型号；操作系统中的设备枚举名称不作为设备型号。
4. 程序字段、配置键、内部方案编号和模型代号不直接进入正文，统一改写为读者可以理解的变量定义、测量含义和比较关系。
5. 影响科学解释的实验参数和分析参数保留在正文；压缩格式、底层数据结构、程序接口等实现细节不进入正文。设备参数集中使用表格呈现。
6. 英文专业术语或缩写首次出现时采用“中文名称（英文术语，缩写）”或“中文名称（缩写）”形式说明，之后优先使用中文名称或通用缩写；不反复中英并列。
7. 理论与文献综述只陈述现有研究能够支持的一般心理关系、测量意义和方法学原则。不得因为本研究已经采用某种题面、变量表示、时间窗口、指标组合或模型比较方案，就反向寻找文献将该项目选择写成学界通行结论。项目自身的操作化和分析方案在研究设计与方法章节说明。
8. 方法、结果和讨论严格分工。方法说明实际采用或已经预先确定的变量形成与分析规则；结果只报告真实分析得到的数据、效应、性能和不确定性；讨论再解释理论意义和研究边界。
9. 尚未确定的候选表示、尚待测量审计的参数和以后可能采用的分析不得以“可、若、如果、当……后”等条件式语句伪装成正式方法；需要保留时放入内部工作表或方法决策文档。
10. 结果正文不得用“将报告、用于评价、如果出现……”等方法说明或假设情景代替真实结果。正式输出尚未形成的结果小节保持空缺，填报规则放在不渲染的内部注释或工作表中。
11. 所有样本量均说明对应的分析单位。参与者、实验场次、试次、思维探针、时间窗和问卷份数不相互替代。
12. 设备输出与心理生理变量严格区分。毫米波结果使用“毫米波估计心率”“毫米波估计呼吸率”等表述；没有独立参考证据时，不写成已完成生理准确性验证。
13. 科学信息类别与设备来源分开：行为、眼部、动作和心肺是科学信息类别；近红外、RGB 和毫米波是采集设备或特征形成依赖。跨设备辅助处理不改变科学信息类别，但必须在设备依赖评价中如实反映。

## 当前章节

第 1 章“引言”以非接触持续注意测评系统的构建与评价为落脚点，说明任务与内容型思维探针的参照依据、传感信息独立预测与行为基础上的增量，并区分当前受控验证和未来跨场景使用。

第 2 章“理论与技术基础”包括持续注意构念与测量、SART 行为与思维探针、眼部动态、身体动作、心肺自主生理以及多模态与跨参与者泛化。该章保留适度超出本研究变量的理论与应用背景，说明外部证据的任务和测量边界，不提前写本研究的具体操作化方案。内容型探针的效度、报告预测的准确性及跨场景适用性分别论证。

第 3 章“研究目标与总体方案”以系统构建、传感信息自身及行为基础上的预测价值、跨参与者与设备配置评价为三个研究问题。总体方案连接任务参照、同步采集、指标形成、解释性分析与预测评价，并单列系统输出与后续扩展：首轮预测探针前 30 s 对应的任务聚焦报告概率，四分类和脱离 SART 的使用另行验证。

第 4 章“系统实现与研究方法”包括：

- `4.1-参与者、研究阶段与样本结构.md`
- `4.2-SART、思维探针与正式实验程序.md`
- `4.3-多设备布置、同步采集与原始数据来源.md`
- `4.4-科学变量形成、窗口化与质量控制.md`（正文标题为“分析指标形成、时间窗口与质量控制”）
- `4.5-解释性统计与主观信息关联分析.md`
- `4.6-跨参与者监督学习与多模态比较.md`

第 5 章按照“样本与测量基础 → 行为和主观状态 → 眼部 → 动作 → 心肺 → 跨参与者单类信息预测 → 多模态增量与条件预测价值 → 设备组合”组织。当前 5.1 已写行为/眼部/动作覆盖，5.2 已有正式行为结果，5.3 已写眼部测量资格结果，5.4 已有正式动作结果；5.5 尚无正式心肺心理效应，5.6–5.8 在正式模型结果生成前不得填入性能结论。

不依赖最终结果数值的方法型科研图可以在方法确定后进入视觉设计；结果型科研图只使用正式分析输出制作。

## 完整结果总账

`完整结果/` 是第 5 章之外的**完整结果证据层**。它不追求正文篇幅，而负责保存每项结论对应的输入、输出、表格、图件、样本分母、本地路径、Google Drive handoff、方法来源和当前证据身份。

完整结果文件使用**任务级整数编号 + 从属材料小数编号**：每一种独立任务/分析线使用新的整数编号，只有该任务内部的补充、复核、敏感性或从属材料才继续使用小数编号。汇总入口放在最前面。已经建立 README、正文、Drive handoff 或脚本映射的结果文件，原则上**不再改文件名和一级标题**；任务状态变化优先更新 `1-结果资产索引.md` 的成熟度总表和文件内容，避免破坏既有映射。

当前入口：

- `完整结果/README.md`：完整结果维护规范；
- `完整结果/1-结果资产索引.md`：全部结果资产的快速定位入口与结果成熟度总表；
- `完整结果/1.1-当前结果总览.md`：跨任务当前结果状态；
- `完整结果/1.2-本地Agent读取与核对说明.md`：local-only 大表、原始数据和未上传完整图件的本地读取规则；
- `完整结果/2-Behavior行为结果与资产.md`；
- `完整结果/3-Ocular眼部结果与资产.md`；
- `完整结果/4-Movement动作结果与资产.md`；
- `完整结果/5-Cardiopulmonary心肺结果与资产.md`；
- `完整结果/6-监督学习与多模态结果与资产.md`。

例如 Ocular 的新增补充材料使用 `3.1-...`，监督学习的新增从属任务使用 `6.1-...`；不得把独立任务继续挂在 `1.*` 下，也不使用 `00/01/90` 这类技术排序号。

### 完整结果维护要求

以后每当出现新的正式分析结果、重新物化、样本分母变化、特征/表示冻结、图表新增/替换、Google Drive final bundle 更新或会改变结果解释的错误，必须同步更新 `完整结果/`。

每个结果模块必须说明：

1. 科学问题与证据身份（正式结果 / 测量资格 / 敏感性 / QC / 待形成）；
2. 实际参与者、实验场次及更细分析单位；
3. 正式输入表及用途；
4. 正式输出表及用途；
5. 所有正式/补充/QC 图件及其源表；
6. 本地绝对路径；
7. Google Drive `_AI_HANDOFF` bundle 及文件名/链接；
8. 方法与代码来源；
9. 当前已知限制与未决事项。

重要且体量较小的结果表、覆盖表和冻结证据表可以直接复制进 Markdown；大型 probe/frame 级表、原始视频、Parquet、雷达数据和可再生中间产物不在 GitHub 重复存储，只登记大小、用途、本地路径和 Drive 是否有副本。对只能在本地核对的证据，必须按 `完整结果/1.2-本地Agent读取与核对说明.md` 的只读顺序和回报格式执行，不得仅凭本地存在某个中间文件就提升其证据等级。

**工作顺序要求：新的正式结果应先完成本地输出和 Drive handoff → 更新 `完整结果/` → 再修改第 5 章正文。若正式结果已经改变而 `完整结果/` 尚未同步更新，则结果交接视为未完成。**

## 证据要求

涉及实验参数时，以正式实验程序的实际执行逻辑为准；涉及行为、眼部、动作和心肺分析时，以当前正式方法文档、对应分析代码、配置和实际输出共同核对；涉及设备真实型号时，以已有实验记录和经过核验的历史报告为依据。来源之间出现差异时，正文采用与实际实验和当前正式分析规则一致的事实，并在工作记录中保留差异来源，不把版本核验过程写入正文。

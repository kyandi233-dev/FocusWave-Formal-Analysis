# 本地 Agent 读取与核对说明

本文件用于指导能够访问 FocusWave 本地 Windows 数据盘的 agent 对“完整结果总账”中无法仅依靠 GitHub 或 Google Drive 完成的证据进行只读核对。网页端结果总账负责记录科学结论和资产位置；本地 agent 负责从权威本地输出中读取大表、逐探针表、逐帧表或未上传的完整图件，并把可复核的小型摘要返回给结果总账。

## 1. 基本原则

1. **默认只读。** 除非任务明确要求重新运行或修改代码，否则不得改写、移动、覆盖或删除本地正式输出。
2. **先看总账，再读本地。** 开始任何核对前，先读取 `国赛报告/完整结果/1-结果资产索引.md` 和对应任务文件，确认当前权威路径、证据等级和待核问题。
3. **优先正式输出，不优先历史备份。** 同一指标存在多个版本时，以总账标记的当前权威根目录为准；备份目录只用于历史追溯。
4. **大表不整表上传。** 对 probe/frame 级大表，优先返回行数、列名、筛选条件、关键统计量、少量必要切片和 SHA256；只有任务明确要求时才生成新的 handoff 摘要文件。
5. **不得用 local-only 中间结果绕过正式方法。** 本地存在某个列或某个临时模型输出，不代表它已取得正式科学资格。是否能进入报告以对应完整结果文件和 Formal 方法合同为准。
6. **结果核对不等于重新分析。** 若只是复核报告数字，应读取正式结果表；不得为了得到“更漂亮”的数值临时重新拟合、改筛选阈值或换分析集合。

## 3. 推荐读取顺序

每次本地核对按以下顺序执行：

1. 读取对应 `完整结果/<任务>.md`，确认当前结论和权威根目录；
2. 读取 manifest、coverage、handoff、正式模型小表；
3. 若小表已经能回答问题，停止，不再扫描大表；
4. 只有在核对分母、异常窗口、具体 probe、来源模式或图源时，才读取大型 probe/frame 表；
5. 输出核对摘要，不在本地重新定义科学结论；
6. 若发现总账数字与本地权威表不一致，先报告冲突及两边来源，不自行覆盖任何一边。

## 5. 本地 agent 回报格式

每次核对至少回报：

| 字段 | 要求 |
|---|---|
| 任务 | Behavior / Ocular / Movement / Cardiopulmonary / Supervised |
| 权威文件 | 完整绝对路径 |
| 文件状态 | 是否存在、大小、修改时间（如有必要） |
| 数据规模 | 行数、列数或图件数 |
| 读取条件 | 实际筛选条件、分母、关键键值 |
| 核对结果 | 需要复核的数字/图件是否与总账一致 |
| 异常 | 缺失、重复、schema 差异、数值冲突 |
| 是否 local-only | 是/否；若 Drive 有副本则注明 bundle |
| 可回传证据 | 小型 CSV/JSON/日志/截图/哈希；不得默认上传原始大数据 |

如需形成新的 Google Drive handoff，应建立新的不可覆盖 bundle，并在回报中给出 bundle 名、文件清单、大小和校验结果。

## 6. 哪些内容通常只保留本地

通常 local-only 的内容包括：原始视频、原始雷达数据、逐帧表、数十至数百 MB 的 probe/trajectory 宽表、含参考 ECG/RSP 的逐探针诊断表、完整 SVG/PNG 图包中未进入 handoff 的部分、以及可由正式脚本稳定重建的大型中间产物。

“local-only”只表示存储与传输策略，不表示科学等级更高。正式结论仍以冻结方法、正式输出表和结果总账的证据身份为准。

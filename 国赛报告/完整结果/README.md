# FocusWave 完整结果总账

本目录是 FocusWave 国赛报告的**完整结果证据层**。它与 `章节草稿/5-*` 的职责不同：第 5 章正文负责面向评审者呈现必要的科学结果，本目录负责保存“这些结论究竟来自什么输入、经过什么正式分析、形成了哪些表和图、证据文件在哪里”的完整可追溯记录。

任何正式结果在进入报告正文前，都应能够从本目录追溯到对应的分析分母、输入表、结果表、图件、方法依据、本地输出路径和 Google Drive 交接证据。反过来，本目录可以记录尚未进入正文的质量控制和敏感性结果，但必须明确其证据身份，不能把它们与主科学结果混写。

`1-结果资产索引.md` 顶部的“当前结果成熟度总表”是判断各任务当前证据等级、正文可用性、完整程度和 local-only 依赖的统一入口。不要仅凭某个文件位于“完整结果”目录，就推断它已经是可进入第 5 章的正式科学结果。

## 一、结果证据等级

本目录统一使用以下五类状态：

| 状态 | 含义 | 能否直接进入结果正文 |
|---|---|---|
| **正式结果** | 方法与测量资格已经冻结，真实数据分析已形成正式效应或描述结果 | 可以 |
| **测量资格结果** | 回答指标是否可靠形成、覆盖率、表示选择和时间支持等问题 | 可以进入 5.1 或相应模态的测量基础部分 |
| **敏感性结果** | 用替代表示、辅助变量或预先规定的替代处理检查结论稳定性 | 仅在有解释价值时进入正文，其余放补充材料 |
| **质量控制（QC）** | 用于判断同步、覆盖、曝光、来源模式、伪迹等测量条件 | 通常不作为注意相关主结论 |
| **待形成** | 当前尚无满足正式证据要求的输出 | 不得填写性能或心理效应结论 |

接口 smoke（冒烟测试）只用于检查 schema、身份、时间合法性或接口能否接通，不自动产生正式科学结果；若未来 P5 形成 smoke 证据，应在监督学习任务下作为从属材料登记，并与后续正式 LOSO/性能结果严格分开。

## 二、每个结果模块必须记录的内容

每个科学信息类别的结果文件至少包含以下内容：

1. **科学问题与结果身份**：本模块回答什么问题，哪些是正式结果、测量资格、敏感性或 QC。
2. **分析样本与单位**：参与者数、实验场次数，以及对应的试次、思维探针、时间窗或其他分析单位；不同层级不得互相替代。
3. **正式输入**：真正进入该分析的上游表、关键字段/指标及其用途。
4. **正式结果**：关键效应估计、95% 置信区间、覆盖率或其他已冻结结果。重要且体量小的表格直接复制到本目录。
5. **输出表格清单**：文件名、用途、体量/行数、是否进入报告正文、本地路径和 Google Drive 位置。
6. **输出图件清单**：逐张记录图名、用途、正文/敏感性/QC 身份、源表、PNG/SVG 位置。不得只写“已绘图”。
7. **大文件与不可复制资产**：不在 GitHub 重复存放大型 CSV、原始视频、帧级表或可再生中间产物，只登记路径、用途和权威来源。
8. **方法与代码来源**：记录用于追溯的仓库、分支/commit、方法文档或正式报告章节。此部分只服务复核，不混入科学结果叙述。
9. **已知限制与未决事项**：例如同步异常、设备缺失、未完成的测量资格、尚未形成的正式模型结果。

## 三、路径记录与 local-only 规则

每项关键资产原则上同时记录两类位置：

- **本地权威路径**：使用实际 Windows 绝对路径，优先指向 `_FormalAnalysis` 下的正式输出；
- **Google Drive 证据路径**：优先指向 `_AI_HANDOFF/<bundle>/` 的真实交接目录。重要小文件如已有稳定单文件链接，可附单文件链接；未逐文件暴露链接时至少给出 bundle 文件夹与文件名。

Google Drive 总入口：`_AI_HANDOFF/`  
https://drive.google.com/drive/folders/1wZ6fHAyz4JMBwQ7LxL2fYZ9DdhO4XAfL

本目录不把 Google Drive 当作唯一数据仓库。大表、原始数据和视频可以仅保留在本地，但必须在资产索引中说明为什么没有上传以及如何定位。

需要访问 local-only 资产时，统一按 `1.2-本地Agent读取与核对说明.md` 执行。该说明规定本地权威路径、读取顺序、只读边界和回报格式。local-only 只是存储策略，不代表该文件自动拥有更高的科学证据等级。

## 四、小表直接嵌入、大表只做索引

以下内容优先直接放入 Markdown：样本与覆盖率表、关键模型效应表、表示一致性与冻结阈值等关键摘要、图件清单和正式结果表清单。

数万至数百万行的探针/帧级宽表、原始视频、Parquet、雷达原始数据、大型固定时间箱轨迹表和可稳定再生的中间产物通常不复制全文，只登记文件名、行数/大小、关键列、用途、本地绝对路径、Drive 是否有副本以及对应 bundle。

## 五、图表记录规范

每一张正式或补充图至少记录图件 ID / 文件名、科学问题、图件身份（main / qualification / sensitivity / qc）、源表、本地 PNG/SVG 路径、Drive 位置以及是否已进入第 5 章正文。只有真实分析输出可以进入结果图，不得提前创建占位数字或模拟曲线。

## 六、编号、文件结构与稳定映射

本目录采用**任务级整数编号 + 从属材料小数编号**，不使用 `00`、`01`、`90` 这类技术排序号。

规则：

- 每一种独立任务或分析线占一个新的整数编号；
- 该任务内部新增的从属、补充、复核或敏感性材料，才使用小数编号；
- 汇总入口放在最前面：总索引为 `1-`，其从属总览为 `1.1-`，本地读取说明为 `1.2-`；
- 新增独立任务时继续使用下一个整数编号，不挂在 `1.*` 下；
- **已建立映射的任务文件原则上不再改文件名或一级标题。** 状态变化优先更新 `1-结果资产索引.md` 的成熟度总表和文件内部内容，避免破坏 README、正文、Drive handoff 或后续脚本中的固定路径引用。

当前结构：

- `1-结果资产索引.md`：全部结果资产的快速定位入口与成熟度总表；
- `1.1-当前结果总览.md`：跨任务样本、已完成结果、当前停止线和正文可用性总览；
- `1.2-本地Agent读取与核对说明.md`：local-only 资产的读取顺序、权威路径和回报合同；
- `2-Behavior行为结果与资产.md`：行为正式结果、输入/输出表、科研图与本地/云端证据；
- `3-Ocular眼部结果与资产.md`：瞳孔与眨眼测量冻结、覆盖、表示一致性和时间支持；
- `4-Movement动作结果与资产.md`：动作 P4 正式结果、模型源表、13 张图和完整资产路径；
- `5-Cardiopulmonary心肺结果与资产.md`：当前毫米波测量与外部验证资产审计；正式心肺结果尚未形成；
- `6-监督学习与多模态结果与资产.md`：正式模型结果的接收合同；现阶段不写性能。

例如，未来若新增 Ocular 同步异常补充审计，应使用 `3.1-...`；若新增监督学习 P5 接口核验，应使用 `6.1-...`，而不是继续扩展 `1.*`。

## 七、持续更新要求

以后每完成一次单模态正式结果首次生成或重新物化、特征/表示正式冻结、结果图表新增/替换、样本分母变化、新 Drive handoff 成为当前权威证据、监督学习或多模态正式结果生成、或发现会改变已报告解释的错误，都必须同步更新本目录。

更新时保留旧 bundle 的历史证据，不覆盖历史路径；在本目录中把“当前权威证据”指向新的 bundle，并说明旧证据为何被替代。

更新顺序优先为：**本地正式输出 → Drive handoff → 完整结果总账 → 第 5 章正文**。若结果只存在于 local-only 大表，本地 agent 应先按 `1.2` 形成可复核的小型摘要，再更新网页端总账。

**若正式结果已经改变，但 `国赛报告/完整结果/` 尚未同步更新，则该结果交接视为未完成，不应直接据此修改最终报告正文。**

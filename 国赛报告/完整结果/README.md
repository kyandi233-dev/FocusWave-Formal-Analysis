## 2. 当前总体样本口径

正式 governed cohort（治理队列）为 **61 名参与者、116 个实验场次、2,320 个 Behavior 权威 probes（思维探针）**。不同模态 availability（可用性）不同，不能把某个模态的有限值样本改写成总体样本。

典型当前覆盖包括：

- Ocular：NIR（近红外）source manifest 覆盖 109 场；主要瞳孔表示在 107–108 场可估，眨眼覆盖结构另行登记；
- Movement：主要动作指标在 115 场、2,300 probes 上有有限值；
- Cardiopulmonary：正式监督学习比较按满足当前 mmWave（毫米波）来源/质量条件的实际分析集合运行；
- 监督学习：不同模型使用 comparison-specific analysis set（比较特异分析集合），参与者、场次与 probe 数不得跨集合混用。

`participant_group_id` 是重复测量推断、participant-cluster bootstrap（参与者簇自助法）和参与者互斥预测的统一统计键。

## 3. 当前监督学习结果已经形成

当前 Q1 二分类监督学习使用 participant-disjoint outer validation（参与者互斥外层验证）。正式结果已经包括：

- Behavior、Ocular、Movement 和 sensor-only joint（仅传感信息联合）的单类/联合预测；
- Behavior → Behavior + modality（行为基础上的模态增量）；
- `Full-x → Full` 条件价值；
- feature-level（特征级）删一/加一比较；
- device package（设备组合）比较；
- participant-macro log loss（参与者宏平均对数损失）、AUROC（受试者工作特征曲线下面积）、Brier score（布里尔分数）与 calibration（校准）诊断；
- 固定 OOF（折外）预测上的 participant-cluster bootstrap（参与者簇自助法）置信区间。

当前报告中的关键判断不能简化成“多模态一定比行为好”。现有正式比较显示 Behavior 是主要稳定预测信息；部分传感组合具有有限排序信息，但许多行为条件增量或完整组合条件价值区间跨 0，部分加项甚至使概率损失略差。所有“额外信息”主张必须来自**同一分析集合内的成对比较**。

当前具体数字优先读取 `6-监督学习与多模态结果与资产.md`、`章节草稿/5.6`、`5.7` 和 `5.8`，不要从 README 手工复制历史数值。

## 4. Cardiopulmonary 当前证据身份

Cardiopulmonary 已通过当前 mmWave producer provenance（生产端来源追踪）和 pre-probe time-legality（探针前时间合法性）合同进入正式监督学习比较。这意味着它可以回答“这些毫米波估计值对 Q1 预测是否提供信息”。

它**不等于**已经证明毫米波估计心率/呼吸率具有独立生理准确性。当前边界固定为：

- HR（心率）/ BR（呼吸率）：支持性使用；
- HRV（心率变异性）：继续 BLOCKED（阻塞）；
- 没有同步独立 ECG（心电图）参考的正式总体，不能把当前机制/QC 审计写成生理验证；
- 结果正文使用“毫米波估计心率”“毫米波估计呼吸率”等表述。

因此 Cardiopulmonary 可以有**正式预测比较结果**，同时仍然保持 physiology-limited（生理验证受限）。这两个层次不能混写。

## 5. Q1 四分类扩展的解释边界

当前正式分析分支已经包含 Q1 四分类模型、运行汇总、多分类概率诊断和合同校验。四分类的目的不是把二分类结果简单扩展为“4 类注意识别”，而是检查原始 Q1 四类在新参与者上的概率预测与类别区分能力。

四分类结果必须联合报告 multiclass log loss（多分类对数损失）、macro AUROC（宏平均曲线下面积）、balanced accuracy（平衡准确率）、macro F1（宏平均 F1）、Brier（布里尔分数）、校准以及预测类别分布。若概率损失改善但预测类别高度集中，不能把它表述成实用的四类别识别能力。

具体数字以当前四分类正式输出及其报告映射为准；README 只冻结解释边界，不复制易过期结果表。

## 6. 结果证据等级

本目录统一使用以下状态：

| 状态 | 含义 | 能否直接进入结果正文 |
|---|---|---|
| **正式结果** | 方法与测量资格已冻结，真实数据分析形成正式效应或性能结果 | 可以 |
| **测量资格结果** | 回答指标能否可靠形成、覆盖、表示选择、时间支持等问题 | 可进入样本/测量基础或相应模态结果 |
| **敏感性结果** | 用预先限定的替代表示、窗口或协变量检查稳定性 | 有解释价值时进入正文，其余作为补充 |
| **质量控制（QC）** | 同步、覆盖、曝光、来源模式、伪迹、producer 机制等 | 通常不作为注意相关主结论 |
| **历史/已取代** | 保存当时运行或方法状态，已被后出正式证据覆盖 | 不直接进入当前正文 |

interface smoke（接口冒烟测试）只证明 schema（数据结构）、身份键和接口能够闭环；它不能替代正式模型性能。相反，正式 LOSO 已经实际运行后，也不能再把旧 smoke 停止线写成当前“尚未运行模型”的证据。

## 7. 每个结果模块必须记录什么

每个独立分析模块至少记录：

1. 科学问题与证据身份；
2. 参与者、场次以及 probe/试次/窗口等实际分析单位；
3. 正式输入表、关键变量与冻结表示；
4. 正式结果、95% CI（置信区间）和必要的多重校正状态；
5. 输出表格、图件及其源表；
6. 本地绝对路径和 Google Drive `_AI_HANDOFF` bundle（交接包）；
7. 方法文档、代码分支/commit（提交）和 producer provenance；
8. 当前限制、blocked 项和任何会影响解释的异常。

小型关键表可以直接复制到 Markdown；数万到数百万行的 probe/frame（探针/帧）级表、原始视频、Parquet、雷达原始数据和可稳定再生的大型中间产物只登记路径、哈希、行数/大小和用途。

## 8. local-only 与 Drive 的关系

Google Drive `_AI_HANDOFF/` 用于跨设备/跨 Agent 交接小型结果包和证据摘要，不替代本地权威大资产。大型数据可以只在本地，但必须按 [`1.2-本地Agent读取与核对说明.md`](1.2-本地Agent读取与核对说明.md) 只读核对，并形成可复核摘要后再更新网页端结果总账。

local-only 只是存储策略，不代表证据等级更高；Drive 有副本也不自动代表其为正式结果。

新的正式结果、重新物化、表示冻结、样本分母变化、图表替换、监督学习重跑或会改变解释的错误，统一按：

```text

→ 运行记录与证据

→ 完整结果总账
```

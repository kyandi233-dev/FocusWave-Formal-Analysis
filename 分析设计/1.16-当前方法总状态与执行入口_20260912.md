## 1. 当前研究主线

FocusWave 当前已经从“重新设计监督学习方案”进入**单模态科学分析与特征冻结、统一接口收口、真实数据验证**阶段。

首轮监督学习的科学问题固定为：对模型训练中完全未见的 participant（参与者），利用 probe（探针）之前合法获得的 Behavior（行为）与传感信息，预测该 probe 的 Q1 注意内容自我报告。当前首轮标签为 `Q1=1` 对 `Q1=2/3/4`。Q1 是主观注意内容报告，不是“真实注意真值”；Q2 是探针时点主观困倦/清醒背景，首轮不作为当前 Q1 predictor（预测变量）；事后问卷主要用于场次级回顾与背景解释。

自 `1.16.10` 起，分析解释分为三个层次：

- **具体特征层**：`x -> Q1`、`B -> B+x`、`F-x -> F`；
- **科学模态层**：Behavior（行为）、Ocular（眼部）、Movement（动作）、Cardiopulmonary（心肺）的单独预测、Behavior-conditioned（行为条件增量）与后续删一模态比较；
- **设备组合层**：RGB、NIR（近红外）、mmWave（毫米波）的现实设备依赖与 device-package analysis（设备组合分析）。旧 M0–M7 仅保留为工程/部署分析，不再定义科学模态。

其中 `B` 为待最终冻结的 Behavior reference（行为参照特征集），`F` 为全部正式可用科学特征组成的 Full model（全特征模型）。科学模态回答“模型使用什么类型的信息”；设备回答“生成这些信息实际需要什么硬件和预处理来源”。两者必须分开。

## 2. 当前样本与可用性口径

当前 `Attention-Analysis` 正式配置声明 governed cohort（治理队列）为 **116 sessions（场次）、61 participant groups（参与者组）**。cohort membership（队列成员资格）与具体特征/设备可用性必须分开。

当前 NIR 测量审计链记录 **109 个 current-compatible NIR source records（当前兼容近红外源记录）**。109 只表示当前 NIR 可运行来源，不是总体样本数，也不能替代 116 场治理队列分母。

毫米波集成快照 v1 按同一治理队列形成：116 场、61 个参与者组、2,320 个 probe 全部保留，其中 109 场、2,180 个 probe 具有可估计的心率与呼吸率，7 场、140 个 probe 保留为来源不可用或格式错误。该快照是 `PROVISIONAL_INTEGRATION_READY / PHYSIOLOGY_LIMITED`，不是毫米波生理算法冻结。

不同模型比较的共同分析集合始终由该比较实际需要的具体 predictor union（预测变量并集）构造，不能用某个设备的全局可用样本代替。

1. **集成 READY 不等于生理效度完成。** 按 snapshot v1 接口接入 HR/BR 只表示分母、键守恒、动态链接库（dynamic-link library [DLL]）主机接收/入队时间列合同与下游资格审计、输入物化冒烟成立；HR/BR 仍为 `SUPPORTING_ONLY`。

4. **`MAIN_ANALYSIS = PROCEED` 不等于毫米波正式 predictor 无条件放行。** 整体主分析可以继续推进，snapshot v1 可作为集成接口与 supporting input（支持性输入）保留；但 snapshot v1 的 source-code provenance（源码来源追溯）尚未闭环（replay manifest 记录的源码 hash 与其自记 `source_commit` 对应文件不一致，原因未定），因此**当前任何 Cardiopulmonary（心肺）feature 都不得取得 `verified_pre_probe_only`，正式预测资格全部 fail-closed（失败关闭）**。逐 feature 判定规则见 `1.16.11` 第 5.1 节。

## 3. 当前统一数据流

当前不再把历史 Task A/B/C/D 当作四条执行线。正式关系为：

```text
单模态 producer（Behavior / NIR pupil / RGB blink & movement / mmWave）
→ 测量审计、QC 与单模态科学分析
→ Behavior / Ocular / Movement / Cardiopulmonary 候选特征交接
→ comparison-specific analysis set（比较特异分析集合）
→ frozen feature registry（冻结特征登记表）
→ formal supervised learning（正式监督学习）
```

producer/source namespace（来源命名空间）使用 `behavior / nir / rgb / mmwave`；科学模态使用 `behavior / ocular / movement / cardiopulmonary`。例如 RGB blink 属于 Ocular；RGB body motion 属于 Movement；如果 pupil 使用 RGB blink 辅助清洗，它仍属于 Ocular，但 `required_devices=[nir,rgb]`。

## 4. Task A/B/C/D 为什么仍能看到

`Task A / B / C / D` 是 1.15 并行实施时期的历史责任名：

- A：监督学习训练与评价主干；
- B：质量/可用性、比较特异样本与物化接口；
- C：Behavior producer 与行为候选特征；
- D：当时的 NIR producer 接口。

这些实现已经汇入当前统一集成线。名称仍可能出现在历史 issue、PR、workflow、测试文件或模块注释中，用于 provenance（来源追踪）和兼容，不代表现在还有四个独立分支，也不代表四种科学模态。

从 2026-09-13 起，新的方法文档、运行说明、结果目录和用户面对的 CLI 不再以 A/B/C/D 为主叙事。历史 workflow 文件可以暂时保留原名，只要测试内容和当前合同一致。

## 7. 当前三条可继续单模态工作线

### 7.1 Behavior

当前第一轮候选科学维度为：

- RT level：mean 或 median，需 Q1-blind（不看 Q1）的测量/分布证据后人工冻结；
- `go_correct_rt_cv`：RT variability（反应时变异），数学最低有效正确-Go 数为 2；不存在旧 `n>=20` 正式硬门槛；
- `go_correct_rt_theilsen_slope_ms_per_s`：RT trend（反应时趋势）；
- `raw_go_omission_rate`：Go omission；
- `commission_rate`：No-Go commission。

`dprime_loglinear`、criterion c、beta 等保留为单模态报告/敏感性或替代表示，不与原始 omission+commission 在第一轮 Behavior reference 中机械重复。

当前仍需清理代码中 `rt_cv_min_n` 的旧 fallback `20`，避免配置键缺失时让废弃阈值复活。

### 7.2 Ocular

Ocular 由 NIR pupil 与 RGB blink 共同构成。当前需要依据已有 G1 测量审计，收口：

- pupil signal：geometry 与 hard segmentation ratio 的主表示选择；soft segmentation 只作 sensitivity（敏感性）；
- cleaning track：NIR-only 与 RGB-assisted 轨道；
- blink buffer；
- probe-relative fixed bins（探针相对固定时间箱）；
- level / variability / slope / curvature；
- blink 第一轮科学维度 `blink_event_rate_per_min`；
- 双眼来源、有效 bin、buffer loss、RGB 可用性等作为 QC，而不是把全部候选逐张画图。

旧 NIR 200 ms、1/3/5/10/20/30/60 s 全窗口 × 全候选图包不再作为当前正式图包。

### 7.3 Movement

第一轮正式科学变量围绕 `body_motion_energy_median`。pose direction 继续作为 exploratory/sensitivity（探索/敏感性），exposure change 作为 QC/confound。blink 不属于 Movement。

Movement 的正式分析需要独立于旧“RGB 5.5”章节组织，使 body motion、pose、exposure 与 blink 的不同科学角色在输出和图中分开。

## 8. 当前绘图与文件组织

绘图和文件组织以 `1.16.12` 为当前执行合同。

核心原则：

1. **问题驱动出图**：每张图必须回答明确科研或资格问题，不按候选列机械展开；
2. **模态图 + 特征图并存**：模态图负责综合；具体 feature 图负责其分布、稳定性、动态或效应；
3. **图型由问题决定**：ECDF（经验累积分布）、density（密度）、paired dots/slopegraph（配对点/斜率图）、scatter/hexbin（散点/六边形密度）、Bland–Altman（一致性差值图）、trajectory（轨迹）、coefficient/dot-whisker（系数点区间图）、heatmap（热图）按实际数据结构选择；box/bar 仅在四分位或计数/比例问题真正适合时使用；
4. **学术规范**：推断图报告估计量和 95% CI；重复测量按 participant/session/probe 层级处理；完整题名和样本说明放外部 caption manifest；图例无边框；中文/西文字体按 `1.3/1.4`；禁止装饰性 3D、无必要双纵轴；
5. **结果与 QC 分开**：`main / qualification / qc / sensitivity` 四类图不得混在同一目录或同一结论层级。

文件结构采用两层：现有 Behavior/NIR/RGB/mmWave 继续保存 producer/staging 大型技术产物；正式小型科学结果按 Behavior/Ocular/Movement/Cardiopulmonary 建立 science output，并分 `tables / figures / manifests`。历史 `5.5` 等章节号不再作为新 canonical 结果目录主键。

## 9. 当前监督学习协议硬约束

以下规则已经冻结：

1. comparison-specific analysis set 的 `required_features` 必须等于被比较模型实际 predictor union；
2. 被研究 feature 在某 outer fold 因训练折全缺失/零方差被删除时，该 fold 对该增量是 `not_estimable_feature_absent`，不能记成零贡献；
3. registry 资格布尔字段严格解析；
4. missing-aware（缺失感知）只允许真正 residual single-feature missingness，malformed/parse failure 必须显式排除；
5. scientific modality、source namespace、required devices 与 preprocessing dependencies 独立登记；
6. 任何请求正式预测资格的 feature 必须通过 producer-side time legality；Q1-blind 冻结本身不能证明无未来信息；
7. 训练折内插补、标准化、列处理和超参数选择继续与 producer-side time legality 分开治理，两者必须同时无泄漏。

## 10. 当前执行顺序与停止点

当前只执行：

`P1 接口收口（已完成当前阶段）`
→ `P2 Behavior 正式分析、精简图包、科学结果目录与候选交接`
→ `P3 Ocular pupil+blink 正式分析、G1 决策图与候选交接`
→ `P4 Movement 正式分析、精简图包与候选交接`
→ `P5 三模态 schema / identity / time-legality smoke（不跑真实性能）`
→ **停止，由研究者另开结果分析分支并冻结具体正式 feature**。

只有研究者完成具体 feature freeze 后，才继续：

`frozen registry`
→ `最终 producer status 接线`
→ `真实 comparison-specific analysis sets`
→ `mini-LOSO smoke`
→ `governed-cohort 正式二分类监督学习`
→ 后续扩展分析。

因此当前不应该把“监督学习代码已经能跑”理解为“现在就可以进行多模态正式预测”。本轮的正确终点是：三条首轮科学模态都能产出可解释、可审计、可供人工选择的正式单模态结果，并且接口已经准备好接收选择结果。

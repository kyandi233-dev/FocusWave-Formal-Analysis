## 1. 本轮纠偏的总体原则

当前监督学习的特征流程不再使用“一个统一百分比 + 一个统一最小样本数”决定所有候选是否进入模型。正式流程拆为三层：

1. **训练前预冻结科学候选库**：依据研究问题、测量含义、程序定义和已知数学关系，先限制哪些信息有资格成为候选。这一步不使用 Q1 预测表现，也不根据外层测试参与者的数据分布调整候选。
2. **特征自身可估计性与测量稳定性**：不同指标依据自身数据结构判断一个 30 秒窗口是否足以稳定估计。这里允许不同指标有不同要求，不再用统一 `n` 或统一帧比例替代。
3. **训练数据内部的经验筛选与模型选择**：覆盖率、实际方差、地板/天花板、经验冗余以及任何依赖本研究样本分布的选择，只能使用当前训练参与者；若某项选择会根据预测表现决定，则必须进入 nested cross-validation（嵌套交叉验证）的内层训练/验证过程。

因此，“producer 能输出”“科学上值得候选”“这一折实际进入模型”是三个不同状态。

## 2. 80% 覆盖率不再作为跨模态统一硬删除门槛

### 2.1 当前旧规则的来源与问题

`1.15.2` 曾将“特征可计算覆盖率 >= 80%”冻结为首轮主预测候选的统一硬门槛。当前没有证据表明 80% 是心理学、SART、多模态生理预测或一般机器学习领域的统一标准。不同研究和领域使用的缺失/覆盖阈值差异很大，通常属于研究者预先设定的操作规则，而不是可以跨指标机械套用的领域定律。

统一 80% 硬门会产生一个循环问题：如果上游先人为设置了过严的“特征可估计最低 n”，它会先制造大量缺失；随后再因覆盖率低于 80% 删除该指标，最终可能把一个理论和测量上重要的特征排除，而真正的问题其实是上游最低 n 不合理。

### 2.2 当前正式修正

从本文件起：

- **80% 保留为覆盖率审计和重点复核参考线，不再作为跨所有模态、所有指标的自动纳入/排除硬门。**
- 每个候选都必须报告特征可计算覆盖率、总体有效率和主要缺失原因。
- 覆盖率较低时，先判断原因属于结构性模态缺失、原生 QC 失败、指标自身最低数据支持不足，还是偶发单特征缺失，再决定候选角色。
- 只有在研究团队为某类指标提供外部方法依据、独立开发数据或预先规定的稳定性标准后，才可以重新冻结该类指标的硬覆盖阈值。
- 任何由本研究样本实际分布决定的覆盖筛选均只在当前外层训练参与者中计算；外层测试参与者不参与筛选规则形成。

因此，后续报告中不得把“78% 覆盖率”直接写成“质量只有 78%”或“自动失败”。它只说明在当前计算/QC 规则下，有效值出现在相应比例的可计算机会中。

## 3. 行为 RT 变异指标的最低 n：当前代码事实与正式处理

### 3.1 当前代码并没有规定 SD 需要 n>=20

当前 `science_v3.py` 对正确 Go RT 的定义为：`is_no_go == 0`、`correct == 1`、RT 非缺失且 RT >= 100 ms；当前配置没有 RT 上限。底层实现中：

- RT mean/median：存在有效 RT 即可计算；
- RT SD：至少 2 个有效 RT 才能数学计算；
- RT-CV：由 SD/mean 得到；
- Theil-Sen RT slope：底层至少 2 个不同时间点即可计算。

但正式 runner 的 `_annotate_scale()` 又额外把：

- `rt_cv_min_n = 20`；
- `rt_slope_min_n = 5`

作为当前项目代码中的可估计门槛。因此“n>=20”目前只作用于 RT-CV，不作用于 SD、MAD 或 IQR。

### 3.2 `rt_cv_min_n=20` 不是领域统一标准

当前没有方法证据支持“SART 探针前窗口的 RT-CV 必须至少有 20 个正确 Go RT”这一通用规则。已有 SART 思维探针研究存在使用探针前 8 个试次计算 RT-CV 的做法，说明该领域并不存在固定的 20-trial 标准。另一方面，试次数越少，SD/CV 的抽样波动确实通常越大，因此完全取消最低数据支持也不合理。

从本文件起，`rt_cv_min_n=20` 定位为**当前旧代码中的项目阈值、待稳定性审计**，不再作为已经得到领域依据的正式科学标准。

### 3.3 后续冻结最低 n 的规则

不得根据“把 n 改成多少可以让覆盖率超过 80%”反向选择门槛。应优先做 measurement-stability audit（测量稳定性审计）：在拥有较充分正确 Go RT 的窗口中，通过预先规定的子抽样/重采样方案比较不同 n 下 RT-CV 与参考估计的一致性、排序稳定性和抽样波动，检查稳定性何时进入平台。

若该门槛由当前正式样本的数据分布推导，而不是来自独立/外部依据，则它属于数据驱动开发决策。为保持外层参与者泛化评估独立，正式预测实现必须将相应选择限制在训练数据内部，或先在独立开发/预实验数据上冻结后再开展外层评估。

同理，NIR（近红外）SD、斜率等连续时间序列特征也需要指标自身的有效时间支持规则，不能直接把函数能在 2 或 3 个点上返回数值当作充分的科学有效性，也不能机械复制 RT-CV 的 n=20。

## 4. Go 试次本身与 Go 反应分类的边界

### 4.1 Go 身份由实验序列决定

正式实验程序中 `is_no_go` 由预生成刺激序列定义。每个正式 Block 有 432 个试次，其中固定 48 个 No-Go（11.1%），其余为 Go。Go/No-Go 身份不是根据参与者表现或后验数据筛出来的，因此当前没有证据显示“哪些 trial 是 Go”这一设计身份本身存在错误。

### 4.2 真正需要审计的是 Go 反应状态，而不是 Go 身份

程序对 Go 的原始记分是：1.15 秒正式反应期内捕获到空格则 `response=1`，未捕获到则 `response=0, omission=1`。后处理还会记录 RT<100 ms、prestimulus press（刺激前按键）、carry-over candidate（跨试次延续按键候选）、RT>1150 ms 等时间诊断。

因此：

- “有效正确 Go RT”只是所有 Go 中满足当前 RT 条件的一部分；
- “raw Go omission”是程序反应窗内没有捕获响应的另一部分；
- 提前/刺激前/边界时序异常等情况保留为 QC/诊断信息。

正式分析不再要求把所有 Go 强制解释成多个互斥的“心理机制类别”。需要的是一张 trial-level（试次级）审计表，保证每个 Go 的程序记分、RT 可用性和 timing QC（时序质量控制）状态可以追溯，且不同特征的分母写清楚。

## 5. omission 稀少时是否还要强制拆 clean 与 timing-ambiguous

### 5.1 当前数据事实

当前正式行为结果中，场次级平均总 Go omission 约为 2.20%，clean omission 约 1.57%，timing-ambiguous/预判遗漏约 0.62%。因此 omission 本身较少，拆分后的 timing-ambiguous 指标更稀疏；在 30 秒 probe 窗口上还可能进一步表现为大量 0 值。

SART 文献中 omission 往往明显少于 commission；一些研究甚至因目标窗口中相关错误事件太少而不对其进行探针级分析。因此不能仅因为代码可以拆分，就假定两个组成率都适合作为首轮监督学习独立预测变量。

### 5.2 当前正式修正

描述性/QC 层继续保留：

- raw Go omission；
- clean Go omission；
- timing-ambiguous Go omission；
- 更细的 prestimulus/carry-over/anticipatory/late timing flags。

这样可以追踪程序记分与时序歧义，不丢失审计信息。

但在**首轮监督学习行为主输入**中，从本文件起不再强制使用 `clean_go_omission_rate + timing_ambiguous_go_omission_rate` 两个组成变量。默认候选恢复为更简洁、与程序原始记分直接对应的：

`raw_go_omission_rate`

clean 与 timing-ambiguous 先作为描述/QC/敏感性候选保留。只有在训练数据内部确认它们分别具有足够的非零发生率、有效变异、稳定性，并且拆分具有明确额外解释价值后，才允许把“拆分 omission”作为一个预先定义的替代特征方案进入内层比较。不得根据外层测试性能决定拆不拆。

这也意味着当前 `candidate_validation.py` 中“对三个 omission 端点特殊处理并全部保留为正式端点”的代码事实需要在后续新版监督学习实现中与本规则区分：历史描述性行为管线可以保留，监督学习候选合同不再强制三项同时进入。

## 6. NIR 多个动态指标应该在训练前还是训练后筛选

当前 producer 已能计算 SD、MAD、IQR、peak-to-trough（峰谷差）、successive difference（相邻变化）、单位时间变化率、扩张速度、收缩速度和 slope（斜率）等。首轮监督学习若把这些全部直接投入模型，会扩大特征数并带来明显的同义/高相关冗余，尤其在当前以简单可解释模型和参与者外泛化为主的任务中没有必要。

正式采用“两段筛选”。

### 6.1 训练前：科学含义预筛，先把候选库缩小

这一层在任何预测模型之前完成，不看 Q1 与特征的显著性、相关性或外层测试性能。

对每一条基础连续生理信号，首轮科学候选原则上只要求覆盖三个不同信息维度：

- **level（水平）**：mean 与 median 属于同一候选家族；最终主模型只需一个代表性水平量；
- **variability（波动）**：SD 必须进入初始波动候选家族；MAD/IQR 作为稳健替代候选，不要求三者同时进入同一主模型；
- **trend（趋势）**：保留一个时间斜率候选，具体算法必须与实际 producer 定义一致。

peak-to-trough、相邻差分、单位时间变化率、扩张速度、收缩速度等更细动态量，在没有预先明确的额外科学问题和可靠时间支持前，不作为首轮主模型的默认输入；保留在 producer 输出和探索/敏感性层即可。

因此第一轮每条主要连续信号目标是一个**小而有结构的候选方案**，而不是把所有可计算统计量堆入模型。

### 6.2 训练数据内部：经验筛选和候选方案选择

科学候选库冻结后，在每个外层训练集内部检查：

- 实际可计算覆盖及缺失原因；
- 有效值数量、零/近零方差；
- 对比例/事件指标的严重地板或天花板；
- 同一科学维度内的经验冗余；
- 指标在参与者之间和参与者内部是否有足够有效变异。

这些步骤只使用训练参与者，不让外层测试参与者参与候选形成。

如果可以仅根据测量原理预先选择代表项，例如已明确采用 median 表示稳健水平，则不需要模型比较。只有当两个合理方案无法在训练前按科学含义确定时，才把少量预定义方案放入 inner cross-validation（内层交叉验证）比较，例如“mean 方案 vs median 方案”或“SD 方案 vs MAD 方案”。这属于模型开发，必须在内层训练/验证中完成。

不采用逐个特征根据 p 值、全数据 Q1 相关性或外层测试 AUC 进行筛选。L2 regularization（L2 正则化）可以缓解剩余共线性，但不能代替前述科学预筛和泄漏安全的特征筛选。

## 7. 修正后的首轮特征流程

正式主流程调整为：

`原始数据/producer输出`

→ `结构与时间合法性 + 模态原生QC`

→ `训练前科学含义预筛：删除明确重复概念、技术QC字段和无明确首轮科学问题的细粒度派生量`

→ `形成小型结构化候选库：每条连续主信号优先覆盖水平 + 波动 + 趋势`

→ `外层按参与者留出`

→ `仅在外层训练参与者中检查实际覆盖、方差、地板/天花板、经验冗余和缺失原因`

→ `若需要根据预测表现在合理候选方案之间选择，则在内层交叉验证中完成，并在每个内层训练折重新拟合所有数据驱动预处理/筛选`

→ `固定该外层折的方案，在完整外层训练集重新拟合`

→ `预测外层留出参与者`。

## 8. 当前仍待代码/数据审计的事项

1. RT-CV `n>=20` 的稳定性依据尚未完成，暂不得把当前 78.19% 覆盖直接解释为 RT-CV 科学质量失败。
2. NIR 的 SD、MAD/IQR、斜率需要结合现有有效时间序列做测量稳定性与时间支持审计；不同特征可以有不同的最低支持规则。
3. 当前 NIR producer 的 slope 实现与历史文档中 “Theil-Sen” 表述需要统一实际算法名称。
4. 新版监督学习代码需要把 80% 从自动硬门改为审计/复核参考，并输出各折具体候选筛选原因。
5. 新版行为监督学习默认使用 raw Go omission 作为 omission 主候选；clean/timing-ambiguous 保留为描述、QC 和可选敏感性方案。
6. 当前多模态 runner 仍需修正内层交叉验证前预处理已使用完整外层训练集的问题；本文件不表示这些代码修改已经完成。

## 9. 方法依据边界

本次修正区分领域通用原则与项目操作规则：

- 交叉验证中的数据驱动预处理、特征筛选和模型选择应限制在训练数据内部，若需要调参或比较特征方案则使用嵌套验证，这是防止乐观偏差/信息泄漏的通用方法原则。
- 具体缺失比例阈值、特征覆盖阈值以及 RT-CV 最低试次数通常依赖任务、测量特性和研究目的，不存在可直接跨领域套用的统一 80% 或 20-trial 标准。
- SART 文献支持 RT variability（反应时变异）作为重要指标，但具体窗口和试次数实现不同；因此 FocusWave 应保留 RT-CV/SD 的科学价值，同时单独验证 30 秒窗口中的估计稳定性。

本文件的后出决策优先于 `1.15.2` 和 `1.15.5` 中与统一 80% 硬门、RT-CV 20-trial 正式准入、以及 clean + timing-ambiguous omission 强制主输入相冲突的旧表述。历史文档保留用于追溯，后续代码与总导航应以本文件为准。

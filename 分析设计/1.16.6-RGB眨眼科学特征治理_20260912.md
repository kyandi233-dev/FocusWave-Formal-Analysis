# 1.16.6 RGB 眨眼科学特征治理

> 日期：2026-09-12
> 状态：methodology_freeze_pending_real_quality_confirmation
> 上游：1.16.4、1.16.5
> Formal 权威分支：codex/code-fix-ledger

本文用于区分 RGB（可见光视频）眨眼事件作为独立科学特征，与 RGB blink mask（眨眼掩码）作为 NIR（近红外）瞳孔清洗信息这两个角色。当前代码事实以 `Attention-Analysis@codex/1.16-abcd-integration-review` 为准。

## 1. 当前代码事实

当前 RGB blink producer 以双眼 EAR（eye aspect ratio，眼睛纵横比）相对开放度形成 `algorithm_defined_blink_candidate` 事件。事件需要可靠主脸、左右眼可观测、双眼一致，且候选闭眼持续时间为 50–1000 ms；timestamp gap、多脸歧义和主脸 track reset 均会打断事件，缺失事件源与真实 0 次事件保持区分。

probe 前 30 s 聚合当前可输出：

- `blink_event_n`；
- `blink_event_rate_per_min`；
- `blink_event_duration_median_ms`；
- `blink_event_duration_total_ms`；
- `blink_ibi_median_ms`；
- `blink_candidate_frame_n` / `blink_frame_ratio`；
- 左右眼可观测率、双眼一致率等 QC 字段。

当前正式 RGB probe metric 集只把 `blink_event_rate_per_min` 纳入 Q1/Q2 和跨模态关联候选，其他 blink 量尚未作为并列正式科学特征。

## 2. 首轮科学特征建议

首轮 RGB blink 独立科学特征保持一个主维度：**blink event frequency（眨眼事件频率）**，主表示为 `blink_event_rate_per_min`。

理由：固定 30 s 窗口内 `blink_event_n` 与 event rate 只差窗口覆盖时长的尺度换算，不应作为两个独立特征；rate 对轻微窗口覆盖差异更有可比性，且当前下游正式代码已经以 rate 为预定义 probe metric。

`blink_event_duration_total_ms` 与事件数和单次持续时间共同决定，容易同时混入频率与时长；`blink_frame_ratio` 还依赖实际帧覆盖及候选闭眼帧定义，因此首轮不与 event rate 并列作为第二个主特征。

`blink_event_duration_median_ms` 表征单次事件形态而非频率，科学上可区分，但 30 s 窗口内事件数可能较少。它暂列 sensitivity/descriptive（敏感性/描述）候选，只有真实数据证明多数 probe 有足够事件支持稳定估计时再讨论升级。

`blink_ibi_median_ms` 只有至少两个事件才能估计，预期比 event rate 更稀疏，首轮保留描述/QC，不作为正式监督学习主输入。

## 3. 可估计性与质量要求

正式 `blink_event_rate_per_min` 的可估计性不能只看事件数。至少需要：

- blink 帧源存在且不是缺失模态；
- 双眼 EAR 参考可建立；
- probe 前 30 s 有足够的双眼可观测时间；
- timestamp continuity、主脸 track 和多脸歧义未使大部分窗口不可观测；
- 真实 0 次 blink 与 event source unavailable 明确区分。

现阶段不在查看真实分布前写死统一的 `bilateral_observable_ratio` 阈值。后续 RGB 全量质量审计应先报告该比例分布、有效覆盖时长、事件率分布和不可估原因，再决定是否需要 measurement-based（测量依据）硬门槛。该门槛不得依据 Q1 显著性或预测性能选择。

## 4. 与 NIR 联合清洗的设备依赖

`blink_event_rate_per_min` 作为独立 RGB 科学特征属于 RGB-only 信息。

若同一 RGB blink 事件用于屏蔽 NIR 瞳孔伪迹，则经 `rgb_plus_nir_qc` 产生的 pupil feature 属于 NIR+RGB 联合信息，不能在 NIR-only 模型中使用。NIR-only 必须使用不依赖 RGB blink 的 `nir_qc_only` 表示。

因此 blink 在 feature registry 中应有两个不同角色：

1. RGB scientific feature：`blink_event_rate_per_min`；
2. cleaning dependency：RGB blink events → NIR pupil cleaning。

二者不能因来源相同而合并成一个 feature id。

## 5. 当前冻结状态

在不发现真实 producer 质量问题的前提下，首轮正式 RGB blink 主科学特征预冻结为 `blink_event_rate_per_min`。duration、IBI、frame-ratio 保留描述/敏感性，不扩充首轮 Full。

下一步只需利用既有 RGB 输出确认 event-rate 的真实可用性与退化风险；不需要新增一套复杂 blink 特征提取。若质量审计显示大部分 probe 的双眼可观测支持不足，再回到测量层解决，不通过增加多个 blink 派生量补救。

## 2. 当前代码事实与差距

当前 `Attention-Analysis/codex/1.15.7-task-d-nir-interface@a3c6e4893e64ebeb5098f4aeff1f7cdd8697bef6` 的新版 NIR（近红外）监督学习接口已经具备 probe（探针）前 10/20/30 s 窗口、原始双眼融合、level（水平）、variability（波动）、时间支持与缺失状态等框架，但其科学合同仍是 1.15.7 版本：

- `BASE_SIGNAL` 只有 `pupil_geom_mean_diameter`（瞳孔几何平均直径）；
- trend（趋势）只有现有 `robust_binned_slope_per_sec`（稳健分箱线性斜率）；
- 尚未接入 `seg_pupil_fraction_within_pupil_iris_hard`；
- 尚未接入 quadratic slope（二维时间趋势/二次斜率）；
- 尚未将 RGB（可见光视频）逐次 blink event（眨眼事件）转换为 NIR 帧级掩码并与 NIR QC 合并。

因此本任务是在现有 Task D 框架上做测量层扩展与审计，不重新设计整个 NIR 管线，也不重跑 YOLO/RITnet。

## 3. 本轮必须实现的测量层能力

### 3.1 两条瞳孔信号独立进入同一摘要框架

需要支持两条彼此独立的信号：

1. `pupil_geom_mean_diameter`；
2. `seg_pupil_fraction_within_pupil_iris_hard`，定义为

\[
R_{seg,hard}=\frac{N_{pupil}}{N_{pupil}+N_{iris}}
\]

hard（硬分割）为当前主候选；soft（软分割）只保留敏感性轨道。两条信号不得提前融合成一个眼部总分。

`R_seg` 需要独立的 segmentation-valid（分割有效）状态，不能机械继承几何椭圆拟合有效性。至少保留来源缺失、RITnet 失败、分母无效、pupil/iris 字段缺失、时间异常等原因。

### 3.2 RGB 眨眼与 NIR QC 联合帧级掩码

输入使用已有 RGB blink event 时间区间和 NIR `unix_ms`。先完成逐 session（场次）时间同步审计，再建立：

`rgb_blink_mask OR nir_qc_invalid -> combined_invalid`

几何直径和 `R_seg` 分别使用各自 NIR validity（有效性）与同一个 RGB blink mask 合并，并保留 invalid reason（无效原因）。

本轮先并行审计 50/50 ms、100/300 ms、200/200 ms 三个既有候选 buffer；100/300 ms 仍只是首选审计候选，不在运行前写成最终正式值。

主窗口统计不对被掩码区间插值。整个 bin（时间箱）没有真实有效观测时保持缺失。

### 3.3 线性与二次瞳孔动态

两条瞳孔信号都先计算：

- linear slope（线性斜率）；
- quadratic slope / curvature（二次斜率/曲率）。

时间方向固定为 probe-relative time（探针相对时间），越接近 probe，时间越大。线性斜率正值表示总体趋向增大，负值表示总体趋向减小。

二次趋势采用包含一次项的二次模型，时间应以窗口中点中心化以改善数值稳定性。当前不生成 turning point（转折点）、先增后减类别或转折时间作为正式特征。

### 3.4 改为 probe 锁定的固定时间箱并保留旧算法对照

`1.16.2` 已确定固定 probe-relative bin（探针相对固定时间箱）的方向，但具体 bin 宽度/数量尚未冻结。本轮代码应允许通过配置运行少量预定义候选，而不能按每个窗口第一条/最后一条有效记录自适应改变边界。

审计中必须保留当前 `robust_binned_slope_per_sec` 结果作为 legacy comparator（旧算法对照），用于判断新固定时间箱方案是否造成系统性变化；但不得因旧算法已经存在就自动把它继续冻结为最终正式算法。

## 4. 第一阶段只做测量审计，不做心理结果选择

第一阶段输出至少回答：

1. RGB–NIR 每个 session 的时间范围、offset（偏移）、nearest-frame residual（最近帧时间残差）、异常跳变和无法可靠同步状态；
2. blink onset/offset（眨眼开始/结束）周围，几何直径、`R_seg`、NIR validity 与瞬时变化何时恢复稳定；
3. 三种 blink buffer 下有效帧损失、probe 窗口损失和完整不可估窗口比例；
4. 两条瞳孔信号在 probe 前 30 s 的实际轨迹分布；
5. 不同 fixed-bin（固定时间箱）候选下 linear/quadratic 系数的可估率、数值稳定性和方案间一致性；
6. 每个 probe 的 `n_valid_bins`、`t_min`、`t_max`、`temporal_span` 和有效 bin 位置模式；
7. `R_seg` 与几何直径的可用率、左右眼/双眼来源组成和主要失败原因；
8. `R_seg` 是否明显受 iris 可见面积、眼睑遮挡、反光或 pupil↔iris 分类边界转移影响。

本阶段禁止使用 Q1/Q2 显著性、行为关联显著性、监督学习 outer-test（外层测试）性能来选择 buffer、QC、bin 或趋势算法。

## 5. 第一阶段结束后才冻结的项目

第一轮真实测量审计完成后，由 Formal 更新方法合同，再冻结：

- 主 blink buffer；
- fixed-bin 的宽度和数量；
- linear/quadratic trend 的最低有效时间支持；
- `R_seg` 是否需要额外 valid-iris、fragmentation 或 valid-pixel 硬门槛；
- `rgb_plus_nir_qc` 是否成为正式主清洗轨道，以及 NIR-only 对照的保留方式；
- 最终字段名与状态值域。

在上述参数冻结前，代码输出只能标记为 measurement audit（测量审计）或 candidate（候选），不能写成 formal primary（正式主方案）。

## 6. 与监督学习和设备比较的边界

本任务第一阶段不修改 Task A 的嵌套交叉验证，不运行 M0-M7，不产生正式 Q1 预测结果。

后续如果 RGB 眨眼参与瞳孔清洗，必须遵守 `1.16.1` 的设备依赖规则：RGB-assisted pupil（RGB 辅助瞳孔）实际依赖 NIR+RGB，不能拿它代表 NIR-only 设备能力。NIR-only 比较必须保留现实中不依赖 RGB 即可生成的对应版本。

眨眼仍是独立 RGB 科学特征族；其作为 NIR 清洗信息的角色不能删除 blink rate（眨眼率）、duration（持续时间）等独立特征的分析资格。

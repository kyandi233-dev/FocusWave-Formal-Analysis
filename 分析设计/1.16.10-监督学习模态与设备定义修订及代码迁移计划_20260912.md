## 1. 修订原因

feature registry 已经能够记录科学特征、原始来源、所需设备和预处理依赖，但旧实现曾主要按 NIR（近红外）、RGB（可见光视频）和 mmWave（毫米波）设备组合组织，并在部分代码中把 `required_devices` 直接当作 `modality_blocks`。这会混淆两个问题：模型使用的是什么类型的信息，以及生成这些信息实际需要哪些设备。

FocusWave 的正式特征并不总与单一设备一一对应。例如瞳孔特征在科学上仍表示眼部信息，但正式表示可以依赖 NIR 主信号以及 RGB 提供的眨眼剔除、头动或其他质量控制信息。因此正式定义为：**模态按所表征的信息内容定义；设备仅表示数据采集和特征生成所依赖的硬件来源。**

另一个独立风险是：Q1-blind（不看 Q1）测量冻结不能自动证明预测特征没有使用 future information（未来信息）。某个特征即使没有依据 Q1 调参，也可能在 producer（特征生成程序）、同步、清洗、参考值或个体化校正中使用 probe（探针）之后的帧、参与者整场统计量或完整序列。科学模态、设备来源与时间合法性因此必须分别登记和审计。

## 2. 正式定义

首轮监督学习采用四个科学模态：

| 模态 | 主要内容 | 当前典型特征 |
|---|---|---|
| `behavior` 行为模态 | SART（持续性注意反应任务）任务表现 | RT（反应时）水平、波动、趋势、Go omission（Go 遗漏）、No-Go commission（No-Go 误按）等 |
| `ocular` 眼部模态 | 眼部生理与眼睑动态 | 瞳孔水平、波动、趋势、眨眼等 |
| `movement` 动作模态 | 头部和身体外显动作 | 头动、体动等 |
| `cardiopulmonary` 心肺模态 | 心脏和呼吸活动 | HR（心率）、BR（呼吸率）；HRV（心率变异性）仅在资格通过后加入 |

设备层只描述真实硬件来源：`rgb`、`nir`、`mmwave`。Behavior 来自实验任务日志和探针记录，不应为了兼容旧实现被解释成传感设备。

每个正式特征至少同时登记：`feature_id`、`scientific_feature_id`、`modality`、必要时的 `feature_type`、predictor columns（预测列）、`raw_source`、`source_namespace`、`required_devices`、`preprocessing_dependencies`、`temporal_anchor`、`temporal_scope`、`time_legality_status`、`time_legality_evidence`、各类比较资格以及冻结依据。

## 3. 跨设备依赖原则

如果最终瞳孔表示由 NIR 主信号产生，但使用 RGB 眨眼事件和/或头动信息进行伪迹处理，可以登记为：

- `modality = ocular`；
- `feature_type = pupil`；
- `required_devices = [nir, rgb]`；
- `preprocessing_dependencies` 记录实际 RGB 清洗或校正步骤。

RGB 眨眼本身同样属于 `ocular`，但可以只要求 `required_devices=[rgb]`。两者可以共同进入 Ocular-only（仅眼部模态）模型，因为 Ocular-only 的含义是“预测变量只包含眼部科学信息”，并不表示只使用一个硬件设备。

RGB 头动/体动可以承担两种角色：作为 `movement` 模态的正式 predictor（预测变量），或仅作为其他特征生产中的校正/QC（质量控制）依赖。第二种情况下不能因此声称模型直接使用了 Movement 模态，但依赖必须完整登记。

心率/呼吸率固定属于 `cardiopulmonary`。其 `required_devices` 依据最终毫米波正式 producer 的真实依赖冻结；不能因为调试阶段使用过 RGB 就把全部心肺特征硬编码为必须依赖 RGB。

## 4. 监督学习比较结构

本次修订不改变 Q1 标签、外层 LOSO（留一参与者交叉验证）、内层 participant-grouped cross-validation（参与者分组交叉验证）、参与者等权训练/预处理/评价和训练折内预处理原则。

### 4.1 具体特征层

继续保留：

- `x -> Q1`；
- `B -> B+x`；
- `F-x -> F`。

`F-x -> F` 默认解释为该具体特征在其他信息存在时的**条件预测价值**，不再默认称为“不可替代信息”。

### 4.2 模态层

首轮独立模型：

- `Behavior -> Q1`；
- `Ocular -> Q1`；
- `Movement -> Q1`；
- `Cardiopulmonary -> Q1`，仅在心肺测量资格与时间合法性均通过后运行。

Behavior-conditioned（行为条件增量）比较：

- `Behavior` vs `Behavior + Ocular`；
- `Behavior` vs `Behavior + Movement`；
- `Behavior` vs `Behavior + Cardiopulmonary`。

正式特征全部冻结后可构造 `Full = Behavior + Ocular + Movement + Cardiopulmonary`，并进行 `Full-modality` vs `Full` 的删一模态消融，用于估计该模态在其他正式信息已经存在时的条件预测价值。

## 5. 设备组合分析

M0–M7 以后只作为 device-package analysis（设备组合分析）的兼容/工程层，不再承担主要科学“模态比较”含义。主要科研结果按科学模态和具体特征组织；设备组合回答现实部署中增加某套硬件后能获得哪些正式特征以及预测能力如何变化。

设备包只能包含该设备集合现实中能够生成的特征。若某瞳孔表示需要 NIR+RGB，则不能放入 NIR-only（仅近红外）设备包。也不需要为了保持八种对称组合而强行生成现实中不可生产的信息包。

一个 Ocular-only 科学模型可以实际依赖 NIR+RGB 两个设备；一个 RGB-only（仅可见光）设备包则可能同时提供 ocular 中的 blink（眨眼）和 movement 中的头动/体动。这两类分析必须分开解释。

## 6. 比较特异共同样本规则

comparison-specific analysis set（比较特异分析集合）按实际模型要求的具体特征构造，而不是按模态名、设备名或历史任务名直接求交集：

`required_features = union(features required by compared models)`。

某 feature 是否可生产，由 source/readability/alignment/QC/estimability（来源、可读性、对齐、质量控制、可估计性）以及其设备和预处理依赖共同决定。无关模态或无关设备缺失不得缩小该比较的共同样本。

## 7. Attention-Analysis 代码迁移合同

当前统一实现需要满足：

1. `RegisteredFeature` 独立记录 `modality`，允许值为 `behavior / ocular / movement / cardiopulmonary`；可选记录 `feature_type`。
2. 保留 `raw_source`、`source_namespace`、`required_devices`、`preprocessing_dependencies`，不得用设备或 producer namespace 反推科学模态。
3. `FeatureScheme` / `PlannedModel` 独立记录科学 `modalities` 与 `required_devices`；停止 `modality_blocks = required_devices` 的语义混用。旧字段如暂时兼容，必须明确 deprecated（弃用）。
4. `FeatureComparisonPlan` 记录 `modality_model_ids`、`modality_increment_pairs`、`full_leave_one_modality_out_pairs`；保留 `device_package_model_ids` 但降为设备分析。
5. device package 可用性由正式 feature 的 `required_devices` 判断，不得决定 feature 属于哪个模态。
6. 归档与 reporting（报告层）同时保存 modality、feature_id、source_namespace、required_devices、preprocessing_dependencies、comparison role（比较角色）与时间合法性字段。
7. 当前正式流程的阶段名统一为：**科学特征产出与交接 → probe 资格与可计算性审计 → 比较特异分析集合构建 → 监督学习输入物化 → 嵌套 LOSO 训练评价 → OOF 归档与比较验证**。

### 7.1 time-legality / leakage provenance（时间合法性 / 信息泄漏来源追踪）合同

首轮模型的目标仍是用某个 probe **之前合法可获得的信息**预测该 probe 的 Q1 报告。对任何有资格进入正式预测模型的 registry entry，必须显式登记并通过：

- `temporal_anchor = probe_time_ms`：当前特征相对于哪个预测时点定义；
- `temporal_scope = pre_probe_only`：正式 predictor 及其生产依赖只能使用该 probe 之前允许的原始数据；
- `time_legality_status = verified_pre_probe_only`：只有已经审计 producer、同步、清洗和校正依赖均满足首轮零个体校准要求的表示才能拥有正式预测资格；
- `time_legality_evidence`：非空、可审计的证据说明，至少指出实际时间窗口/边界以及 preprocessing dependencies 为什么不使用 probe 后帧、未来 probe、该测试参与者完整 session（场次）统计量或完整个人序列。

`required_devices`、`source_namespace`、`preprocessing_dependencies` 本身都不能替代时间合法性证明。尤其需要审计 RGB 开眼参考、眨眼掩码、头动/尺度校正、滤波/平滑、同步参数、NIR 双眼融合、毫米波窗口聚合等步骤是否使用当前 probe 之后的信息。

正式 fail-closed 规则为：只要一个 feature 的任何预测资格为真——包括 Behavior reference（行为参照）、standalone（单独模型）、Behavior increment（行为增量）、modality model（模态模型）、Full、leave-one-out（删一比较）或 device package——该 feature 就必须是 `verified_pre_probe_only`。尚未完成时间合法性审计的候选可以留在 registry 草案或上游测量表，但其全部预测资格必须为 false。

训练过程中学习的插补、标准化、经验列处理、候选方案与超参数选择继续由 `1.16.1` 的折内合同管理；本节治理进入监督学习执行之前已经生成的科学特征及其 producer 依赖。二者都必须满足才能称为无泄漏。

### 7.2 历史 A/B/C/D 标识边界

Task A/B/C/D 是 `1.15.7` 并行实现时期的工作包名称，已经由当前统一语义流程取代。历史 workflow、测试名、函数名和 Issue/PR 可以暂时保留旧标识以维持可追溯性和兼容性，但必须满足两条规则：

1. 新方法文档、README、运行说明、结果解释和用户面对的 CLI 不再把 A/B/C/D 写成当前分析阶段；
2. 若代码中仍有 `task_a` / `task_b` 等内部名字，文档必须同时给出其当前语义，不得由内部名字反推科学流程。

## 8. 毫米波集成与正式预测资格边界

毫米波权威仓库当前状态为 `MMWAVE_INTEGRATION = READY`、`MAIN_ANALYSIS = PROCEED`，并保留 `MMWAVE_INTEGRATION_SNAPSHOT_V1` 作为多模态接口快照；HR/BR 维持 `HOLD / SUPPORTING_ONLY`，HRV 维持 `BLOCKED`。

这些状态允许继续接口对接和数据结构验证，但**不自动授予毫米波科学 predictor 正式预测资格**。Formal `1.15.8` 当前记录的三项 probe 级生成链问题尚未验证关闭，其中右端排他边界和 `window_effective_start_unix_ms` 实际切片语义直接涉及 probe 前窗口时间合法性。依赖该 adapter 的 feature 在修复、回归测试和差异核验完成前不得仅凭 `MMWAVE_INTEGRATION = READY` 标记为 `verified_pre_probe_only`。

## 9. 必需测试

至少覆盖：

1. pupil 可以是 `modality=ocular` 且 `required_devices={nir,rgb}`；
2. blink 可以是 `modality=ocular` 且只依赖 RGB；
3. head/body motion 属于 `movement` 而不是 `rgb` 模态；
4. HR/BR 属于 `cardiopulmonary`，设备依赖按 registry 实际声明；
5. Ocular-only 模型可同时包含跨设备产生的 pupil 与 blink，但科学模态仍只有 ocular；
6. RGB-only 设备包不能纳入需要 NIR+RGB 的 pupil；
7. `Behavior` vs `Behavior+Ocular` 的 `required_features` 恰好等于两侧实际 predictor 并集；
8. leave-one-modality-out（删一模态）删除该模态正式 predictor，不误删仅作为其他模态预处理依赖的信息；
9. 旧配置进入兼容路径时必须显式标记兼容/弃用，不能静默把 device 当 modality；
10. 现有 LOSO、参与者等权、missing-aware（缺失感知）、OOF archive 与 paired comparison（成对比较）合同不得退化；
11. 任一具有正式预测资格的 feature 缺失 `temporal_anchor / temporal_scope / time_legality_status / time_legality_evidence` 时 fail closed；
12. `time_legality_status=pending_upstream_freeze` 的候选只有在全部预测资格为 false 时才允许保留；
13. 跨设备 pupil 即使 `modality=ocular`、`required_devices={nir,rgb}` 合法，也必须单独证明 RGB 清洗/校正依赖没有使用当前 probe 之后的信息；
14. run manifest（运行清单）与 paired-comparison provenance（成对比较来源追踪）必须保留时间合法性字段，不能只归档设备和 source namespace；
15. 任一用户面对的当前流程说明不得再把 Task A/B/C/D 作为阶段名。

## 10. 本次不修改

本次语义迁移不改变 Q1 二分类标签、验证结构、参与者等权、科学特征冻结规则，也不提前冻结毫米波 HR/BR 最终科学资格。Brier score（布里尔分数）和 calibration plot（校准图）继续作为正式 OOF 概率产生后的独立概率校准诊断，不混入本次模态/设备与时间合法性重构。

## 11. 当前执行顺序

Formal 以本文件冻结定义。各单模态先完成真实科学特征交接与人工冻结；随后完成 probe 资格审计、比较特异分析集合构建、真实 registry、监督学习输入物化的 schema smoke；再执行 mini-LOSO 验证训练、折外归档、失败记录与 provenance 完整性。毫米波只有在对应科学资格和 producer-side time legality 都通过后，才能从接口快照提升为正式 Cardiopulmonary predictor。所有闸门完成后才进入 governed cohort 正式监督学习。

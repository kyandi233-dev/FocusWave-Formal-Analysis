> 状态：**active_methodology_contract / implementation_required**

> 本文件是 2026-09-12 对监督学习“模态”定义的最新修订。与本文件冲突时，本文件优先于此前将 NIR/RGB/mmWave 直接作为科学模态的表述。

## 1. 修订原因

当前 feature registry（特征登记表）已经能够记录科学特征、原始来源、所需设备和预处理依赖，但后续模型计划仍主要按 NIR（近红外）、RGB（可见光视频）和 mmWave（毫米波）设备组合组织，并在部分代码中把 `required_devices`（所需设备）直接当作 `modality_blocks`（模态块）。这会混淆两个问题：模型使用的是什么类型的信息，以及为了生成这些信息实际需要哪些设备。

FocusWave 的正式特征并不总与单一设备一一对应。例如瞳孔特征在科学上仍表示眼部信息，但正式表示可以依赖 NIR 主信号以及 RGB 提供的眨眼剔除、头动或其他质量控制信息。因此正式修订为：**模态按所表征的信息内容定义；设备仅表示数据采集和特征生成所依赖的硬件来源。**

## 2. 正式定义

首轮监督学习采用四个科学模态：

| 模态 | 主要内容 | 当前典型特征 |
|---|---|---|
| `behavior` 行为模态 | SART 任务表现 | RT 水平、波动、趋势、Go omission、No-Go commission 等 |
| `ocular` 眼部模态 | 眼部生理与眼睑动态 | 瞳孔水平、波动、趋势、眨眼等 |
| `movement` 动作模态 | 头部和身体外显运动 | 头动、体动等 |
| `cardiopulmonary` 心肺模态 | 心脏和呼吸活动 | HR（心率）、BR（呼吸率）；HRV（心率变异性）待测量资格通过后加入 |

设备层只描述真实硬件来源：`rgb`、`nir`、`mmwave`。Behavior 来自实验任务日志和探针记录，不应为了兼容旧实现被解释成传感设备。

每个正式特征至少同时登记：`feature_id`、`scientific_feature_id`、`modality`、必要时的 `feature_type`、predictor columns（预测列）、`raw_source`、`required_devices`、`preprocessing_dependencies`、各类比较资格以及冻结依据。

## 3. 跨设备依赖原则

如果最终瞳孔表示由 NIR 主信号产生，但使用 RGB 眨眼事件和/或头动信息进行伪迹处理，可以登记为：

- `modality = ocular`；
- `feature_type = pupil`；
- `required_devices = [nir, rgb]`；
- `preprocessing_dependencies` 记录实际 RGB 清洗或校正步骤。

RGB 眨眼本身同样属于 `ocular`，但可以只要求 `required_devices=[rgb]`。两者可以共同进入 Ocular-only（仅眼部模态）模型，因为 Ocular-only 的含义是“预测变量只包含眼部科学信息”，不是“只使用一个硬件设备”。

RGB 头动/体动可以同时承担两种角色：作为 `movement` 模态的正式 predictor（预测变量），或仅作为其他特征生产中的校正/QC 依赖。第二种情况下不能因此声称模型直接使用了 Movement 模态，但依赖必须完整登记。

心率/呼吸率固定属于 `cardiopulmonary`。其 `required_devices` 依据最终毫米波正式 producer 的真实依赖冻结；当前不能因为调试阶段使用过 RGB 就提前把全部心肺特征硬编码为必须依赖 RGB。

## 4. 监督学习比较结构

本次修订不改变 Q1 标签、外层 LOSO（留一参与者交叉验证）、内层 participant-grouped 交叉验证、参与者等权训练/预处理/评价和训练折内预处理原则。

### 4.1 具体特征层

继续保留：

- `x -> Q1`；
- `B -> B+x`；
- `F-x -> F`。

`F-x -> F` 默认解释为该具体特征在其他信息存在时的**条件预测价值**，不再默认称为“不可替代信息”。

### 4.2 模态层

首轮独立模型：

- `Behavior -> Q1`；
- `Ocular -> Q1`；
- `Movement -> Q1`；
- `Cardiopulmonary -> Q1`，待心肺测量资格通过后运行。

Behavior-conditioned（行为条件增量）比较：

- `Behavior` vs `Behavior + Ocular`；
- `Behavior` vs `Behavior + Movement`；
- `Behavior` vs `Behavior + Cardiopulmonary`。

正式特征全部冻结后可构造 `Full = Behavior + Ocular + Movement + Cardiopulmonary`，并进行 `Full-modality` vs `Full` 的删一模态消融，用于估计该模态在其他正式信息已经存在时的条件预测价值。

## 5. 设备组合分析

M0–M7 以后只作为 device-package analysis（设备组合分析）的兼容/工程层，不再承担主要科学“模态比较”含义。主要科研结果按模态和具体特征组织；设备组合回答现实部署中增加某套硬件后能获得哪些正式特征以及预测能力如何变化。

设备包只能包含该设备集合现实中能够生成的特征。若某瞳孔表示需要 NIR+RGB，则不能放入 NIR-only 设备包。也不需要为了保持八种对称组合而强行生成现实中不可生产的信息包。

一个 Ocular-only 科学模型可以实际依赖 NIR+RGB 两个设备；一个 RGB-only 设备包则可能同时提供 ocular 中的 blink 和 movement 中的头动/体动。这两类分析必须分开解释。

## 6. Task B 共同样本规则

comparison-specific analysis set（比较特异分析集合）继续按实际模型要求的具体特征构造，而不是按模态名或设备名直接求交集：

`required_features = union(features required by compared models)`。

某 feature 是否可生产，由 source/readability/alignment/QC/estimability 以及其设备和预处理依赖共同决定。无关模态或无关设备缺失不得缩小该比较的共同样本。

## 7. Attention-Analysis 代码迁移

当前 `feature_registry.py` 已有 `scientific_feature_id`、`raw_source`、`required_devices`、`preprocessing_dependencies`，但 `required_devices` 仍被用于 `modality_blocks` 和 M0–M7 设备包生成。实现时应完成：

1. `RegisteredFeature` 增加 `modality`，允许值为 `behavior / ocular / movement / cardiopulmonary`；可选增加 `feature_type`。
2. 保留 `raw_source`、`required_devices`、`preprocessing_dependencies`，不得用设备反推科学模态。
3. `FeatureScheme` / `PlannedModel` 独立记录科学 `modalities` 与 `required_devices`；停止 `modality_blocks = required_devices` 的语义混用。旧字段如暂时兼容，必须明确 deprecated（弃用）。
4. `FeatureComparisonPlan` 增加 `modality_model_ids`、`modality_increment_pairs`、`full_leave_one_modality_out_pairs`；保留 `device_package_model_ids` 但降为设备分析。
5. device package（设备包）可用性由正式 feature 的 `required_devices` 判断，不得决定 feature 属于哪个模态。
6. 归档与 reporting（报告层）同时保存 modality、feature_id、required_devices、preprocessing_dependencies 和 comparison role。

## 8. 必需测试

至少覆盖：

1. pupil 可以是 `modality=ocular` 且 `required_devices={nir,rgb}`；
2. blink 可以是 `modality=ocular` 且只依赖 RGB；
3. head/body motion 属于 `movement` 而不是 `rgb` 模态；
4. HR/BR 属于 `cardiopulmonary`，设备依赖按 registry 实际声明；
5. Ocular-only 模型可同时包含跨设备产生的 pupil 与 blink，但科学模态仍只有 ocular；
6. RGB-only 设备包不能纳入需要 NIR+RGB 的 pupil；
7. `Behavior` vs `Behavior+Ocular` 的 Task B `required_features` 恰好等于两侧实际特征并集；
8. leave-one-modality-out 删除该模态正式 predictor，不误删仅作为其他模态预处理依赖的信息；
9. 旧配置进入兼容路径时必须显式标记兼容/弃用，不能静默把 device 当 modality；
10. 现有 LOSO、参与者等权、missing-aware、OOF archive（折外预测归档）和 paired comparison（成对比较）合同不得退化。

## 9. 本次不修改

本次语义迁移不改变 Q1 二分类标签、验证结构、参与者等权、科学特征冻结规则，也不提前冻结毫米波 HR/BR 最终生产链。Brier score（布里尔分数）和 calibration plot（校准图）继续作为正式 OOF 概率产生后的独立概率校准诊断，不混入本次模态/设备重构。

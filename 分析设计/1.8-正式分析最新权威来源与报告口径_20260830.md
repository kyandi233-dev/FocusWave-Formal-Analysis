## 3. 用户已确认的报告口径

### 3.1 行为遗漏名称

正式正文采用简洁名称：

- `Go 遗漏率`；
- `无时序歧义遗漏率`；
- `时序歧义遗漏率`。

第一次出现时说明后二者依据按键时序特征对 Go 遗漏进一步区分。不得把“无时序歧义遗漏”直接命名为“注意遗漏”。更细的抢按、跨试次延续、迟发反应等用于解释时序构成，不作为并列核心心理结局。

### 3.2 RGB 最终范围

正式报告按**已经确定的最终轻量范围**书写，而不是按历史大而全 RGB 管线书写。当前正式范围为：

1. 整体运动；
2. 曝光/亮度变化控制；
3. 必要的姿态确认和方向性运动候选；
4. 眨眼候选事件。

AU、情绪、rPPG、PERCLOS、完整头姿分析、复杂 RGB 独立预测退出当前正式报告主线。Pose 前后方向只是辅助方向候选，不解释为真实物理位移。Blink 仍需真实数据验证后才能升级为正式事件结果。

### 3.3 NIR 基线表述

正式报告不使用“session 中心化”“baseline contract”“fallback”等工程语言。分析逻辑写为：

- 以每次实验中稳定的典型瞳孔水平描述个体内相对变化；
- 事件相关分析以事件发生前的短时瞳孔水平作为参照；
- 任务开始前 3 min 静息阶段仅在眼部具有足够可观测数据时用于探索性比较。

主分析不依赖静息瞳孔基线，也不把闭眼或不可观测时间补值后解释为静息瞳孔水平。

### 3.4 毫米波来源和边界

毫米波分析方法以 greenboo 最新 main 为权威。正式数据不是 raw ADC：正式存储结果为 2T4R、8 通道、256 距离单元的复数距离域数据，Range FFT 已在上游完成，正式报告不得再写“下游首先做 256 点距离 FFT”。

最新时间语义以采集过程中记录的 DLL 时间作为逐帧时间参照。旧 Python `time.time()` 窗口与修正后的 DLL-time 窗口已经证明不可互换，因此旧窗口统计不能直接作为当前正式结果。

现阶段 HR/BR 仍保留验证边界，IBI/HRV 不能作为已经获得独立生理验证的正式指标。身体运动与心肺相关微动分开解释。

### 3.5 多模态方法

多模态科学问题不是比较不同样本上的单模态准确率，而是在相同参与者、相同探针窗口和相同测试划分下检验每种模态在行为/任务背景之外提供的增量信息。

当前冻结的方法设计包括：

- 以探针前窗口为共同分析单位；
- 外层验证按参与者完全独立，重复实验始终随同一参与者进入同一划分；
- 先采用可解释的特征级融合；
- 在完整共同样本上比较 `C`、`C+M`、`C+N`、`C+R`、`C+M+N`、`C+M+R`、`C+N+R`、`C+M+N+R` 八种组合，其中 C 为任务背景/行为，M 为毫米波，N 为 NIR，R 为 RGB；
- 主要比较同一测试参与者上的性能增量，并进一步评价模态之间的冗余和互补；
- 规则化回归作为主要可解释模型，Random Forest 等作为预设稳健性比较；
- 更复杂的 MLP、质量感知融合或小型跨模态模型只作为次级预测分析，只有在相同参与者独立验证下优于简单模型才进入最终报告主结果。

`docs/results/2026-08-30_FORMAL_MODEL_READY_V1/` 已形成 Behavior+NIR+RGB 的共同探针级建模前提和 LOSO 划分证据，但这不等于模型已经训练，也不等于多模态结果已经产生。当前其中 1,295 个共同探针 / 65 次实验 / 46 名重复参与者属于该阶段已整理的数据子集，不能替代正式实验总体 63 名参与者 / 119 次实验的研究样本口径。

## 4. 报告语体转换

内部分析文件可保留 `gate`、`contract`、`model-ready`、`not_estimable`、`fallback`、`runner` 等词，但正式正文只写其科学含义：

- 数据质量是否满足分析条件；
- 某种测量在多少有效观测中可获得；
- 某个分析是否因数据不足而无法估计；
- 某个参照值是否真正来自静息阶段；
- 模型是否在独立参与者上获得稳定增量。

正文不复述仓库、分支、SHA、代码测试、生产状态、放行状态或数据管线治理。

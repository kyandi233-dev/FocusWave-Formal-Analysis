# 1.16.2 瞳孔相关：眨眼联合清洗与探针前动态分析当前决策

> 日期：2026-09-12  
> 状态：`partially_frozen_pending_measurement_audit`  
> 标签：瞳孔相关 / NIR（近红外）/ RGB（可见光视频）眨眼 / probe-aligned dynamics（探针对齐动态）

本文件只汇总当前已经明确的事实和决策，并把尚未确定的参数保留为待审计项。当前已经形成清晰的联合分析框架，但还没有冻结成最终 implementation contract（实现合同）。

## 1. 当前研究对象

FocusWave 当前要研究的是 thought probe（思维探针）之前的 pupil dynamics（瞳孔动态），即随机采样到某一注意状态之前，瞳孔水平与时间轨迹怎样变化。这里不采用 physical near response（物理近反应）的“物体靠近眼睛”解释。

当前分为两个独立眼部特征族：

1. pupil dynamics（瞳孔动态）：NIR 产生；
2. blink / eyelid dynamics（眨眼/眼睑动态）：RGB 产生。

二者不先合成一个分数。RGB 眨眼同时还作为 NIR 瞳孔清洗的外部伪迹定位信息；这不影响眨眼继续作为独立候选特征。

## 2. 已经明确的数据事实

当前已经明确：RGB 下游具有逐次眨眼事件时间信息，包括 `start_unix_ms`、`end_unix_ms`、`duration_ms`、`blink_event_id`；NIR analysis-ready（分析就绪）帧表具有逐帧时间戳、瞳孔几何、pupil/iris（瞳孔/虹膜）分割和 QC（质量控制）信息。因此后续不再讨论“这些时间戳和瞳孔/虹膜信息是否存在”，只需审计逐 session（场次）的时间 offset（偏移）、漂移、重启和最近帧时间残差。

## 3. 两个瞳孔指标分开分析

第一条为当前几何轨道：`pupil_geom_mean_diameter`。

第二条为分割归一化指标。hard segmentation（硬分割）主候选为：

\[
R_{seg,hard}
=\frac{hard\_pupil\_fraction}{hard\_pupil\_fraction+hard\_iris\_fraction}
=\frac{N_{pupil}}{N_{pupil}+N_{iris}}
\]

生产代码已经确认 hard pupil fraction（硬分割瞳孔比例）与 hard iris fraction（硬分割虹膜比例）共享同一个 `analysis_valid_pixel_count` 和 `valid_source_mask`（真实来源有效像素掩码），因此该公式数学成立。当前推荐字段为 `seg_pupil_fraction_within_pupil_iris_hard`。它表示 RITnet 硬分类得到的 pupil+iris 区域内 pupil 像素占比，不是基于直径的 PIR（pupil-to-iris ratio，瞳孔—虹膜直径比）。

soft segmentation（软分割）对应比例同样可计算，但表示概率质量比例，当前保留为 sensitivity（敏感性）候选。几何直径和 hard 比例保持为两条独立瞳孔信号，不先融合。

## 4. RGB 眨眼与 NIR QC 的联合方向

当前总体整合方向已经确定：

`RGB blink event（RGB 眨眼事件） → 时间同步审计 → 事件前后短时 buffer（缓冲） → rgb_blink_mask`

同时：

`NIR source / RITnet / geometry / temporal QC → nir_qc_invalid`

最后：

\[
combined\_invalid = rgb\_blink\_mask \lor nir\_qc\_invalid
\]

再使用剩余真实有效帧计算瞳孔窗口指标。RGB 主要定位明显闭眼事件，NIR QC 判断分割和几何测量是否可信，两者不能互相替代。逐帧应保留 invalid reason（无效原因）。

眨眼本身仍作为独立 RGB 特征分析。候选包括 blink event count（眨眼事件数）、blink rate（眨眼率）、total blink duration（总眨眼持续时间）、blink duration fraction / burden（眨眼持续占比/负荷）及平均或中位眨眼持续时间；最终进入监督学习的子集尚未冻结。

## 5. blink buffer 目前只有候选，没有最终值

当前 `NIR分析/1.3.1-RGB辅助眨眼剔除与分割归一化瞳孔指标实施计划_20260911.md` 给出三个候选：50/50 ms、100/300 ms、200/200 ms（事件前/事件后）。其中 100 ms 前 + 300 ms 后只是当前首选审计候选，不是最终正式值。

最终 buffer 应通过 measurement-recovery audit（测量恢复审计）冻结：把 RGB blink onset/offset（眨眼开始/结束）对齐后，观察几何直径、`R_seg`、有效率、瞬时变化和 NIR QC 在何时恢复稳定。不能根据 Q1/Q2、行为显著性或预测性能挑 buffer。

短时 buffer 用于处理闭眼、部分遮挡和重新睁眼造成的测量伪迹。较长的 blink-related pupil response（眨眼相关瞳孔反应）可能持续数秒，当前不通过把每次眨眼后数秒全部删除来处理；若后续确认影响明显，再作为 sensitivity analysis（敏感性分析）加入 blink burden 协变量或事件回归。

## 6. QC 当前明确到什么程度

几何轨道至少要求真实观测、RITnet 成功、几何量为有限正值，并排除 interpolation-only（仅插值得到）的观测。`R_seg` 需要独立 segmentation-valid（分割有效）规则，至少要求 pupil/iris 两个 hard fraction 来自同帧同眼同分析域、值合法、分母大于 0、来源真实、RITnet 成功且非 interpolation-only。

目前仍未冻结：额外 valid-iris gate（有效虹膜门槛）、fragmentation（碎裂）或 valid-pixel（有效像素）硬阈值、最终 combined invalid fraction（联合无效率）门槛、以及 slope（斜率）所需最低有效时间支持。当前治理继续遵循 `1.15.2`：不能机械套统一 80% 或统一最小 n，阈值应依据实际缺失结构和稳定性审计冻结。

## 7. 正式窗口与不插值原则

当前正式主窗口仍为 probe 前 30 s；严格位于 probe 之前，不包含 probe 锚定试次，不跨 Block（区块）或场次，不使用 probe 之后的信息。

两个瞳孔指标都分别考虑 level（水平）、variability（波动）和 dynamics/trend（动态/趋势）。正式 level/variability/trend 不对眨眼缺口做线性、样条或其他插值；空缺保持缺失。插值只允许用于轨迹可视化或单独敏感性分析，不回流到正式窗口统计。

## 8. slope 与 quadratic trend（二次趋势）

probe-relative time（探针相对时间）定义为：

\[
t=(T_{frame}-T_{probe})/1000,\qquad -30\le t<0
\]

在线性模型：

\[
P(t)=\alpha+\beta_{linear}t+\epsilon
\]

中，`β_linear > 0` 表示越接近 probe 瞳孔总体增大，`β_linear < 0` 表示越接近 probe 瞳孔总体减小。几何直径和 `R_seg` 分别计算自己的 slope，不混合。

当前方法学倾向使用 probe-locked fixed bins（探针锁定固定时间箱），避免旧实现按每个窗口第一条/最后一条有效观测重新定义 bin 边界。但用户已明确：**具体 bin 宽度和数量暂不冻结，等查看真实轨迹、缺失和稳定性结果后再定。**空 bin 不插值；bin 内代表值当前以 median（中位数）为主要候选。

一次和二次目前都先进行单模态分析。二次模型可写为：

\[
P(x)=\alpha+\beta_1x+\beta_2x^2+\epsilon
\]

建议对时间做窗口中点中心化。`β2` 表示 curvature（二次曲率），不等于“先升后降”；只有 turning point（转折点）实际落在观察窗口内且轨迹支持反转时，才解释为先升后降或先降后升。

最终监督学习是否只保留线性、只保留曲率，或同时保留总体线性趋势与曲率，目前未冻结。若同时考虑，不建议把 linear-only slope、二次模型的一次项和二次项三个高度重叠量机械全部纳入。

## 9. slope 的最低时间支持必须审计，但数值未定

30 s 窗口即使只剩很短一段数据，数学上仍可能拟合 slope，但这种 slope 不一定代表整个 30 s。因此后续至少应保存 `n_valid_bins`、`t_min`、`t_max`、`temporal_span`（有效时间跨度）以及早期/接近 probe 时段是否都有有效观测。

当前只冻结“趋势指标需要科学上足够的时间支持”，不先规定具体最小 bin 数或覆盖比例。先看真实缺失分布和稳定性，再冻结阈值。

## 10. 联合清洗仍是候选路线，不是已验证唯一正式路线

当前 `1.3.1` 建议并行保留四条测量轨道：`original_nir`、`rgb_blink_only`、`nir_qc_only`、`rgb_plus_nir_qc`。其中 `rgb_plus_nir_qc` 是当前推荐联合清洗方向，但在时间同步、buffer、数据损失、恢复时间和稳定性审计完成前，仍属于 recommended candidate preprocessing track（推荐候选预处理轨道）。

## 11. 下一步应先做的测量审计

下一步需要先回答：RGB–NIR 时间残差是否稳定；不同 blink buffer 下瞳孔和 `R_seg` 何时恢复稳定；两类瞳孔轨迹在 probe 前 30 s 的实际形状；不同 fixed-bin（固定时间箱）方案下 linear slope（线性斜率）和 quadratic curvature（二次曲率）是否稳定；有效 bin 数与时间跨度怎样分布；`R_seg` 是否受 iris 可见面积、眼睑遮挡、反光或 pupil↔iris 分类边界转移明显影响；眨眼独立特征之间是否高度冗余。

完成这些审计后，再形成下一份 implementation contract（实现合同），冻结具体 buffer、QC、bin、一次/二次趋势表示、最低时间支持和最终字段命名。

## 1. P3 Ocular 关闭事实

真实冻结物化执行于 `Attention-Analysis` commit `49d2f9a231bd1436b543ebc93f61541db24d2c53`，exit code=0。正式参数为：

- blink buffer（眨眼缓冲）：`pre200_post200`；
- fixed bin（固定时间箱）：`2 s × 15`；
- minimum temporal span（最低时间跨度）：`20 s`；
- dynamic（动态）项同时要求 early/late support（前后半窗口均有真实支持）；
- 不对缺失时间箱插值；
- 第一轮 pupil representation（瞳孔表示）：`seg_pupil_fraction_within_pupil_iris_hard`；
- level（水平特征）：`level_mean`；
- variability（波动特征）：`variability_mad`；
- dynamics：`linear_slope_per_sec` + `quadratic_curvature_per_sec2`；
- geometry（几何瞳孔）为 cross-representation sensitivity（跨表示敏感性）；
- soft `R_seg` 为 segmentation sensitivity（分割敏感性）；
- RGB blink rate（眨眼率）作为独立 Ocular 科学特征。

20 s 规则真实执行后，首选联合清洗 hard `R_seg` 的 linear slope 有限值为 1857，quadratic curvature 为 1855；与冻结支持表中的预期精确一致。`registry_ready=true` 在 Ocular handoff 中只表示接口和资格证据已经齐全，不等于统一 registry 已被修改。

P3 验收后发现的两个 provenance（来源追踪）问题不改变数值结果：顶层 manifest 的旧 `formal_minimum_span_frozen=false` 语义需要修正；四张 freeze-support（冻结支持）表归档应改为 byte-exact（字节完全一致）复制，避免 CSV 浮点重写产生约 1e-16 的末位差。该补丁只修改 manifest/归档语义，不重新估计 Ocular 特征。

## 3. P5 的科学边界

P5 的唯一目的，是证明三条科学模态可以在不改变科学语义的前提下接到共同 feature-registry / analysis-set（特征登记/分析集合）接口。P5 不回答“哪个模态预测最好”，也不估计 Behavior→Behavior+sensor 的增量。

P5 输入为当前真实 science-output（科学输出）层：

1. `FormalScience/Behavior/tables/behavior_feature_handoff.csv`，以及其 manifest 指向的 Behavior probe 主表；
2. `FormalScience/Ocular/tables/ocular_feature_handoff.csv` + `ocular_probe_features_wide.csv`；
3. `FormalScience/Movement/tables/movement_feature_handoff.csv`，以及 Movement manifest 指向的 RGB strict pre-probe probe 表。

P4 的 `ocular_cross_artifact_audit.csv` 属于 measurement-artifact sensitivity（测量伪迹敏感性）证据，不决定 P5 的 schema、身份键、required devices（所需设备）或 time legality（时间合法性），因此不是 P5 强制输入；其权威副本继续保留在 Movement 科学输出中。

## 4. P5 必须验证的接口合同

P5 validator（验证器）必须 fail-closed（失败关闭）检查：

1. 三个 handoff 具有统一的必需字段合同；
2. `scientific_modality` 分别为 `behavior / ocular / movement`，不得用 producer/source namespace（生产来源命名空间）替代科学模态；
3. `source_namespace` 与 `required_devices` 可解析且与当前科学角色一致；
4. 所有 `registry_ready=true` 行必须有非空 predictor、真实 predictor 列、`time_legality_status=verified_pre_probe_only` 及非空 time-legality evidence（时间合法性证据）；
5. probe 主键统一为 `participant_group_id + session_id + block_id + probe_index_in_block`；允许各 producer 使用已审计别名，但规范化后不得有重复键或同一 session 对应多个 participant group；
6. 缺失只记录 availability（可用性），不得补零；
7. 输出每个模态、两两和三模态的 key overlap（键交集）以及每个 registry-ready predictor 在共同键上的有限值覆盖率；
8. `researcher_freeze_required=true` 的候选必须显式列为 warning/pending，不得被 validator 自动选择或升级；
9. validator 不创建或修改 unified feature registry，不调用 Task A 模型，不做插补、标准化、特征筛选、LOSO 或性能估计。

Behavior 当前 RT level mean/median（反应时水平均值/中位数）仍属于研究者表示选择未决项。二者已有完整接口，因此不阻塞 P5 schema smoke；P5 必须把这一状态原样报告为 pending，而不能自行择一。

## 5. P5 输出与通过条件

建议输出到独立目录：

```text
FormalScience/P5_InterfaceSmoke/
├─ tables/
│  ├─ p5_handoff_audit.csv
│  ├─ p5_predictor_audit.csv
│  ├─ p5_key_overlap.csv
│  └─ p5_common_key_missingness.csv
└─ manifests/
   └─ p5_interface_smoke_manifest.json
```

P5 `pass` 的最低条件为：

- 三模态 handoff schema 合法；
- 每个模态至少存在一个 `registry_ready=true` 且 predictor 实际存在的候选；
- registry-ready 候选的时间合法性全部已验证；
- canonical probe key（权威探针键）无重复和身份冲突；
- 三模态共同键可构造，并明确报告实际 participant/session/probe 数；
- missingness（缺失）和 pending freeze（待研究者冻结）均有显式审计；
- manifest 明确记录 `final_feature_registry_mutated=false`、`supervised_model_run=false`、`multimodal_model_run=false`。

P5 通过后立即停止。下一阶段应由研究者处理剩余 Behavior 表示冻结并物化统一 feature registry；只有 registry 冻结后，才允许进入真实监督学习。

## 6. 毫米波当前不并入 P5

现有 mmWave（毫米波）工程链已经完成过少量真实场次的 producer → analysis-set → materialize schema smoke，说明工程接口并非从零开始。但当前 Cardiopulmonary（心肺）科学模态的正式测量资格和第一轮科学特征尚未完成冻结。因此本轮 P5 保持 `Behavior + Ocular + Movement` 三模态，不把“毫米波工程接口已通”误写成“心肺科学特征已冻结”。待 Cardiopulmonary 单模态资格完成后，再沿相同接口合同加入，而不回退修改本轮三模态 smoke 的科学含义。

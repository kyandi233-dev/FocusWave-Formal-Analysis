# Behavior 遗漏双层结局与可选执行控制补充

> 日期：2026-08-30
> 状态：覆盖此前“将 Go 反应强制拆成五个互斥心理结局”的表述；旧记录保留用于追溯，不再作为当前正式分析口径。

## 1. 正式程序事实

最终 `FocusWave/formaltest` 的正式任务为 BB 两个 Block。每个 trial 为刺激 250 ms + 掩蔽 900 ms，总反应期约 1.15 s。程序对 Go trial 的原始记分为：在程序反应期内捕获到空格则 `response=1`；未捕获到空格则 `response=0, omission=1`。程序另外保存 `raw_keypresses` 和 `prestimulus_press_ms`，因此后处理可以审计刺激前按键、重复按键和相邻试次边界附近的运动时序歧义，但这些记录不能覆盖程序原始记分。

## 2. 当前正式 omission 结局

正式 Behavior 分析预先保留三个相关但非独立的 Go omission 结局：

1. `raw_go_omission_rate`：程序原始 Go omission；
2. `clean_go_omission_rate`：原始 omission 中未检出当前预定义 motor-timing ambiguity 的部分；
3. `timing_ambiguous_go_omission_rate`：原始 omission 中检出刺激前按键和/或前试次串键候选的部分。

三者使用同一个有效 Go opportunity 分母，并强制满足：

`raw_go_omission_rate = clean_go_omission_rate + timing_ambiguous_go_omission_rate`。

`clean` 只表示“没有检出当前定义的运动时序歧义”，不等于证明该 trial 是纯粹的注意失败；`timing_ambiguous` 也不等于独立心理错误机制。两者作为正式结局是因为该现象在当前任务中具有实际频率和解释价值，但报告必须同时展示原始 omission，并说明三者的从属关系。

## 3. 仅作 QC/描述的 timing 字段

以下字段不升级为独立主结局：

- prestimulus-only ambiguity；
- carryover-only ambiguity；
- prestimulus + carryover ambiguity；
- multiple keypress；
- very-early/anticipatory candidate；
- `RT > 1150 ms` 等超出名义 trial 长度的 timing diagnostic；
- timestamp/字段异常造成的 unclassifiable 状态。

其中 `RT > 1150 ms` 首先按时间记录/边界诊断处理，因为正式程序的反应轮询本身位于 1.15 s trial 内，不直接解释为一种新的“迟反应”心理结局。

## 4. 统计与报告合同

三个 omission 结局均进入预先定义的多尺度验证，包括场次、Block、cycle/time-on-task、严格探针前窗口、B1-B2、参与者内/参与者间分解和重复访问敏感性。其候选稳定性审计关注 coverage、floor/ceiling、参与者间与参与者内变异及冗余，不以 outcome p 值决定是否保留。

三者具有代数从属关系，因此相关系数高不能作为自动删掉其中一个的规则；报告中也不得把三者当成三份独立样本或三个独立错误机会。No-Go commission 始终使用独立的 No-Go opportunity 分母。

## 5. 当前分析子集与总体样本

代码中当前 44 session / 38 participant groups / 6 double-session groups 是当前已经完成整理与身份联结的分析子集拓扑门，不代表正式实验总体。方法与总样本口径继续以最新方法证据为准：正式实验总体为 63 名参与者、119 次实验；各结果必须报告实际进入该分析的数据分母。

## 6. Behavior / NIR 可选执行与计时合同

正式 runner 需要统一支持：

- `--list-steps`：显示结构性步骤与可选分析；
- `--only-steps`：只运行指定的可选科学分析；
- `--skip-steps`：显式跳过指定可选科学分析；
- `--subjects`：用于受治理队列内的隔离式 smoke/subset 运行；
- 每一步记录 `completed / skipped / failed`、开始/结束时间和 `elapsed_seconds`；
- 输出 `execution_steps.csv` 与 `execution_manifest.json`。

身份、cohort、输入完整性、核心 QC、必要的时间/探针合同等结构性门不得静默跳过。主动跳过可选分析时整次运行必须标为 `partial_run`，不能伪装成完整 formal run。

## 7. NIR 三分钟静息段的最新定位

`FocusWave/formaltest/01-MainProgram/main_experiment_msmf.py` 已确认：三模态启动和坐姿确认后，程序记录 `baseline_start`，调用约 3 min 的 resting baseline，再记录 `baseline_stop`；这些事件写入每场 `beh/master_timeline.csv`，时间戳为 Unix ms。因此静息 NIR 的权威切段应使用 `baseline_start → baseline_stop`，不得直接把视频开头 180 s 当作静息段。

但静息瞳孔参考仍未自动放行。现有 pupil-only source 已能区分 source observed/missing、RITnet success/failure、pupil geometry validity、ROI clipping、temporal flags 等质量轴；下一步应先用这些事实生成静息可观测性审计，再预先冻结 coverage/连续有效时长门槛。不可探测状态不得自动命名为“闭眼”，阈值也不得依据后续行为显著性反向选择。

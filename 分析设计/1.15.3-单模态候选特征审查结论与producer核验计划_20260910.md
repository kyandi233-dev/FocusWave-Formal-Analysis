## 一、这轮审查解决的问题

本轮针对“此前单模态指标是否选得过窄，以及 30 秒窗口是否因为中位数汇总而丢失动态信息”进行重新核验。结论需要区分三层：当前代码已经实际计算的内容、正式方案正在要求补充的内容、以及尚未经过 producer（特征生成程序）逐字段审计而不能冻结的内容。

当前可以确认：行为单模态已经具有较完整的水平、变异、趋势、错误与信号检测指标，不存在“30 秒只用中位数”的代码事实；此前较明显的候选空间过窄问题主要集中在 NIR（近红外）、RGB（可见光）和毫米波进入正式监督学习的候选合同。连续信号使用中位数本身不是错误，问题在于若只保留一个窗口水平统计量，就不能充分表示同一 30 秒内的波动和趋势。

## 二、已经确认的当前代码事实

### 2.1 Behavior（行为）

`Attention-Analysis/src/attention_pipeline/behavior_formal/science_v3.py` 当前 `CANONICAL_METRICS` 已实际包括：

- `go_correct_rt_mean_ms`：正确 Go RT（反应时）均值；
- `go_correct_rt_median_ms`：正确 Go RT 中位数；
- `go_correct_rt_sd_ms`：正确 Go RT 标准差；
- `go_correct_rt_mad_ms`：正确 Go RT 中位绝对偏差；
- `go_correct_rt_iqr_ms`：正确 Go RT 四分位距；
- `go_correct_rt_cv`：正确 Go RT 变异系数；
- `go_correct_rt_theilsen_slope_ms_per_s`：正确 Go RT 的 Theil–Sen 稳健斜率；
- `omission_rate`、`commission_rate`：Go 遗漏率和 No-Go 误按率；
- `dprime_loglinear`、`criterion_c`、`beta`：信号检测指标。

因此此前“行为仍需补 IQR（四分位距）”的说法不再成立，IQR 已经实际实现。P90–P10、极慢反应比例、更多逐 trial（试次）动态量等只能作为后续可能候选，必须先有明确行为学含义和样本支持，不以扩大特征数量本身作为目标。

行为当前窗口实现同样已经明确：`primary_probe_window_seconds=30`，`sensitivity_probe_windows_seconds=(10,20,30)`。30 秒输出被标记为 `primary_probe`，10/20 秒属于 `window_sensitivity_only`。因此当前正式解释应保持“30 秒主窗口 + 10/20 秒窗口敏感性分析”，不能把 10/20/30 秒描述为三个同等地位的主分析窗口。

### 2.2 NIR、RGB 与毫米波

当前方案已经提出连续传感信号从单一水平汇总扩展为至少区分 level（水平）、variability（变异）和 trend（趋势），并允许 30 秒内部前/中/后三段 10 秒均值用于展示粗略变化形状。但这属于正式修改方向，不能在 producer 逐字段核验前写成“当前代码已经完整实现”。

RGB 当前代码树已经存在姿态、运动质量控制、眨眼候选等独立模块，例如 `rgb_formal/pose_direction.py`、`rgb_formal/motion_qc.py`、`rgb_formal/blink_candidates.py`。因此后续审查必须区分“上游或单模态 producer 已经生成的信息”和“当前多模态融合配置实际挑选进入模型的信息”；不能只看融合 YAML 中的少量字段就断言 RGB 上游没有更多信息。

毫米波继续受既有科学资格门控约束。允许扩展的对象只能是已经验证、时间支持足够的信号。若某个 30 秒窗口实际上只有单次估计，就不能为其伪造 SD（标准差）或 slope（斜率）。HR（心率）估计的窗口内离散程度也不能直接改称 HRV（心率变异性）；未通过正式资格门控的 HRV、LF/HF（低频/高频功率比）等不能因为建立“宽候选库”而重新进入主预测。

## 三、对“中位数压掉 30 秒信息”的正式判断

均值和中位数都属于窗口 level（水平）统计量，回答窗口整体处在什么水平；SD、MAD、IQR 等描述 variability（变异）；斜率描述整体 trend（趋势）；短时分段或事件率描述更局部的变化和事件结构。它们反映不同信息维度。

因此当前问题不应表述为“中位数不合理”，而应表述为：对连续模态，如果一个 30 秒窗口只由单个水平统计量表示，就无法利用窗口内部的波动与变化方向。均值与中位数均可保留到候选审查阶段；若二者在同一信号上高度重复，最终只保留一个代表性水平指标。选择过程不得依据外层测试参与者的性能结果。

## 四、历史 baseline 的定位

`greenboo26/focuswave-multimodal-attention-analysis` 的 `FINAL_BEHAVIOR_CONTEXT_BASELINE_V2.md` 记录了北京 canonical baseline（规范基线）：70 sessions（场次）、46 natural participants（自然参与者）、1,400 probes（探针），目标为 Q1=1 对 Q1=2/3/4，30 秒为主窗口，10/20 秒为敏感性窗口。

其中 30 秒结果为：Behavior-only（仅行为）ROC-AUC（受试者工作特征曲线下面积）=0.639，Context+Behavior（情境+行为）ROC-AUC=0.675。该结果继续保留为历史 baseline anchor（基线比较锚点），不作为当前全正式队列的性能结论。

如果未来需要判断“扩展候选特征是否真正提高预测能力”，必须在相同参与者集合、相同标签、相同外层划分、相同预处理和模型选择条件下重新运行旧特征集与新特征集。不能将新的全队列结果直接与 0.639 做差后解释为特征扩展增益。

## 五、对 `1.15.2` 候选筛选逻辑的解释性修正

`1.15.2` 当前使用了“完成覆盖率、分布和冗余复核后得到固定候选特征集”的表述。为避免信息泄漏，后续实现必须把候选过程拆成两个层级。

### 5.1 预冻结科学候选库

这一层依据测量原理、代码定义和预先记录的科学资格建立，不依赖外层测试参与者。例如：

- 明确定义哪些原始信号允许派生 level、variability、trend；
- 数学同义别名只保留一个；
- 明确存在确定代数关系的变量不同时作为简单线性模型的独立输入；
- QC（质量控制）字段与科学预测指标分轨；
- 尚未验证的 HRV 等指标禁止进入主候选；
- 30 秒主窗口以及 10/20 秒敏感性窗口的角色预先冻结。

这一层可以形成全局一致的候选字典和字段资格表。

### 5.2 每个外层训练集内部的实际特征筛选

凡是需要根据本研究样本实际分布计算后才决定是否保留的步骤，都必须只使用当前外层训练参与者的数据。包括：

- 特征可计算覆盖率是否达到 80%；
- 零方差或有效值过少；
- 实际地板/天花板分布；
- 基于 Spearman 相关的经验冗余；
- 同一信号 mean（均值）与 median（中位数）的数据驱动取舍；
- 其他依赖样本实际分布的列筛选。

若某一步还要作为超参数或候选方案的一部分进行比较，则在 nested cross-validation（嵌套交叉验证）的每个内层训练折内重新估计，并应用于相应内层验证参与者。完成内层选择后，再在完整外层训练集重新拟合一次，最后应用于外层测试参与者。

因此，后续代码中的“固定候选集”应理解为预冻结的科学候选库，而不能理解为先使用全体正式样本做覆盖率、相关性和分布筛选后，再进行参与者留出验证。

## 六、跨 fold 稳定性的用途边界

完成外层参与者隔离验证后，可以汇总每个候选指标在不同外层训练折中的入选频率、方向和窗口稳定性，用来描述 feature-selection stability（特征选择稳定性）。这属于结果层面的稳定性证据。

不得根据同一轮外层测试产生的入选频率重新冻结一套“赢家特征”，然后仍在同一批外层测试参与者上重新评估并声称得到独立泛化性能。若要将该结果转为下一版固定模型，需要新的独立验证集合，或明确标记为模型开发后的内部性能。

二分类 Q1=1 对 2/3/4 可以承担首轮粗粒度监督预测与折内特征发现。后续四分类应在新的外层训练过程中重新执行相应特征处理；不能先利用全体参与者的二分类结果得到全局赢家特征，再把同一批数据称为独立四分类测试。

## 七、下一步 producer 逐模态核验计划

下一步不直接继续增加候选字段，先对每个单模态 producer 的实际输出、时间支持和当前融合入口做完整映射。顺序固定为 NIR → RGB → mmWave；行为只做已实现字段的监督学习资格整理，不再优先扩充。

### 7.1 NIR 第一优先

逐项读取 NIR 当前正式 producer、配置和输出 schema，建立字段清单，并对每个字段记录：原始来源、单位、时间分辨率、左右眼处理、QC 前后定义、是否当前已输出、是否可从现有序列直接派生、是否需要重跑上游、30 秒内是否具有足够时间支持。

随后将字段分为：

1. 当前已有且可进入科学候选；
2. 当前已有但仅作为 QC/诊断；
3. 可从现有逐帧/逐时间点输出直接派生的水平、变异、趋势或事件特征；
4. 需要修改 producer 才能得到；
5. 当前证据不足，不进入主预测。

重点核验瞳孔几何水平、有效瞳孔序列的变异与趋势、左右眼组合方式、眨眼/闭眼相关字段是否真实存在及其正式定义。PERCLOS（闭眼时间比例）只有在事件定义、时间覆盖和质量规则已经明确后才能进入候选，不预先假设其可用。

### 7.2 RGB 第二优先

读取 RGB 正式 producer、`pose_direction`、`motion_qc`、`blink_candidates`、runner 和当前融合配置，区分姿态、运动、眨眼、跟踪质量等不同角色。

重点检查：哪些姿态/运动字段已有逐帧基础因此可以合法计算 30 秒 level、variability、trend；blink（眨眼）是否已达到正式事件定义；tracking confidence（跟踪置信度）等字段是否只应作为 QC；当前多模态配置是否遗漏 producer 已经存在的科学候选。

### 7.3 mmWave 第三优先

读取毫米波正式生产路线、窗口生成逻辑、HR、BR/RR、运动与质量字段，并记录每个指标上游估计窗口长度和步长。只有 30 秒内包含足够多个有效时间估计的变量才考虑 variability 和 trend。

继续维持 HRV、LF/HF 等现有资格边界；先确认当前可验证的 HR、BR/RR 和运动序列究竟提供什么时间分辨率，再决定可派生统计量。

## 八、producer 审查后的正式交付

三个模态完成后形成统一的单模态候选指标矩阵。每一行对应一个候选字段，至少包含：

| 字段 | 内容 |
|---|---|
| modality | Behavior / NIR / RGB / mmWave |
| raw_signal_or_source | 原始信号或 producer 来源 |
| feature_name | 当前或拟新增字段名 |
| scientific_role | 水平 / 变异 / 趋势 / 事件 / QC / 上下文 |
| unit | 单位 |
| time_support | 原始时间分辨率、估计窗口和步长 |
| current_status | 已输出 / 可直接派生 / 需改代码 / 暂不允许 |
| qc_requirement | 计算前必须满足的模态质量条件 |
| main_30s_eligible | 是否允许进入 30 秒主候选库 |
| sensitivity_10_20s_eligible | 是否允许进入 10/20 秒敏感性分析 |
| missingness_role | 少量特征缺失 / 结构性模态缺失 / 不适用 |
| redundancy_group | 与哪些字段存在数学或经验冗余风险 |
| decision | 保留 / 删除 / 新增 / 仅 QC / 暂缓 |
| rationale | 科学与统计依据 |

完成该矩阵后，再修改实际监督学习 producer/配置和 nested cross-validation 流程。不得先根据一次 Top-N importance（前 N 个重要性）或全样本相关结果确定最终单模态指标。

## 九、当前执行优先级

当前下一阶段按以下顺序执行：

`NIR producer 全字段审查 -> NIR 候选矩阵 -> RGB producer 全字段审查 -> RGB 候选矩阵 -> mmWave producer 全字段审查 -> mmWave 候选矩阵 -> 汇总单模态科学候选库 -> 修正折内覆盖率/冗余/预处理流程 -> 在相同参与者划分下重跑 baseline 与扩展候选比较 -> 再进入四分类与多模态融合解释`

在前三个 producer 审查完成前，不冻结新的 NIR/RGB/mmWave 最终特征名单，也不以候选数量多少作为模型质量判断依据。

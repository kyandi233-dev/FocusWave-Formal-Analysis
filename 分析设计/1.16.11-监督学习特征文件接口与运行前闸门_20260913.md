## 1. 当前阶段与术语裁决

监督学习已经进入“统一接口冻结、真实单模态特征回填、运行前真实性验证”的阶段。Behavior、Ocular、Movement、Cardiopulmonary 最终都进入同一套特征登记、比较特异分析集合、输入物化、嵌套 LOSO（留一参与者交叉验证）训练评价和 OOF（折外预测）归档流程。

**历史 Task A / B / C / D 不再是当前方法阶段名，也不再作为研究流程的正式叙事。** 它们只允许出现在历史 Issue、PR、workflow、测试文件、函数名或兼容字段中，用于 provenance（来源追踪）和避免无必要的破坏性重命名。正文遇到这些旧实现标识时，必须按其当前语义解释，不能据此恢复“四条 Task 线”。

现在允许继续单模态真实分析、测量表示冻结和接口验证，但正式监督学习仍未放行。真实 predictor（预测变量）、时间合法性证据、真实 schema smoke（数据结构冒烟验证）和 mini-LOSO（小规模留一参与者验证）仍是正式运行前闸门。

## 2. 当前正式数据流

```text
单模态科学特征产出与交接
→ probe 级资格、可计算性与来源审计
→ probe_feature_status.csv 等资格表
→ 冻结特征登记表 + 比较规格
→ comparison-specific analysis set（比较特异分析集合）
→ 物化一个 analysis_set_id × membership_type
→ 监督学习宽表
→ outer participant-disjoint LOSO + inner grouped 5-fold
→ OOF 归档 / 配对比较 / manifest
```

单模态 producer（特征生成程序）决定测量表示、清洗、QC（质量控制）与数学可估性；probe 资格审计决定某个具体模型比较中哪些 probe 可进入完整样本或缺失感知样本；监督学习执行层只在已经冻结的 predictor 和比较特异样本上训练与评价。

## 3. 标准 probe 身份接口

标准 probe key 固定为：

- `session_id`
- `block_id`
- `probe_index_in_block`
- 统计身份另带 `participant_group_id`

主窗口为 `pre_30s`。Behavior 是 Q1/Q2 与 probe 元数据的权威来源；其他 producer 只能对齐和核验，不能重新定义标签。

## 4. Feature registry（特征登记表）最小合同

每个真实 feature 至少登记：

- `feature_id`
- `scientific_feature_id`
- `columns`
- `role`
- `modality`
- `feature_type`（需要时）
- `raw_source`
- `source_namespace`
- `required_devices`
- `preprocessing_dependencies`
- `temporal_anchor`
- `temporal_scope`
- `time_legality_status`
- `time_legality_evidence`
- standalone / Behavior+x / modality / Full / leave-one-out 资格
- device package（设备包）资格

科学模态、producer source namespace（来源命名空间）和设备依赖必须分别登记；不得相互反推。

## 5. 时间合法性运行闸门

任何 feature 只要进入正式预测模型或 device package，必须同时满足：

```text
temporal_anchor = probe_time_ms
temporal_scope = pre_probe_only
time_legality_status = verified_pre_probe_only
time_legality_evidence != blank
```

`pending_upstream_freeze`、`blocked_future_information`、`blocked_temporal_scope_unknown` 只允许保留为候选/阻塞状态，全部正式预测资格必须为 false。

Q1-blind（不看 Q1）表示冻结不能单独证明无信息泄漏。必须实际审计 producer 是否使用 probe 后帧、未来 probe、whole-session statistics（整场统计量）、完整测试参与者序列、非因果滤波/平滑或其他未来信息。

训练折内插补、标准化、列处理和超参数选择仍按 `1.16.1` 管理，与 producer-side time legality（生产侧时间合法性）是两个独立闸门。

### 5.1 毫米波当前边界

毫米波权威仓库当前已经给出 `MMWAVE_INTEGRATION = READY` 与 `MAIN_ANALYSIS = PROCEED`，并保留 `MMWAVE_INTEGRATION_SNAPSHOT_V1` 作为当前多模态集成输入；这表示**接口集成可以继续**，不等于其中每个毫米波科学 predictor 已经取得正式预测资格。

`1.15.8` 当前三项 probe 级生成链问题仍未验证关闭，其中 probe 右端排他边界和 `window_effective_start_unix_ms` 的实际切片语义直接属于时间合法性问题。因此，任何依赖该 adapter 切片结果的毫米波 feature，都不能仅凭 `MMWAVE_INTEGRATION = READY` 标记为 `verified_pre_probe_only`。在对应代码修复、回归测试和 old-vs-new（旧版对新版）逐 probe 差异核验完成前，其正式预测资格必须保守关闭；snapshot v1 仍可保留用于接口、schema 和 supporting（支持性）集成验证。

当前 HR（心率）与 BR（呼吸率）维持 `HOLD / SUPPORTING_ONLY`；HRV（心率变异性）维持 `BLOCKED`。这些状态不能由下游模型性能反向升级。

## 6. probe 级资格审计文件接口

资格审计固定产生：

- `formal_probe_identity.csv`
- `modality_probe_status.csv`
- `probe_feature_status.csv`
- `feature_coverage.csv`
- `modality_availability.csv`

其中 `probe_feature_status.csv` 的历史字段 `modality` 当前只表示 producer/source namespace，不能解释为 Behavior/Ocular/Movement/Cardiopulmonary 科学模态。科学模态由 registry 与 `required_feature_records` 显式提供。

比较特异分析集合固定产生：

- `analysis_sets.csv`
- `analysis_set_summary.csv`

每个比较有自己的 `analysis_set_id`；共同样本由所比较模型实际需要的 predictor union（预测变量并集）决定。

## 7. 监督学习输入物化接口

每次只物化：

`一个 analysis_set_id × 一个 membership_type`

membership 允许：

- `included_complete`
- `included_missing_aware`

监督学习宽表至少包含标准 probe key、`participant_group_id`、`probe_event_id`、`q1_nominal_4class`、`analysis_set_id`、`membership_type`、`comparison_models`、`required_features`、`required_feature_records`、`required_outcomes` 和当前比较需要的全部 predictor columns。

Q2 可以作为报告/解释元数据保留，但不进入首轮 Q1 predictor。

## 8. 监督学习输出接口

正式 run 至少归档：

- `probe_predictions.csv`
- `fold_audits.json`
- `failures.csv`
- `participant_log_loss.csv`
- `model_evaluation.csv`
- `participant_bootstrap.json`
- `paired_participant_increments.csv`
- `paired_model_increments.csv`
- `paired_fold_estimability.csv`
- `paired_increment_bootstrap.json`
- `probe_trajectory.csv`
- `session_discrimination.csv`
- `paired_comparison_provenance.json`
- `run_manifest.json`

跨 analysis set 的 raw increment（原始增量）不得直接排行；直接增量解释要求两侧来自同一比较特异分析集合。

## 9. 当前真实特征仍待冻结的项目

以下内容不在本文件提前决定：

1. Behavior RT level 使用 mean 还是 median；
2. pupil 的最终 signal、cleaning track、level/variability/dynamics 表示；
3. pupil 最终是否依赖 RGB 及具体依赖；
4. RGB blink/movement producer 的真实 QC 放行；
5. HR/BR 的正式生理测量资格；
6. 每个真实 feature 的 time-legality evidence（时间合法性证据）。

这些决定完成后，只回填真实 registry 与 producer 接线；统一资格审计、比较特异样本、输入物化和嵌套 LOSO 训练评价的总体接口不再因具体特征选择重构。

## 10. 正式监督学习放行条件

至少同时满足：

1. Behavior / Ocular / Movement 首轮真实 feature freeze 完成；Cardiopulmonary 仅在科学资格和时间合法性均通过后加入；
2. 所有正式 predictor 通过 time-legality fail-closed（时间合法性失败关闭）；
3. 真实 feature registry 完成并通过 validator（验证器）；
4. 各 producer 与标准 probe 身份完成最终接线；
5. `producer → probe 资格审计 → 比较特异分析集合 → 输入物化` 的真实 schema smoke 通过；
6. mini-LOSO 验证 outer LOSO、inner grouped CV（内层参与者分组交叉验证）、OOF archive（折外预测归档）、failure/provenance（失败与来源追踪）输出完整；
7. 之后才允许 governed cohort 正式监督学习。

在这些条件完成之前，不发布正式 Q1 预测性能，也不以历史 Task A/B/C/D 名称描述当前方法流程。

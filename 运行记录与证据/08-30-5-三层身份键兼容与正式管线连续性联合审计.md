## 3. 三层身份键结论

已确认：

```text
cohort_manifest.repeat_participant_id
        +
repeat registry.participant_key
        ↓
reconcile_cohort_identity()
        ↓
participant_group_id
        ↓
Behavior compatibility: repeat_participant_id = participant_group_id
```

因此：

- `participant_key` 是最可靠的已核验匿名参与者来源；
- `repeat_participant_id` 是旧 cohort input 和 Behavior 兼容列名；
- `participant_group_id` 是统一内部统计接口的设计目标；
- staged NIR 另有 `analysis_group_token` 兼容别名，它不是第四种独立身份来源，但当前必须纳入桥接测试；
- `session_id/subid` 只是一场实验，当前没有发现代码把它伪装为 participant 的证据。

## 4. 对另一轮网页判断的复核

“当前没有 session_id participant fallback”判断成立。RGB `participant_inference_gate()` 明确返回 `participant_identity_unresolved_no_session_id_fallback`；`reconcile_cohort_identity()` 没有按 `sub-XXX` 推断 participant。

“所有模块都在协调前 require legacy group”不成立。Behavior `prepare_behavior_runtime_config()` 当前先加载 registry 并 `reconcile_cohort_identity()`，之后才 `included_cohort(..., require_groups=True)`。真正存在顺序缺陷的是 RGB `_governed_identity()`：它先 `included_cohort(require_groups=True)`，再 reconcile。

## 5. 新发现/重新确认的身份缺陷

### 5.1 未验证 legacy group 仍可能获得 cluster 身份

当前 reconciliation 会拒绝一个 legacy group 对应多个已知 `participant_key`，但对完全没有 questionnaire overlap 的旧组，只要 `repeat_participant_id` 非空，就会生成 `legacy:<id>`。虽然示例 cohort manifest 有 `identity_status`，当前函数并没有用它作为 fallback gate。

风险不是“session 泄漏”，而是**未经过明确治理状态验证的旧匿名组可能被授权为 participant cluster**。

### 5.2 RGB 过早要求旧组存在

若未来新增 session 具有可靠 `participant_key` 但 legacy `repeat_participant_id` 为空，RGB 会在 reconciliation 之前失败。这与“身份 unresolved 只阻断 participant inference、不删除 lightweight QC session”的设计不一致。

### 5.3 必须做 cross-module identity parity

后续测试要同一 synthetic cohort 同时走 Behavior、NIR、RGB，证明 group partition 相同；并覆盖 questionnaire-present/legacy-missing、questionnaire-missing/validated-legacy、unvalidated-legacy、conflict、future append/remap、no-session-fallback。

## 6. NIR 管线连续性问题

### 6.1 NIR 仍从旧 Behavior 配置读取 trial

正式 Behavior runner 默认 `behavior_formal_v2.yaml`；NIR `nir_formal_analysis.yaml` 仍指向旧 `behavior_formal.yaml`。旧配置含 D:/E:/F: 绝对路径，违背当前 path registry 规则。

正确修复应复用 Behavior 正式 runtime preparation，而不是只改 YAML 文件名。

### 6.2 一个 `nir_source_manifest` path key 对应两种 schema

- staged pupil-only materializer：JSON object + `sessions[]`；
- `formal_multimodal_analysis.py nir-adapt`：CSV，要求 `session_id/status/eye_metrics_csv/schema_version`。

同一 logical path key 不应代表两个不兼容格式。必须冻结唯一正式 materialization authority；另一条只能明确成为 legacy/compatibility 并使用不同 path key/输出合同。

## 7. RGB lightweight 剩余缺陷

在身份顺序之外，本轮函数级复核仍确认：

- Motion observable 没有完整消费 producer 已保存的 `motion_valid/gap_before/irregular_dt` 质量门；
- `bilateral_eye_consistent` 已计算，但 closed Blink candidate 没有显式把它作为必要条件；
- runner component status 当前 generic `status` 优先于 `blink_status`，可能掩盖 Blink `not_estimable`；
- pose radial 候选实际是多个分量的符号一致性均值，`_per_sec` 命名会误导为物理速率。

这些只属于工程合同问题，不能写成 RGB 科学无效。

## 9. 多模态边界

当前不能因为存在 `merge.py` 就宣称三模态已经直接 merge-ready。Behavior 使用协调后的 `repeat_participant_id` 兼容列，staged NIR 仍有 `analysis_group_token`，RGB 使用 `participant_group_id`。应先统一 bridge，再恢复正式融合。

事件定位继续依赖 session/block/trial/probe/window/time；`participant_group_id` 用于合并后的 grouping metadata、混合/聚类推断和 participant-disjoint prediction。不得为满足 merge key 制造 participant。

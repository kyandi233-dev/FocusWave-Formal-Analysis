# 人工智能任务接手说明

## 一、接手时的强制阅读顺序

1. 根目录 `README.md` 和根目录 `AGENTS.md`。
2. 本目录 `README.md`，以及协作治理说明 [1.2-协作角色、任务分工与Git治理](1.2-协作角色、任务分工与Git治理.md)。
3. `资产导航/1-当前资产与权威来源地图.md`。
4. `分析设计/1-修订执行计划.md`。
5. `分析设计/1.1-指标与结局候选验证方案.md`。
6. 当前模块的 `README.md`。
7. 当前模块最近的工作记录、配置、数据字段结构和运行清单。

不得用旧对话、旧报告或文件夹名称代替当前文件、代码、数据和产物核验。

任务开始时还必须声明当前角色（本地数据执行、网页 GPT 科学/写作、监督协调或专门 Git）以及允许修改的仓库和文件。角色边界、并发规则、跨仓库源码归属、提交推送门控和停止点以 `1.2` 为准；本地数据执行任务完成后交给监督任务和专门 Git 任务，不自行提交或推送。

## 二、每个任务的输入模板

- 任务目标：明确到一个模块、一个阶段或一个问题。
- 权威代码基线：列出仓库、具体分支、完整40位提交、远端、工作树和是否已经由专门Git同步任务更新。
- 允许修改的仓库/文件：列出权威位置，说明是否允许修改；禁止执行任务自行创建临时脚本、新分支或第二份数据合同。
- 只读输入：列出原始数据、历史结果和报告资料。
- 样本范围：场次数、唯一参与者数、重复映射和剔除规则。
- 科学冻结：因变量、主要候选指标、质量门、协变量和模型层级。
- 工程冻结：主键、字段结构版本、配置和产物目录。
- 必需输出：代码、测试、表、图、运行记录、决策记录和产物校验值。
- 逐项验收：明确每个需求对应的代码位置、合成测试、真实数据试跑、表/图/清单及通过条件。
- 停止点：身份冲突、来源重复、字段结构变化、时间轴无法解释、重复参与者泄漏或需要扩大权限。

任务包缺少具体分支、完整提交、验收内容或最新资料同步证据时，不向网页或本地执行对话分派。不得只给一句自然语言目标，让执行任务自行猜项目背景、代码入口或科学口径。

## 三、完成回传模板

1. 最终结果与完成状态。
2. 实际使用的仓库、分支、提交版本、解释器和配置。
3. 实际样本：场次数、唯一参与者数、排除和缺失。
4. 新增/修改文件和产物索引。
5. 测试、快速测试、整体运行和视觉检查的证据。
6. 科学决策：保留、降级、不可评估、待补充和未来工作及理由。
7. 未完成、失败、不可估计和需要用户确认的事项。

## 四、全局不可越过的边界

- 场次不是独立被试；同一参与者的所有场次必须同折。
- NIR 正式主几何是拓扑规则版本；其他方法只作紧凑的方法敏感性证据。
- 刺激亮度、对比度、刺激大小和上一刺激只是 NIR 瞳孔模块的核心前置混淆审计，不默认进入毫米波或 RGB 科学模型。
- 远程光电容积描记已退出当前分析路线。
- 传感器特征是预测变量；因变量是已验证的试次、探针窗口、区块/场次行为结局或 Q1/Q2 状态。
- 不以显著与否作为报告唯一准入标准，也不为了结果漂亮改窗口、阈值、折或因变量。
- 开发证据、失败例和不适合报告的结果保留在过程区，不删除，不伪装成正式结论。

## 五、协作交接与 Git 基线

- 每个任务开始前核验实际仓库路径、分支、HEAD、远端和工作树，并执行安全 `fetch`；若远端有新提交、工作树有无法归属的变化或出现冲突，停止提交/合并并回传。
- 网页端提交与本地资料不一致时，先由专门Git同步任务完成安全拉取、提交映射和最新资料包，再启动或续发具体任务；其他任务不得直接从旧工作树推断最新状态。
- 网页 GPT 的代码修改保留在对应权威仓库的独立分支和合并请求（PR，代码审查请求）；正式分析仓库只记录关联提交、运行记录和产物索引。
- 不删除、重命名或覆盖既有文件，不 `reset` 用户工作，不强制推送。完成回传应包含角色、基线、输入输出、测试、失败/不可评估状态、关联提交和下一步验收标准。

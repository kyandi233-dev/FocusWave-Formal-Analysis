# FocusWave 六张正式科研图详细规格

本文件用于把正式报告中最值得绘制的 6 张科研示意图，转换成可以直接交给 Figma、Adobe Illustrator、Inkscape、BioRender 或外部科研绘图 AI 的 Figure Specification。目标不是让绘图工具重新理解研究，而是预先固定每张图的科学逻辑、panel 结构、对象关系和文字边界。

总体视觉方向参考心理学、认知神经科学、眼动与生理测量论文中的多面板科研图：白底、低饱和配色、线条统一、短标签、面板之间对齐清楚；复杂实体可使用简化矢量图标，但不要卡通化。正式图中不使用 Mermaid 作为最终视觉形式。Mermaid 仅保留为早期结构验证记录。

## F01 FocusWave 整体研究框架图

### 1. 沟通目标

读者应在 5 秒内理解：参与者完成持续性注意任务并回答思维探针，同时采集行为、近红外眼部视频、RGB 视频和毫米波信号；不同模态分别描述任务表现、瞳孔变化、外显运动和心肺相关微动，再在统一任务时间参照下分析注意状态的时间变化与多模态互补信息。

### 2. 推荐工具

首选：**Figma 或 Adobe Illustrator**。如果需要快速得到参与者、摄像头、雷达等设备图标，可先在 **BioRender** 中找近似矢量元素，再导入 Figma/Illustrator 统一风格。AI 生成工具只适合生成局部设备/人物视觉草图，不负责最终文字、箭头和结构。

### 3. 版面

建议横向 16:9 或约 180 mm × 95–110 mm，全图分为 4 个主要区域，从左到右阅读。

- **Panel A：实验任务与参与者**
- **Panel B：同步多模态采集**
- **Panel C：模态特异指标**
- **Panel D：时间尺度与统计分析**

### 4. Panel A：实验任务与参与者

中央画一名坐姿参与者面向显示器。显示器只需要显示简化后的水果 SART 刺激，不需要完整实验界面。参与者旁边用短标签标注：

- `SART 持续性注意任务`
- `Go / No-Go`
- `思维探针`

不要在这一 panel 写模型或算法名。

### 5. Panel B：同步多模态采集

围绕参与者画 3 类传感器，并保持与真实布置一致：

- NIR 相机：对准眼部，标签 `NIR 眼部视频`
- RGB 相机：位于显示器上方，标签 `RGB 头面部与上半身视频`
- 毫米波雷达：位于参与者正前方、胸骨上段方向，标签 `mmWave 胸部微动`

任务程序本身作为第四条记录流，从显示器/电脑引出：

- `行为与任务事件时间`

四条数据流使用平行箭头进入中央的 `同步记录 / 共同任务时间参照` 区域。

### 6. Panel C：模态特异指标

将四条记录流分别连接到四个并列小模块：

- **Behavior / Probe**：`RT`、`Go 遗漏`、`No-Go 误按`、`注意内容`、`警觉程度`
- **NIR**：`瞳孔直径 / 面积`、`事件相关变化`
- **RGB**：`整体运动`、`姿态变化`、`眨眼候选`
- **mmWave**：`呼吸相关`、`心搏相关`、`身体运动`

四个模块使用不同但低饱和的颜色类别，并保持同一颜色在后续图中代表同一模态。

### 7. Panel D：时间尺度与统计分析

四条模态指标汇聚到统一时间尺度模块：

`Trial` → `错误事件前窗口` → `Probe 前窗口` → `Block 时间进程`

右侧再分成两类统计用途：

- `个体内状态变化与个体间差异`
- `单模态关系与多模态增量比较`

箭头只表示数据组织与分析流程，不表示传感器直接因果决定“注意力”。

### 8. 必须避免

- 不画“Focus Score”“注意力分数”或类似未经验证的单一输出。
- 不把毫米波、瞳孔或 RGB 直接画成“注意力真值”。
- 不画地点、实验室名称或可识别面孔。
- 不把所有算法名塞进这张总览图。

## F02 正式实验范式与时间轴

### 1. 沟通目标

读者应快速理解正式实验由任务前静息、练习、两个相同结构的正式 Block 和双问题思维探针组成，并能看清单个 SART 试次的时间结构。

### 2. 推荐工具

首选：**Figma / Adobe Illustrator / Inkscape**。如果追求最快制作，也可以先用 PowerPoint 画出草图，再转到 Figma/Illustrator 精修。此图不建议用自由生图模型完成，因为时间和数量关系需要精确。

### 3. 版面

建议 4-panel 结构，类似心理学实验范式论文常见布局，而不是流程树。

- **A：正式实验总时间轴**
- **B：单试次结构**
- **C：Block 内任务与探针关系**
- **D：双问题思维探针**

### 4. Panel A：正式实验总时间轴

横向主时间轴从左向右：

`3 min 静息记录` → `18 个练习试次` → `Block 1` → `休息 ≥ 2 min` → `Block 2`

Block 1 与 Block 2 视觉上完全等宽、同色，强调正式实验的两个 Block 结构相同。每个 Block 下方用两行短标签：

- `432 trials`
- `384 Go / 48 No-Go / 10 probes`
- `约 9 min`

不要将练习与正式 Block 画成同等视觉权重。

### 5. Panel B：单试次结构

用水平时间条表示：

- 水果刺激：`250 ms`
- 掩蔽/反应阶段：`900 ms`

在同一 panel 下方放两个小示例：

- `Go：非苹果 → 按键`
- `No-Go：苹果 → 抑制按键`

Go 与 No-Go 只需用一个非苹果水果和一个苹果示意，不必展示全部 9 种水果。

### 6. Panel C：Block 内部

画一条连续 trial stream，用 10～15 个小刺激框象征连续任务，不需要按真实 432 个 trial 比例展开。中间插入 2～3 个 probe 标记，注明：

`10 probes / Block`

探针标记应表现为任务流中的间歇性插入，而不是独立 Block。

### 7. Panel D：双问题思维探针

上下两个小模块：

**Q1 注意内容**

- `专注于分类任务`
- `注意实验但未专注分类`
- `任务无关思维`
- `头脑空白`

**Q2 警觉程度**

画 4 级水平标尺，从：

`非常困倦` → `非常清醒`

不要把 Q1 画成有序高低等级；Q1 是四类别名义变量。Q2 才表现为有序等级。

### 8. 视觉重点

Panel A 最大；Panel B、C、D 作为下方三个辅助 panel。这样整张图应类似用户提供的专业 SART 示例：总范式 + 局部试次 + probe 结构，而不是一棵巨大的逻辑树。

## F03 多模态采集装置与空间布置图

### 1. 沟通目标

读者应理解三种连续传感设备如何围绕同一参与者布置、各自主要观测什么，以及这些数据与任务事件时间如何对应。

### 2. 推荐工具

首选：**BioRender + Figma/Illustrator**。BioRender 用于快速获得参与者、显示器、摄像头和雷达的简化科研图标；Figma/Illustrator 负责最终位置、箭头、短标签和参数排版。如果能够获得设备实拍图，也可以用照片作为小 inset，但主体仍保持矢量示意风格。

### 3. 版面

建议 2-panel：

- **A：实验空间布置**，约占 70% 宽度
- **B：同步记录关系**，约占 30% 宽度

### 4. Panel A：空间布置

使用侧前方 30–45° 视角画坐姿参与者和显示器。

必须体现：

- RGB camera 位于显示器上方，朝向头面部及上半身。
- NIR camera 对准眼部区域，旁边可加一个小的 eye inset，显示红外成像方向。
- mmWave radar 位于正前方、胸骨上段方向，雷达到胸部标注 `≈ 0.3 m`。
- 参与者保持坐姿，显示器呈现 SART。

设备旁只放短参数：

- `NIR · 1920×1080 · 30 fps · 940 nm`
- `RGB · 1280×720 · 30 fps`
- `mmWave · 57–66 GHz · ≈99 Hz · 2T4R`

更完整参数仍由表 4-1 承担，不要将图变成参数表。

### 5. Panel B：同步记录

中央写：`任务事件时间`

从中分别连接：

- `Behavior`
- `NIR`
- `RGB`
- `mmWave`

这四条记录不需要汇总成“统一采样率”。可以在下方写一行小字：`保留各模态原有时间分辨率`。

### 6. 必须避免

- 不画成产品硬件线路图，不需要 USB 端口、驱动、线程等工程细节。
- 不画地点和实验室空间细节。
- 不把 RGB、NIR、mmWave 画成彼此直接控制或触发。

## F04 正式分析总体框架图

### 1. 沟通目标

读者应理解：四类数据先分别形成科学可解释的指标，再与共同任务时间对应，最终用于行为机制分析、主观状态关联、个体内/个体间变化及多模态增量比较。

### 2. 推荐工具

首选：**Figma / Illustrator / Inkscape**。该图本质是论文级方法架构图，最接近用户上传的 CNN-LSTM、pupil pipeline 或多模块网络总览图；应通过人工控制模块尺寸、颜色和箭头，而不是自动布局。

### 3. 版面

建议横向 4 列结构：

1. `原始记录`
2. `模态特异处理`
3. `共同时间尺度`
4. `统计分析`

四条模态数据在前两列保持平行，在第三列进行时间上的对齐，第四列再根据研究问题汇聚。

### 4. 第一列：原始记录

四个垂直排列模块：

- `SART + 思维探针`
- `NIR 眼部视频`
- `RGB 视频`
- `mmWave 距离域复数信号`

### 5. 第二列：模态特异处理

行为：

`RT / Go omission / No-Go commission / d′ / c / probe state`

NIR：

`YOLO26n 眼部定位` → `RITnet 瞳孔分割` → `pupil geometry / dynamics`

RGB：

`motion energy` + `exposure change` + `pose direction` + `blink candidates`

mmWave：

`反射位置与通道` → `相位微动` → `respiration / cardiac / movement`

其中算法名只写必要名称，不画神经网络内部层结构。

### 6. 第三列：共同时间尺度

用一个大框包含四个横向尺度：

- `Trial`
- `错误前 8 个正确 Go`
- `Probe 前 30 s（10/20 s 敏感性）`
- `Block 内时间进程`

四条模态在此处汇聚，表示“按同一任务时间对应”，而不是数学融合。

### 7. 第四列：统计分析

分成两个大模块：

**解释性分析**

- `Block / 时间进程`
- `行为事件关系`
- `思维探针关系`
- `个体内与个体间效应`

**多模态增量分析**

- `行为/任务基准`
- `单模态 → 双模态 → 三模态`
- `LOSO 参与者独立验证`

最右侧不要画“AI attention score”。

## F05 NIR pupil-only 分析示意图

### 1. 沟通目标

读者应理解 NIR 不是利用不可靠的虹膜比例指标，而是从原始眼部视频中定位眼睛、用 RITnet 分割瞳孔，得到直接瞳孔几何及时间变化指标，并控制刺激视觉属性。

### 2. 推荐工具

首选：**Illustrator / Figma / Inkscape**。如果后续选出代表性真实 NIR 帧，可以将真实帧嵌入矢量流程中，效果会比纯图标更专业。结构应参考用户上传的眼动算法 pipeline 图，但不需要复制复杂神经网络层级。

### 3. 版面

建议单行主流程 + 下方两个 inset。

主流程：

`原始 NIR 帧` → `YOLO26n 眼部定位` → `眼部 ROI` → `RITnet 四分类分割` → `瞳孔几何` → `时间序列`

### 4. 主流程对象

**原始 NIR 帧**：使用灰度眼部图像。

**YOLO26n**：在眼睛周围画 bounding box，标签短写 `Eye detection`。

**RITnet**：展示一个四色 segmentation mask，但视觉上重点突出 pupil；iris 可以淡化，仅表示辅助空间定位与质量评价。

**瞳孔几何**：在瞳孔轮廓上画椭圆拟合，并用箭头标出：

- `equivalent diameter`
- `major / minor axis`
- `area`

不需要同时把所有衍生变量都塞进去。

**时间序列**：右侧画简化 pupil diameter curve，标出 event/probe 对应位置。

### 5. 下方 inset A：视觉刺激控制

画三个不同亮度/大小的水果刺激示意，连接到：

`relative luminance`、`RMS contrast`、`visible area`

再用细箭头连接至 pupil analysis，表示这些属性作为瞳孔模型中的视觉因素考虑。

### 6. 下方 inset B：三个参照逻辑

用三个小图标或时间条表示：

- `实验过程中的稳定瞳孔水平`
- `事件前短时参照`
- `3 min 静息：仅在眼部数据稳定可用时探索`

不要使用 `session centering`、`baseline contract` 等工程术语。

### 7. 必须避免

- 不画 pupil-to-iris ratio 作为正式指标。
- 不把 iris 分割结果解释为可信的虹膜尺寸测量。
- 不画“瞳孔越大 = 注意越高”的单向因果关系。

## F06 毫米波心肺相关活动与身体运动分析图

### 1. 沟通目标

读者应理解毫米波通道从已经形成的距离域复数信号中提取胸部相位微动，并将呼吸相关、心搏相关和身体运动信息分开分析；RGB 运动用于帮助解释运动对毫米波微弱心肺相关信号的影响。

### 2. 推荐工具

首选：**Figma / Illustrator / Inkscape**。如果需要表现电磁波照射人体，可使用 BioRender 或简化矢量人体图作为视觉元素，但信号处理链应人工排版。该图可参考用户上传的算法 architecture 图：上方主链路，下方局部模块放大。

### 3. 版面

建议上方一条主流程，下方两个 inset。

主流程：

`8 channels × 256 range bins complex I/Q`
→ `人体反射位置 / 通道`
→ `phase unwrap / relative chest motion`
→ 三路分支：

1. `Respiration-related`
2. `Cardiac-related`
3. `Body movement`

### 4. 呼吸分支

图中可画一条慢周期波形，标注：

`0.10–0.50 Hz`

输出：`Respiratory rate` + `respiration-related features`

### 5. 心搏分支

画快速低振幅波形，标注：

`0.8–2.0 Hz`

并在小模块中写：

`Band-pass + VMD`

输出：`Heart rate` + `cardiac-related features`

不要将 HRV 作为默认主输出展示，因为其生理解释仍需更强逐搏识别与外部参考支持。

### 6. 身体运动分支

单独画 `movement amplitude / phase instability / range instability` 等质量和运动信息，但标签保持简短，例如：

`Body movement`

### 7. 下方 inset A：任务时间对应

用一条 Block 时间轴表示毫米波连续窗口只能位于正式 Block 内，并与 task event / probe time 对应。不要跨越休息和 Block 边界。

### 8. 下方 inset B：RGB 体动敏感性分析

左侧画 RGB camera + 简化人体运动轨迹，输出 `RGB motion`。

将 `RGB motion` 连接到毫米波结果的敏感性分析框，而不是连接到心率信号提取算法内部。敏感性分析框内只需写：

- `原始结果`
- `排除明显高体动时间段`
- `连续运动量协变量`

这一 panel 的视觉逻辑必须体现：RGB 运动用于判断毫米波关系是否受到明显身体运动影响，而不是用 RGB “校准出真实心率”。

### 9. 必须避免

- 不从 I/Q 原始采样重新画成一次距离 FFT；当前正式分析输入已经是距离域数据。
- 不把毫米波画成“直接测量注意力”。
- 不声称不存在证据支持的 ECG 级生理准确度。

## 可选 F07：多模态增量与 LOSO 验证图

这张图建议等正式模型结果确定后再进入正文。方法结构可以提前画，但结果数值必须来自真实分析。

核心结构：`任务进程 + 近期行为基准` → 三个单模态 → 三个双模态 → 三模态 → `LOSO` → `AUROC / balanced accuracy / macro-F1 / Brier or log loss`。所有模型使用相同参与者和相同探针观测进行比较。

如果篇幅有限，F07 可以并入 F04 的右侧，不必单独占一张图。

# 统一绘图规范

## 颜色

建议固定 5 类语义色，并在所有图中保持一致：

- Behavior / Probe：暖橙或金黄
- NIR：蓝紫
- RGB：绿色或青绿色
- mmWave：蓝色或深青色
- Statistics / integration：中性灰或低饱和紫灰

不要使用红—绿作为唯一对比方式；颜色只辅助区分，文字标签仍需明确。

## 字体

中文建议思源黑体 / Noto Sans CJK SC；英文和数字可用 Arial / Helvetica。最终论文图不使用花体、手写体和圆润卡通字体。

## 线条

主流程箭头统一粗细；辅助关系用细箭头或浅灰连接线。相关/协变量关系不要使用强调性的粗黑因果箭头。

## 图内文字

只保留名称、时间、数量、算法名和非常短的变量标签。完整统计解释写在图题和正文中。每个框尽量不超过 2–3 行。

## 输出

优先保存可编辑 SVG / PDF / AI / Figma 文件；最终插入 Word 时可额外导出 300 dpi 以上 PNG。图中文字、箭头、框和面板标签尽量保持矢量对象，不要全部栅格化。

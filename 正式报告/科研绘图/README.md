# 科研绘图工作区

本目录用于 FocusWave 正式报告中的科研流程图、实验范式图、采集示意图、方法框架图和图形摘要。这里保存图形规划、Figure Specification（图形规格）、公开绘图工具的调用记录、结构草图、可编辑矢量图和最终导出图；统计结果图仍应由正式分析代码生成，不以生成式图片替代。

## 基本原则

科研图优先保证科学关系正确，再处理视觉风格。每张图先确定沟通目标、空间布局、节点、箭头、并行/汇聚关系和图内标签，再进入实际绘制。避免直接把长篇方法文字交给图像模型，也不使用仅包含“Nature style”“clean”“professional”等表面风格词的提示词。

本项目的正式科研绘图流程在 **本 GitHub 仓库内调用公开科研绘图仓库或其脚本/Skill**。公开仓库作为外部工具来源，本仓库保存输入规格、调用方式、版本来源和生成结果。除非用户明确要求聊天内预览，否则不以 ChatGPT 对话中的直接 ImageGen 生图替代这一流程。

统一采用四步流程：

1. **Figure Specification**：把研究内容拆成图的核心信息、空间拓扑、节点、箭头、标签和省略项。
2. **结构草图与实际渲染**：在本仓库通过 GitHub Actions、Codex 或其他可复现方式调用 Mermaid、SVG 等公开工具，检查箭头方向、并行关系、时间顺序和信息层级，并保存真实渲染结果。
3. **复杂视觉生成**：仅当图中需要人体、仪器、眼睛、毫米波等复杂视觉对象时，再从本仓库调用适合的 PaperVizAgent/PaperBanana 等公开工作流；若外部工作流需要模型 API 或密钥，先明确其依赖，不在仓库中写入密钥。
4. **可编辑重建与质检**：优先得到 SVG/PPTX；文字、箭头和框保持可编辑，并检查标签、遮挡、箭头终点、比例和科学关系。

## 推荐工具分工

- **sci-plot**：作为科研内容到 Figure Specification / Prompt 的规划参考，重点学习其“沟通目标 + 空间布局 + 箭头 + 标签 + 禁止项”的提示词结构。
- **PaperVizAgent / PaperBanana**：用于复杂科研示意图和 graphical abstract 的布局探索，尤其适合同时包含参与者、设备、任务和多模态信息的整体图。
- **academic-figures**：用于实验流程、分析管线、时间窗和统计框架等结构清晰、需要最终可编辑 SVG 的图。
- **scientific-figure**：用于将复杂视觉母版重建为可编辑 PPTX/SVG，并做版面与元素级 QA。
- **Mermaid diagram skill**：用于结构验证和快速草图，并优先通过其公开渲染脚本产生可复现输出；适合检查数据流、时间流、分支和汇聚。

上述外部仓库只作为绘图方法、提示词和工具来源，不在其中维护 FocusWave 项目正文或治理内容。

## 当前已验证的调用方式

F02“正式实验范式与时间轴”已经建立首条真实调用链：本仓库 GitHub Actions checkout `mgranberry/mermaid-diagram-skill`，记录其实际 commit，调用该公开仓库的 `references/render_mermaid.sh` 渲染本项目 `.mmd` 文件，并将 PNG 与外部工具版本记录写回本分支。该流程用于验证“公开工具执行、项目仓库持有输入与输出”的工作方式。

## 目录约定

- `01-图形总计划.md`：正式报告计划绘制的图、用途、推荐工具和优先级。
- `02-Figure-Specification模板.md`：每张图在绘制前填写的结构化规格模板。
- `03-科研绘图Prompt模板.md`：从已确认 Figure Specification 转成最终生图提示词的模板。
- 每张图按 `F01-图名/` 建立独立子目录，保存 specification、公开工具来源/版本、输入文件、渲染结果、SVG/PPTX 和最终 PNG/PDF。

## 边界

正式统计结果图（效应图、置信区间图、分布图、模型比较图等）必须由数据分析代码可重复生成。生成式绘图主要用于实验装置、任务范式、方法流程、技术路线和 graphical abstract，不用于生成或美化不存在的结果。

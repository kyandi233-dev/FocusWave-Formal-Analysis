# 正式报告章节融合工作要求

## 1. 权威落点

正式报告正文、逐章融合稿、章节级参考文献核对稿和最终报告版本，统一放在本目录 `正式报告/` 下。正式报告正文不得写入 `行为分析/`、`NIR分析/`、`RGB分析/`、`毫米波分析/` 等单模态目录；这些目录只保存各自的分析事实、方法证据、质量评价和结果证据。

正式报告和本项目分析说明只写入 `kyandi233-dev/FocusWave-Formal-Analysis` 与 `kyandi233-dev/Attention-Analysis`。`greenboo26/focuswave-multimodal-attention-analysis` 仅作为毫米波和多模态方法的只读证据来源，不在该仓库写本项目报告正文、写作规则或治理文件。

## 2. 当前正文结构

继续沿用现有报告的正文编号：题目、摘要、关键词不编号；正文从 `1 引言` 开始，之后为 `2 文献综述`、`3 研究目标与研究问题`、`4 方法`、`5 结果`、`6 分析与讨论`，后续特色与创新点、参考文献和附录按最终报告需要组织。官方模板只作为内容与格式要求，不机械转换为正文编号。

方法章保留 `0827报告v1.docx` 已形成的章级逻辑：`4.1 参与者与研究结构 → 4.2 实验设计与程序 → 4.3 两阶段预实验与正式方案的形成 → 4.4 正式实验程序与多模态采集 → 4.5 数据处理与统计分析`。除非存在明确的科学错误、事实冲突或用户明确要求，不为追求“重构”而重新排列成熟章节。

方法章执行“一个事实一个主要归属位置”。4.1 定义参与者、研究阶段和重复测量结构；4.2 介绍各阶段共享的任务范式、刺激与基本试次时序；4.3 说明预实验比较了什么、观察到什么以及这些证据如何形成正式方案；4.4 集中说明最终正式实验的 Block、试次、探针、静息记录、休息、多模态采集和时间记录；4.5 说明数据处理、质量评价、分析变量和统计推断。章节之间不通过上一节预告下一节来承接，每一节直接结束于本节的科学信息。

## 3. 章节融合原则

逐章写作以当前报告为主骨架，吸收补充材料、项目证据和已经冻结的分析证据。正文必须区分正式研究证据、形成性预实验观察、方法依据、探索性分析和尚未验证的分析内容，不把工程成功、算法接口通过或未来部署写成心理测量效度。

当前正式实验样本统一按 **61 名参与者、116 个实验场次** 书写。场次是采集与任务时间轴单位；同一参与者的重复实验记录形成参与者内重复测量。各单模态及具体统计模型根据实际数据可用性报告参与者数、场次数和有效试次/窗口/探针数。旧稿中的 **63 人/119 场口径已废止，不得继续用于正式实验总体或当前分析样本。**

总叙事为：持续注意是测量对象；SART 行为和思维探针构成任务内认知参照；毫米波是重点考察的无感连续测量通道；NIR 与 RGB 分别提供眼部和可见行为层面的并行观测及混杂解释。多模态价值由共同时间轴、测量质量、效标关系和增量信息支持，而不是由传感器数量本身定义。

正式正文采用论文/竞赛报告语体，不出现仓库治理、代码执行、审批或写作过程语言。`gate`、`contract`、`runner`、`fallback`、`model-ready`、`not_estimable` 等内部术语只能在分析设计和治理记录中使用，正文改写为相应的数据质量、测量条件、统计可估计性和效度边界。

正文禁止章节导航式元话语，包括“下一节将说明”“下文将介绍”“后文进一步讨论”“将在第 X 节说明”“相关内容见下一节”等。图表、公式和附录的必要交叉引用可以保留，但不以作者导航句代替科学论述。

正式正文采用肯定式方法陈述。质量控制直接说明有效观测的判定条件、质量指标与分析单位，不围绕“没有删除什么”“未采用什么”“如果失败怎么办”等防御性审计语言展开。只有直接影响结果分母或科学解释的限制才进入正文。

正文不出现具体实验地点、赛区、校区、采集城市等地点身份信息，也不写匿名标识、身份登记、身份映射、参与者键、场次键等内部身份管理语言。重复参加只说明其形成重复测量，并说明统计上如何处理相关性。

实验设计直接使用读者可理解的描述。`Block` 第一次出现时定义为“任务区块（Block）”，之后主要使用 `Block`。第一阶段写为“6 个 Block，顺序为 A-B-C-C-B-A”，第二阶段写为“3 个相同的 B 条件 Block”，正式实验写为“2 个相同的 B 条件 Block”；正文不使用 BB/BBB 等内部简称。

4.3 的任务是解释正式方案如何由预实验形成，而不是复制完整预实验结果章。正文只保留足以支持设计决策的关键方向性观察和极少量代表数字；完整检验统计、更多指标和支持图表放入预实验支持材料或附录。设计参数本身，例如 No-Go 比例、Block 数量和每个 Block 的试次数，仍在正文保留，因为它们定义了实际实验条件。

4.4 以正式实验的执行与采集逻辑为主体。设备型号、频段、分辨率、帧率、镜头和距离等参数优先集中到“设备与采集参数表”，正文说明三种传感通道分别观测什么、如何布置、如何同步以及如何与任务过程对应，避免参数在段落和表格中重复堆叠。

4.5 执行“科学解释参数留正文、实现参数入附录”的颗粒度原则。正文必须保留算法名称及会改变测量、效应解释或统计结果的关键参数，例如 YOLO26n、RITnet、Motion Energy、EAR、VMD、主要频段、行为阈值、探针窗口和参与者独立验证方式；训练轮次、模型输入尺寸、ROI 重建尺寸、滤波器具体阶数、VMD 内部参数等复现性实现细节主要放入方法附录。附录用于补充而不是替代正文中的方法逻辑。

### 3.1 正文与附录的篇幅分工

正文采用“**完整但不过载**”原则。“不要写太短”意味着一个结果小节不能只剩几句结论或分析提纲；但也不意味着把完整统计审计、所有模型参数和次要结果全部搬进正文。

正文应优先保留：必要的描述统计、能够识别分析的核心方法、主要效应及其不确定性、与研究问题直接相关的关键非显著结果，以及足以支撑结论的样本信息。完整模型表、全部参数、逐 lag/逐窗口结果、模型样本量审计、敏感性分析、QC 和次要指标统一优先放入附录。

这一分工适用于行为、NIR、毫米波、RGB 和多模态章节。不能因为追求简洁把正文压成提纲，也不能因为担心“太短”把单模态专项报告的全部细节复制到总报告。

图表同样执行该原则。正文优先使用能够共同回答一个科学问题的 **2×2 或 2×3 多面板组合图**，而不是每个指标单独占一张图。多个现有单图可以重新排版为组合图，但应统一字体、字号、坐标标注、误差线定义、图例和面板字母；视觉风格不一致时优先根据正式结果表重新生成，不机械截图拼贴。完整单图、候选指标图和 QC 图进入附录。

行为指标使用简洁、可读的名称。Go omission 统一写为“Go 遗漏率”；进一步的时序划分写为“无时序歧义遗漏率”和“时序歧义遗漏率”。第一次出现时说明后二者依据按键时序特征区分，不把“无时序歧义遗漏”直接命名为“注意遗漏”。

NIR 基线采用研究逻辑表述：以每次实验中稳定的典型瞳孔水平描述个体内相对变化；事件相关分析以事件发生前的短时瞳孔水平为参照；实验开始前 3 min 静息阶段仅在眼部具有足够可观测数据时用于探索性比较。正文不使用“session 中心化”“baseline contract”“fallback baseline”等内部词汇。

RGB 正式报告范围固定为整体运动、曝光/亮度变化控制、必要的姿态确认与方向候选、眨眼候选事件。AU、情绪、rPPG、PERCLOS、完整头姿和复杂 RGB 独立预测不作为当前正式主线。前后方向只解释为可见运动方向候选；眨眼在独立事件验证充分之前按候选事件表述。

毫米波方法以当前权威生产证据为准。正式保存的数据为 2T4R、8 通道、256 距离单元的复数距离域 DataCube，Range FFT 已在上游完成；正文不再描述一次不存在的下游原始 ADC 距离 FFT。逐帧时间使用当前核验的采集时间与任务事件对应；HR/BR 保留其当前验证边界，IBI/HRV 仅在逐搏与外部参考验证能够支持生理解释时使用。

多模态比较以共同样本和参与者独立验证为核心。所有模态贡献比较在相同参与者、相同探针窗口和相同外层测试划分上完成。主要方法采用可解释的特征级融合，比较任务背景/行为基准以及毫米波、NIR、RGB 的单模态、双模态和完整组合；复杂 AI 融合属于次级预测分析，以其在相同参与者独立验证下是否提供稳定额外信息为判断依据。

目前没有伦理审批编号、伦理委员会名称或明确的伦理豁免文件。报告只陈述已有资料能够支持的知情同意和实验报酬信息，不自行补写“经伦理委员会批准”、审批编号或伦理豁免。

## 4. 两遍完成与整章复核

每个章节采用“两遍完成”流程。第一遍依据现有报告骨架、补充材料、项目证据和外部文献完成正文；第二遍必须从整章层面重新通读并实际修改，而不是只做禁用词检查。

第二遍优先检查：章节顺序是否形成自然的信息递进；每一节是否有清楚而单一的功能；同一事实是否在多个小节反复定义；前一句与后一句、前一段与后一段是否存在真实的因果或说明关系；技术细节是否压过研究问题；方法是否与后续结果一一对应；预实验是否服务于设计形成而非变成独立结果章；正文与表格、附录之间是否合理分工。完成这些逻辑检查后，再检查工程措辞、中英文术语、地点/身份信息、内部协议简称、防御性语言、章节导航元话语和引用格式。

本规则同时执行用户提供的《竞赛与学术报告撰写规则》（2026-08-28，SHA256=`cb90aa76c4e71cb8f357ed6c1052194410f534e4fd18ec54d007012657b469e0`），尤其遵循“正式正文层”“使用肯定式方法陈述”“以研究逻辑组织段落”和“整章审查先于局部润色”的要求。

## 5. 分步交付方式

完整正文、完整章节参考文献和可直接嵌入报告的文本只写入 `正式报告/章节草稿/` 或相应 `正式报告/附录草稿/`，不在聊天中重复粘贴全文。对话中只回报修改文件、资料来源、组织逻辑、第二遍实际修正的问题、证据边界和需要人工审阅的事项。

## 6. 与正式分析的关系

`分析设计/` 是正式分析的方法总入口，负责样本、重复测量、指标定义、时间窗口、质量控制、统计模型、图表和文献证据矩阵；它不是正式报告正文的存放位置。行为、NIR、RGB、毫米波等模块保存各自分析证据，正式报告引用已经冻结的科学事实。

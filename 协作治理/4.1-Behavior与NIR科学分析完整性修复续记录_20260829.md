## 2. 已追加：event-response 专属 pupil 候选层

新增：

- `src/attention_pipeline/nir_formal_analysis/event_response.py`
- `tests/test_nir_event_response.py`

并接入：

- `scripts/nir_formal_pipeline.py`
- `scripts/nir_build_analysis_tables.py`

这一层不把 peak latency / recovery 强塞进所有 tonic/state window，而是只在显式 trial event 上计算。当前 reference signal 仍只是既有 `binocular_primary`，用于验收事件特征接口，不表示 geom-mean diameter 已被冻结为最终 pupil endpoint。

当前 event-response candidate 包括：

- baseline median / MAD；
- dilation peak amplitude；
- dilation peak latency；
- constriction peak amplitude；
- constriction peak latency；
- dominant peak direction / amplitude / latency；
- recovery tolerance；
- recovery time after onset；
- late-recovery residual / absolute residual。

事件窗口规则：

- baseline：`[-200, 0) ms`；
- response：默认 `[0, 1150) ms`；
- 若下一 trial onset 更早，则 response 在下一 trial onset 处截断，禁止未来 trial 污染当前事件响应；
- baseline / response 分别有最低有效样本数；
- baseline / response 都有最大 temporal gap gate；
- recovery 定义为 dominant peak 之后第一次回到 `max(20% peak amplitude, 1 × baseline MAD)` 容差带内。

恢复规则及其阈值写入 manifest，不能根据结果显著性自动调参。

输出：

- `event_response_candidates/trial_event_response_candidates.csv`
- `event_response_candidates/event_response_failures.csv`
- `event_response_candidates/event_response_manifest.json`

当前角色固定为：

`candidate_event_response_only`

最终冻结状态仍为：

`pending_real_data_scientific_review`

## 3. 已追加：adjustment audit，禁止把非视觉调整冒充视觉调整

新增：

- `src/attention_pipeline/nir_formal_analysis/adjustment_audit.py`

该模块解决一个命名/解释风险：reference model 的 `adjusted` 可能只纳入 time-in-block、coverage、source mode 等质量协变量；如果视觉表缺失或视觉变量没有真正进入拟合，就不能把这条模型称为“视觉调整模型”。

正式规则：

只有同时满足：

1. configured visual table 实际 available；
2. adjusted model 的 covariate set 中实际包含 current / previous brightness、contrast、visible area 或 stimulus size 等视觉变量；

才标记：

`visual_time_quality_adjusted`

否则只能标记：

`time_quality_adjusted_only`

并把 formal visual adjustment status 写为：

`not_estimable`

新增机器可读输出：

- `formal_unadjusted_vs_adjusted_comparison.csv`
- `adjustment_audit_failures.csv`
- `adjustment_audit_manifest.json`

comparison table 保留：

- unadjusted estimate / CI；
- adjusted estimate / CI；
- adjusted-minus-unadjusted；
- absolute / relative change；
- participant-group N；
- session N；
- row N；
- adjustment set；
- 实际 covariates；
- visual adjustment 是否真正可估。

代码本身仍不授权科学推断，也不允许按 p-value 选择 pupil endpoint。

### 4.1 README 给出的正式读取规则

当前正式口径为：

- `questionnaire_derived_data.csv` 是正式分析主表；
- `subject_repeat_registry.csv` 用于身份 / 重复参与审计；
- 两张表都是一行一份问卷 / 一次实验场次，不是一行一个自然人；
- `subid` 是行为、NIR、RGB、毫米波等 session join key；
- `participant_key` 是匿名重复测量聚类 / GroupKFold / mixed model grouping key；
- `experiment_id` 只做原始问卷追溯，不能替代 `subid`；
- session / sensor table 必须作为 left-join 主表，不能从问卷反推完整场次集合；
- `sub-102_` 当前没有有效问卷，不能补造空白问卷行，也不能因此删除其行为/传感器场次。

### 4.2 对本次两张 CSV 的结构审计

实际读取结果：

- `questionnaire_derived_data.csv`：146 rows × 69 columns；
- `subject_repeat_registry.csv`：146 rows × 25 columns；
- 146 个不同 `subid`；
- 81 个不同 `participant_key`；
- 39 个 `participant_key` 对应多个 `subid`；
- participant session-count 分布：42 组只有 1 场、14 组 2 场、24 组 3 场、1 组 4 场；
- 每个 `subid` 只映射到 1 个 `participant_key`，未发现一对多冲突；
- 两张表的 `subid / participant_key / experiment_id / visit_order / prior_visit_count` 逐行一致；
- `visit_order` 无缺失且在每个 participant 内从 1 开始连续；
- `visit_order` 分布：1 次=81 行、2 次=39 行、3 次=25 行、4 次=1 行；
- `prior_visit_count` 与 visit order 对应；
- `sub-102_` 不在两张 CSV 中，与 README 的缺失问卷说明一致。

此外：

- `identity_conflict_flag=1` 有 29 行；
- README / CSV 当前 `identity_match_basis` 为 `phone_digits`；
- conflict fields 主要涉及 age / major / grade / college / handedness 等人口学不一致。

这些 conflict 不能被代码自动解释为 participant_key 无效；但必须保留为 identity QC / sensitivity 字段，正式使用 participant_key 前应把冲突分布写入 audit output。

原治理记录中以下两项原本因为没有 verified registry 而 fail-closed：

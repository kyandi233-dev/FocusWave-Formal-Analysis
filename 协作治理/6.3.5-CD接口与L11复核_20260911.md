## 一、L06 的决定性证据：producer 已产出状态字段，消费者完全不读

### C 分支（行为）的状态字段

`behavior_formal/behavior_supervised_interface.py` 明确声明并要求以下状态列存在：

```
rt_cv_status
rt_slope_status
sdt_status
omission_taxonomy_status
```

并且做了**双向**一致性校验：

```
should_be_estimable      = n_rt >= RT_CV_MATHEMATICAL_MIN_N
wrongly_masked           = should_be_estimable & cv.isna()
wrong_estimable_status   = should_be_estimable & ~status.eq("estimable")
spuriously_present       = ~should_be_estimable & cv.notna()
spurious_status          = ~should_be_estimable & status.eq("estimable")
```

两个方向都报错——既禁止"本可估计却标为缺失"，也禁止"本不可估计却标为 estimable"。**C 的状态字段质量是可靠的。**

### D 分支（NIR）的状态字段

`nir_formal_analysis/supervised_features.py::summarize_supervised_window()` 产出：

| 字段 | 取值 |
|---|---|
| `pupil_level_{mean,median}_status` | `computable` / `not_estimable_no_valid_samples` |
| `pupil_variability_{sd,mad,iqr}_status` | `computable` / `not_estimable_low_valid_samples` / `not_estimable_no_valid_samples` |
| `pupil_trend_robust_binned_slope_per_sec_status` | `computable` / `not_estimable_no_valid_samples` / `not_estimable_low_valid_samples` / **`not_estimable_time_support`** |

**D 明确区分了"样本数不足"与"时间支撑不足"两种不可估计原因。**

### B 分支（消费侧）的读取情况

穷尽检索 `multimodal_formal/quality_admission.py`：

```
→ 对任何 pupil/NIR 的 *_status 字段：零次读取
```

B 对 NIR `pupil_*` 特征的支撑判定完全依赖**列名模式 + `n_pupil_valid` 阈值**：

| B 认定的特征名 | B 要求的最小 `n_pupil_valid` |
|---|---|
| `pupil_diff_mad` / `pupil_diff_rate_mad_per_sec` / `pupil_peak_to_trough` | 2 |
| **`pupil_slope_per_sec`** | 3 |
| 其余 `pupil_*` | 1 |

**而 D 实际产出的列名是 `pupil_trend_robust_binned_slope_per_sec`，不是 `pupil_slope_per_sec`。** B 为"斜率需要 3 个有效样本"设置的专门门槛，作用在一个**不存在的列名**上，实际会落进"其余 `pupil_*` → 最小 1"这一档。

### 后果（按严重度排序）

1. **`not_estimable_time_support` 被完全忽略**：D 判定某窗口趋势因时间支撑不足不可估计，B 只要看到 `n_pupil_valid >= 1` 就判为可算，该行进入 missing-aware 集参与建模。
2. **趋势门槛失效**：B 以为自己在用 3 帧门槛保护斜率，实际门槛是 1 帧。
3. **两个答案不一致**：同一窗口，D 说 `not_estimable`，B 说支撑有效——而下游只信 B。

**B 分支对行为侧的处理是正确的**（读 `sdt_status == "estimable"`，并有测试 `test_behavior_explicit_nonestimable_sdt_is_not_residual_missingness` 覆盖）。**NIR 侧缺少对应的读取逻辑，是同一设计的不对称实现。**

### 需要的动作

1. B 对 NIR 必须先读 D 的 `*_status` 字段，仅在状态字段缺失时才回退到 `n_pupil_valid` 阈值，并把回退标记为降级判定；
2. 修正 B 的特征名清单，使其与 D 实际产出的列名一致（`pupil_trend_robust_binned_slope_per_sec`）；
3. 增加测试：D 输出 `not_estimable_time_support` 而 `n_pupil_valid` 充足时，B 必须判为 `feature_support_invalid`。

## 二、L11：D 分支的双眼切换与时间支撑

### 2.1 双眼融合规则（已核验）

`supervised_features.py::build_raw_binocular_timepoints()`：

```python
both       → (left + right) / 2.0     source_mode = "binocular"
left_only  → left                     source_mode = "left_only"
right_only → right                    source_mode = "right_only"
neither    → NaN                      source_mode = "missing"
```

每个时点都记录 `raw_binocular_source_mode`，并强制 `(session_id, block, unix_ms[, frame_idx])` 无重复、按时间稳定排序。

### 2.2 仍然存在的双眼切换问题

**问题：切换点会引入阶跃跳变，并被 variability 与 trend 当作真实波动吸收。**

两眼瞳孔直径存在系统性差异（anisocoria，瞳孔不等大）与各自的测量偏差。当窗口内在 `binocular` 与 `left_only` / `right_only` 之间反复切换时，合成序列是由三类不同测量拼接而成：

```
binocular 段 = (L+R)/2
left_only 段 = L
right_only 段 = R
```

在 `binocular → left_only` 的切换点上，序列值从 `(L+R)/2` 跳到 `L`，跳变量为 `(R-L)/2`。若两眼差异为 d，则幅值约 d/2。

这个跳变对三类特征的影响：

| 特征 | 影响 |
|---|---|
| level（mean/median） | 影响相对温和，取决于各模式占比 |
| **variability（SD / MAD / IQR）** | **被直接抬高**。SD 对阶跃极敏感；MAD/IQR 只有在跳变帧占比小的时候才稳健 |
| **trend（robust_binned_slope_per_sec）** | **被扭曲**。若切换集中在窗口前半段，会造出一个虚假的单调趋势 |

**当前代码记录了 `raw_binocular_source_mode`，但只用于审计输出**（`audit_supervised_window_support()` 里的 `source_mode_summary`），**不参与特征计算、不做分层、不触发告警。**

### 2.3 时间支撑的处理现状

`supervised_support.py::audit_supervised_window_support()` 已经接受 `available_start_ms` / `available_end_ms`，并报告：

```
window_truncated_by_available_start / window_truncated_by_available_end
available_duration_fraction
max_temporal_gap_sec
automatic_coverage_drop_allowed = False
```

`supervised_probe_table.py::_available_bounds()` 优先取 `block_analysis_start_ms` / `block_analysis_end_ms`，回退到 `available_start_ms`。

**这部分的函数级实现是完整的**，且 `automatic_coverage_drop_allowed=False` 保证了不会静默丢覆盖。D 的 `not_estimable_time_support` 状态也正是由此产生。

**但 L11 的审计原意是"A 与 B 是否正确处理了 D 的支撑信息"，这一点依然是断的**：D 算出支撑不足，B 不读 D 的状态字段（见第一节）。**函数级实现 ≠ 链路级生效。**

### 2.4 需要的动作

**针对双眼切换：**

1. 在窗口摘要中输出 `source_mode` 的**逐模式帧数与占比**（当前只在 support 审计里，未随特征输出）；
2. 对切换频繁的窗口给出明确标记（例如 `binocular_mode_switch_count` 与 `binocular_mode_dominant_fraction`），并在正式分析中作为**排除或分层依据**在看过结果前冻结；
3. **不能直接把拼接序列喂给 SD/MAD/IQR 与斜率**而不做任何处理。至少需要：(a) 只在 `binocular` 帧上计算作为敏感性轨，与 (b) 现有拼接轨并列比较；
4. 增加**受控测试**：构造"双眼各 100 帧、在第 50 帧切换 mode、两眼均值差 d"的合成序列，验证 SD/MAD/IQR 与斜率的抬升幅度可被检出。

**针对时间支撑链路：**

5. 让 B 读取 D 的 `*_status`（同第一节 L06 的动作）；
6. 增加端到端测试：D 的 `not_estimable_time_support` 必须传导为 B 的 `feature_support_invalid`。

## 三、D 分支对 NIR 主信号边界的遵守情况

已核验 `configs/nir_supervised_features_v1.yaml`：

```yaml
base_signal:
  name: pupil_geom_mean_diameter
  zero_calibration: true
  forbidden_session_baselines: [centered, robust_z, participant_within_between]
sensitivity_inputs:
  pupil_iris_ratio_allowed: false
  iris_fraction_as_scale_allowed: false
```

| 《NIR问题.txt》的要求 | D 配置的实际状态 | 判定 |
|---|---|---|
| `pupil_geom_mean_diameter` 是唯一冻结 NIR 主信号 | `base_signal.name` 唯一指定 | 一致 |
| level / variability / trend 围绕它构建 | `feature_schemes` 四个方案全部基于 `pupil_level_*` + `pupil_variability_*` + `pupil_trend_*` | 一致 |
| `seg_pupil_fraction_within_pupil_iris` **不得**并入主候选家族 | `pupil_iris_ratio_allowed: false` 且 `iris_fraction_as_scale_allowed: false` | **一致，配置已明令禁止** |
| 禁止跨会话基线校正 | `forbidden_session_baselines` 三项全禁，`zero_calibration: true` | 一致 |
| 头部运动 / 尺度代理未被验证不得使用 | `head_motion.status: not_validated`、`scale.status: not_validated`，并列出 `qc_fields_not_promoted_to_scientific_covariates` | 一致 |

**D 分支的配置层面完全遵守了《NIR问题.txt》的 Task D 正式边界，不需要修改。**

需要补的是 `nir_mean_sd_trend` / `nir_median_sd_trend` 被标为 `role: primary_candidate`，而 `nir_median_mad_trend` / `nir_median_iqr_trend` 标为 `role: robust_sensitivity_candidate`。这个 `role` 字段目前**只是配置里的字符串标注**，代码层面没有任何强制（对照 A 分支 L04 的同一问题）。若 `role` 要承担科学角色约束，需要有对应的校验实现。

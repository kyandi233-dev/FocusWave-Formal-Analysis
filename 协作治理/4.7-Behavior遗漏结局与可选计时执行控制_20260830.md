# Behavior 遗漏结局与可选计时执行控制（2026-08-30）

## 1. 本轮触发与用户裁决

用户审查此前“五类 Go 状态”后提出：Go omission 本身事件可能较少，不应把所有 timing 情况拆成多个稀疏心理结局；但 `clean_go_omission` 与 `timing_ambiguous_go_omission` 在当前任务中较常见，仍应与程序原始 omission 一起作为正式分析结局。RGB 指标选择暂时暂停，等待后续单独讨论。

因此本轮只继续完善 Behavior/NIR 正式主线，不扩展 RGB 指标。

## 2. omission 最新正式合同

权威程序 `FocusWave/formaltest` 规定每 trial 为刺激 250 ms + 掩蔽 900 ms，共约 1.15 s。Go trial 在该反应期内未捕获空格时由程序记 `omission=1`；`prestimulus_press_ms` 另存刺激上屏前死区按键。

当前代码正式保留：

- `raw_go_omission_rate`；
- `clean_go_omission_rate`；
- `timing_ambiguous_go_omission_rate`。

三者共享 Go opportunity 分母并强制满足 `raw = clean + timing_ambiguous`。`clean` 不写成 `true attentional omission`；更细 prestimulus/carry-over 亚型和 >1150 ms timing candidate 只作 QC/诊断。No-Go commission 继续独立使用 No-Go 分母。

## 3. Attention-Analysis 本轮代码推进

权威代码分支始终为 `codex/formal-analysis-v2-portable`，未新建代码分支。本轮从 `774bf575bc977ef16a7a1bc445e36f56e9876c56` 后继续提交，主要实现：

- `behavior_error_taxonomy.py`：正式化 raw/clean/timing-ambiguous omission，并保留兼容别名与 finer QC flags；
- `omission_candidate_validation.py`：将三个 omission 标为 prespecified formal endpoints，QC timing 字段不升级为主结局；
- `candidate_validation.py`：把三个 omission 纳入总体 Behavior endpoint validation，结构性相关不触发自动删除；
- `omission_endpoints.py`：增加 B1-B2 配对与 `raw=clean+timing-ambiguous` 恒等审计；
- `sart_formal_analysis.py`：增加 `--subjects`、`--list-steps`、`--only-steps`、`--skip-steps` 和逐步骤执行 ledger；subset smoke 输出与 full-cohort formal 输出隔离；
- `nir_formal_pipeline.py`：同样增加可选步骤、计时和 partial-run 语义；

当前代码最新提交应以远端分支实时 HEAD 为准；本记录不以提交文件存在代替 CI/真实数据验收。

## 4. CI 实际发现与处理

扩大 CI 后，Behavior formal contract 测试组全部通过。新纳入的 NIR 测试暴露两个历史测试问题：

1. probe visual exposure 对浮点均值使用 `0.30000000000000004 == 0.3` 的精确比较；已改为数值近似比较；
2. event-response compact fixture 只提供到 onset+300 ms 的 pupil 数据，却默认要求完整 1150 ms response 的末段 recovery 值。当前实现正确地不从“最后一个观测样本”推断协议 response end；测试已改为在需要 late-recovery 的 fixture 中显式给出有效 response/next-boundary，并新增“不得从最后样本偷偷推断 late window”的回归断言。

上述修复不改变正式 NIR 科学参数，只纠正测试的边界假设。

## 5. 三分钟静息段新证据

本轮直接核对 `FocusWave/formaltest/01-MainProgram/main_experiment_msmf.py`：NIR/RGB/mmWave 启动、坐姿调整完成后，程序依次记录 `baseline_start`、执行 `show_resting_baseline()`、记录 `baseline_stop`；最终 `_write_master_timeline()` 将事件和 Unix ms 写入每场 `beh/master_timeline.csv`。

这解决了静息段“如何定位”的问题：下游必须按 timeline 的 `baseline_start → baseline_stop` 切片，而不能取视频最开头固定 180 s。

但 `4.6` 的可观测性门仍未完成最终冻结：pupil-only source 有 observed/missing、RITnet、geometry、ROI、temporal 等质量字段，可以支持 observability audit；具体可用 coverage/连续时长阈值仍必须预先定义，不能根据后续 Behavior 结果调参，也不能把所有 not-observed 自动解释为闭眼。

## 6. 当前放行边界

本轮代码可进入 CI 和本地 smoke 准备，但以下状态仍分开：

- 代码提交；
- CI 通过；
- 本地环境/路径配置成功；
- 1–2 场 Behavior/NIR smoke 通过；
- 当前分析子集真实数据完整运行；
- endpoint/阈值依据真实分布但非结果导向地冻结；
- 报告正式结果成立。

当前 44 session / 38 participant groups / 6 double-session groups 只用于当前已整理分析子集的拓扑校验。正式报告总体仍按最新方法证据记录正式实验 63 名参与者、119 次实验，并在每项结果中报告实际分析分母。

## 2. 身份键统一定义

当前代码存在三层主要身份字段和一个 NIR 兼容别名：

| 名称 | 准确定义 | 治理结论 |
|---|---|---|
| `participant_key` | 问卷/重复登记中已核验的匿名参与者键 | 最高优先级身份来源；缺问卷时保持缺失，不补造 |
| `repeat_participant_id` | 旧 cohort manifest 的匿名重复组列；Behavior 旧统计接口仍读取该列名 | 仅作为 legacy input/provenance 与 Behavior 兼容列名；不再扩展为跨模块标准名 |
| `participant_group_id` | `reconcile_cohort_identity()` 后的统一参与者聚类/分折接口 | 目标为 Behavior、NIR、RGB、cluster bootstrap、混合/重复模型和 participant-disjoint prediction 的唯一内部统计键 |
| `analysis_group_token` | staged NIR pupil-only 仍保留的分析组兼容别名 | 不是第四种身份来源；必须桥接并测试与 `participant_group_id` 一致 |

正式关系固定为：

```text
participant_key（若存在）
        +
经治理验证的 legacy repeat_participant_id（仅缺问卷时可补足）
        ↓
reconcile_cohort_identity()
        ↓
participant_group_id
```

`session_id/subid` 始终是一场实验/采集记录，严禁作为 participant fallback。

## 3. 对另一轮审计结论的纠正与吸收

以下判断被确认：

- 当前没有证据表明代码把 `participant_key` 偷换为 `session_id`；RGB 已有 no-session-fallback gate，identity reconciliation 也不会根据 `sub-XXX` 推断参与者。
- Behavior 后续大量使用 `repeat_participant_id` 确实属于尚未完全收口的兼容层；协调后该列的数值已经被回写为 `participant_group_id`。
- 身份无法解析的 session 应保留单模态 QC/覆盖率，但参与者级推断必须 `not_estimable + reason`。
- 当前 44 session / 38 当前匿名组 / 6 双场重复组是当前 cohort snapshot，不是永久代码常量；未来追加场次必须重新映射和重新生成 participant-disjoint folds。

需要纠正的地方：不能笼统地说“`cohort.py` 会在所有模块中于身份协调前 `included_cohort(require_groups=True)`”。Behavior 的 `prepare_behavior_runtime_config()` 当前是**先 reconcile，再 require_groups**；真正存在该顺序缺陷的是 RGB `_governed_identity()`。

## 4. 身份层待修复门

1. **legacy group validation gate**：当前 `reconcile_cohort_identity()` 只检查 legacy group 与已知 `participant_key` 的一对多冲突；完全没有 questionnaire overlap 的 legacy group 仍可直接变成 `legacy:<id>`。必须读取/定义允许用于聚类的治理状态，例如受控的 `identity_status`，未验证旧组只能保留 session、不得授权 participant inference。
2. **RGB reconciliation order**：RGB 先 `require_groups=True` 再 reconcile，必须改为先保留 governed sessions、再协调身份、最后只在 participant inference gate 要求 resolved identity。
3. **跨模块 identity parity test**：同一 synthetic cohort 必须同时通过 Behavior/NIR/RGB，证明最终 `participant_group_id` 分区完全一致；NIR `analysis_group_token` 只能作为受测别名。
4. **no session fallback**：新增跨模块回归测试，任何 unresolved case 都不得出现 `participant_group_id == session_id` 或由场次号可逆推断参与者键。

## 5. NIR 新发现的正式执行断点

### 5.1 NIR 仍读取旧 Behavior 配置

正式 Behavior science-v3 入口使用 `configs/behavior_formal_v2.yaml` 和 path registry；当前 NIR `configs/nir_formal_analysis.yaml` 仍引用旧 `configs/behavior_formal.yaml`，该旧配置含 D:/E:/F: 机器路径。修复不能只替换文件名，必须让 NIR 复用正式 Behavior runtime preparation、cohort 和 identity reconciliation。

### 5.2 `nir_source_manifest` 双格式竞争

staged `nir_analysis_ready.pupil_only` 对 `@path:nir_source_manifest` 要求 JSON + `sessions[]`；`scripts/formal_multimodal_analysis.py nir-adapt` 对同一路径键要求 CSV。必须冻结唯一正式 materialization 入口；另一条若保留历史/兼容用途，必须使用不同 path key/命名并声明非 authoritative，不能让同一 logical key 同时代表两个 schema。

## 6. RGB lightweight 剩余修复门

RGB 正式轻量范围仍为 Motion/exposure 分轨 → Pose confirmation/direction → independent Blink candidates；PERCLOS/AU/emotion/rPPG/复杂 prediction/fusion 继续 deferred。当前仍需修：

- identity reconciliation order；
- Motion observable/validity 必须纳入 producer 的 `motion_valid / gap_before / irregular_dt` 等质量字段；
- Blink 已计算左右眼一致性，但 closed candidate 还必须显式要求 bilateral consistency；
- runner component status 应优先 Blink 自己的 `blink_status/blink_reason`，不能被 generic primary-face `status` 覆盖；
- radial pose 指标当前是多分量方向符号一致性，不应以 `_per_sec` 命名为物理速率。

这些是工程合同问题，不是 RGB 测量效度或心理学结论。

## 7. active path 与历史资产

本轮不要求删除历史实现。治理原则是：

- 当前正式入口只能有一套；
- legacy config/runner/test 可以保留 provenance、回归或恢复价值，但必须明确标为 legacy/deferred；
- 不得让历史绝对路径 config、旧 NIR adapter、旧 PIR 路线或 heavy RGB science 默认回流 active route；
- 不以“没有在当前 runner 中 import”为理由物理删除历史资产。

## 8. 多模态状态

当前 formal merge/fusion 仍应视为 deferred scaffold。Behavior 兼容列、staged NIR `analysis_group_token`、RGB `participant_group_id` 尚未完全统一为同一内部字段名，因此不能把“存在 merge helper”写成“当前三个模态已经直接 merge-ready”。

下一阶段应先完成单模态身份和加载合同，再恢复正式 merge：row/event location 由 `session_id + block/trial/probe/window/time` 定位，`participant_group_id` 作为合并后的 grouping metadata 和正式 inference/prediction cluster。

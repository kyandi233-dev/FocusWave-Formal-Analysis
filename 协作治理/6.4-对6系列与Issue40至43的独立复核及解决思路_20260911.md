## 二、四个 issue 的核验与改写建议

### 2.1 #40：保留“状态消费缺陷”，不要把回退规则写成普遍许可

B 的 _feature_support_state 不读取 D 新的 pupil_level_*_status、pupil_variability_*_status、pupil_trend_robust_binned_slope_per_sec_status。新趋势字段也未命中旧 pupil_slope_per_sec 的专门 n 条件。这个问题真实存在，本轮重新运行前次合成反例仍可复现。

但需纠正两种表述：

1. 当 D 数值为 NaN 时，B 的 feature_computable 仍因非有限值为 False；错的是 feature_support_valid 可能为 True，随后 eligible_for_missing_strategy=True。应写“显式不可估计可被误归为残留缺失并进入含缺失集合”，不能不加条件地写成“B 已计算出有效趋势”。
2. 四分支尚未集成且没有这次正式运行证据，不能宣布已污染实际模型结果。这里证实的是允许错误纳入的路径。

状态字段缺失时一律回退到 n 阈值，会把未知新 schema、漏传状态、真正时间支持不足重新伪装为通过。更合适的合同：

| 输入情况 | 建议结果 |
|---|---|
| 当前 D schema + 状态 computable + 数值/支持一致 | 可进入后续质量/集合判断 |
| 显式 not_estimable 或 QC失败 | 保留原原因；不归入当前允许插补的残留缺失 |
| 当前 D schema 缺状态列、空状态或未知状态 | schema/状态未知，拒绝正式准入或显式待核验 |
| 已登记旧 schema | 仅允许该版本已验证的适配规则；记录来源、证据及局限 |
| 状态与数值/机会数冲突 | 合同错误，不能简单选择更宽松的一方 |

只比较 B 全部特征名与 D 全部状态名“完全相等”也不适合：B 包含其他模态和历史候选。应对本次请求的 NIR 科学特征子集做逐字段映射校验。

#41 是集成验收依赖，不是 #40 单元验证的前置。B 的状态函数可以用标准化身份键与 D 的真实状态字段单独测试，#40/#42 可与接口工作并行开发。

证据：[B quality_admission](https://github.com/kyandi233-dev/Attention-Analysis/blob/0d1a4d9069051435f90c8557e55a8236f68287df/src/attention_pipeline/multimodal_formal/quality_admission.py)、[D状态输出](https://github.com/kyandi233-dev/Attention-Analysis/blob/a3c6e4893e64ebeb5098f4aeff1f7cdd8697bef6/src/attention_pipeline/nir_formal_analysis/supervised_features.py)。

### 2.2 #41：需要统一接口，但不能以最小常量替代实际输出合同

准确部分：A、B、D 的必需定位键不同；全局 probe 序号与块内序号不是直接别名；没有一个已经完成并验收的新版 D→B→A 集成入口。

不准确部分：

- D 的 PROBE_ID_COLUMNS 不是完整输出字段清单。build_supervised_probe_table 会在输入存在时透传 probe_index_in_block 和 probe_event_id。
- B 的 _probe_index_from_task_a 依次优先读取 probe_index_in_block、probe_order_in_block，最后才用 probe_event_id 正则。因此归档并不完全依赖 event_id。
- issue 引用的是旧 load_modality_table：它固定读取旧文件路径，并在检查 probe index 前先读取 analysis_group_token。D 最小输出直接放入旧路径，首先可能抛 KeyError，而非必定返回空表。
- A 应消费行为、传感特征合并后的正式训练宽表，不是要求 D 单表独自满足含 Q1 的全部 A 输入。probe_event_id 可以由行为权威 probe 字典提供，无须削弱 A 的审计键要求。

本轮执行的三个输入得到：

| 放到旧 NIR 路径的合成输入 | 实际行为 |
|---|---|
| 仅 D 最小键 | KeyError: analysis_group_token |
| 加兼容组键，仍缺块内序号 | 空表 + nir_missing_probe_index_column |
| 再加 D 可透传的块内序号和 event_id | 返回 1 行、无 problems |

所以修复目标应是“定义新版集成契约”，不是把所有失败都归到某一个别名缺失。

建议由 B/集成层建立一次性、版本化的适配器，以权威行为 probe 字典为定位与标签来源。字典保留 participant_group_id、session_id、block_id/block_num、probe_event_id、块内序号、全局序号、probe 时间及窗口身份。用显式映射连接 D；校验一对一、参与者一致、时间一致、30秒主窗口。

缺少映射时停止，不能按每块固定10/20个 probe 做取模或算术推断，也不能用 Q1 相似性猜对应关系。相同全局序号在不同 session 必须保持不同键。

T2.1 应补充“提供权威映射字典”的前提，仅给四个列名不能保证能推导出所有身份语义。已有低层测试共享规范键并无错误，应保留；额外新增真实 producer schema 的集成测试，而不是禁止所有单元测试共享键。

证据：[D实际输出](https://github.com/kyandi233-dev/Attention-Analysis/blob/a3c6e4893e64ebeb5098f4aeff1f7cdd8697bef6/src/attention_pipeline/nir_formal_analysis/supervised_probe_table.py)、[B旧loader](https://github.com/kyandi233-dev/Attention-Analysis/blob/0d1a4d9069051435f90c8557e55a8236f68287df/src/attention_pipeline/multimodal_formal/alignment.py)、[B归档三路索引](https://github.com/kyandi233-dev/Attention-Analysis/blob/0d1a4d9069051435f90c8557e55a8236f68287df/src/attention_pipeline/multimodal_formal/prediction_archive.py)。

### 2.3 #42：核心正确，补完整预期维度和标签来源

B 只核 y_true 取值域，不回指正式 Q1；覆盖循环从实际 predictions 的 set 开始，能遗漏整个未输出集合。本轮重跑反例确认两条均可 PASS，修复方向正确。

证据措辞需小修：现有 _prediction_rows 固定 y_true=1，但 _tables/_prediction_sets 本身没有提供权威 Q1。因此它证明“测试未覆盖标签回指”，不是独立证明“测试已经带错标签却通过”。本轮另提供 Q1=1、y_true=0 的输入，才直接证明后者。

建议：
- 用稳定 probe 键连接独立权威标签表，按固定 Q1 编码核 y_true，跨模型保持一致；标签不属于某个分析集合本身，先核身份/来源，再核成员资格。
- 从显式请求的 set×outcome×model 清单生成预期全集。调用者只验一个集合时要明确传入范围，不能把未请求的其他集合误判为缺失。
- 补空 predictions、整 outcome缺失、整模型缺失、整集合缺失、标签错位、重复键的测试。
- 失败模型行仍保留，并计入归档行覆盖；“归档完整”与“有可用性能”分开。全失败不能生成貌似有效的平均性能。
- 保留 run_id、feature_set_id、membership_type与成员摘要；完整集合和含缺失集合不能仅靠同名 analysis_set_id 混用。

可以优先修，无需等 NIR 接口完成。证据：[归档代码](https://github.com/kyandi233-dev/Attention-Analysis/blob/0d1a4d9069051435f90c8557e55a8236f68287df/src/attention_pipeline/multimodal_formal/prediction_archive.py)、[测试fixture](https://github.com/kyandi233-dev/Attention-Analysis/blob/0d1a4d9069051435f90c8557e55a8236f68287df/tests/test_task_b_analysis_set_audit.py)。

### 2.4 #43：应改成“逐probe预测的参与者等权评价合同”

缺少正式性能汇总、权重决策和区间输出是事实。但“概率平均/多数投票合成一个参与者类别”不适合当前任务：同一个人的 Q1 随 probe 改变，预测对象是窗口，不是一个固定的人类标签。

合成例：真实标签为 [0,1]。预测 [.01,.99] 与 [.99,.01] 的平均概率同为 .5，但平均 log loss 分别约 .01005 和 4.60517，表现截然不同。平均概率可以描述预测专注比例或用于专门校准比较，不能替代预测性能。

建议的主评价方案（待方法负责人冻结）：

1. 每个留出 probe 先计算误差，使用它自己的真实标签与预测概率。
2. 每位参与者内平均误差：L_i = mean_j loss(y_ij,p_ij)。
3. 主汇总 L = mean_i L_i，使参与者等权；同时给按 probe 数加权的汇总作为补充。
4. M0 与 M1 在同一成员集合计算 Δ_i = L_i(M0)−L_i(M1)，再汇总配对增量。
5. 以参与者为簇重采样全部对应 probe/模型预测，重复抽到同一参与者时保留其重复抽样权重。固定 OOF（折外预测）的 bootstrap 只描述这种重采样下的不确定性，不包括完整重训练的全部变异。
6. 对 AUROC 等非可加指标单独定义汇总。单类参与者的 AUROC 不可估计，不能默默记0.5；跨全部参与者 pooled AUROC 与按人宏平均AUROC回答不同问题。
7. 训练权重、内层选择评分和外层报告权重分开冻结。当前 A 有逐行等权拟合和折均 log loss 的实际默认行为，不能说“三者完全没有任何定义”。改变训练权重或内层目标须重跑训练；仅增加预定的最终汇总可消费已有完整折外预测，不必重新做传感器提取。

必须修改 T4.4：

- 正向：最终评价接收合法外层测试预测和真实标签，应成功。
- 负向：这些外层评价结果被传入候选选择、调参、阈值优化或预处理 fit，应拒绝。

官方文档明确区分训练、验证与测试评价；log_loss 也明确是逐样本损失的平均，并支持权重：[交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)、[log_loss](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.log_loss.html)。

T4.3 的“N≥2必须输出有效区间”过强。两个参与者可能产生极不稳定或退化的区间，不同指标还有类别条件。允许显式不可估计/不充分支持，不以有限数值冒充可靠区间。固定种子测试宜在固定环境内或用数值容差，不要求跨版本逐位一致。

建议把其严重性写为“正式性能报告前的必需方法决定”，不把缺少报告模块等同于现有模型的 P0 代码错误。可新建独立评价模块，避免把报告计算塞入训练循环。依据：[A models](https://github.com/kyandi233-dev/Attention-Analysis/blob/83d7f4a6bdd95b291d822f586d87587d80ffa69f/src/attention_pipeline/supervised_learning/models.py)、[A runner](https://github.com/kyandi233-dev/Attention-Analysis/blob/83d7f4a6bdd95b291d822f586d87587d80ffa69f/src/attention_pipeline/supervised_learning/runner.py)。

## 三、NIR生产分母审查的版本误认

6/6.3.2 读了 D 分支 runtime/nir-formal/ritnet_fullclass_metrics.py 的旧320×160路径：total_pixels=analysis_w*analysis_h，输出 pupil_fraction/iris_fraction。这是所读文件的真实内容，但不能据此宣称它就是当前 fullclass-final 的生产路径。

本轮核验 nvidia-cuda-v8 与 amd-DirectML 的 ritnet_fullclass_metric_adapter.py：
- 生产函数是 summarize_final_hard_metrics。
- 接收 valid_source_mask，统计 labels[valid]，分母为 valid_count。
- 输出 hard_pupil_fraction、hard_iris_fraction及对应像素数。
- 人工 padding 预测作为单独 QC 记录。
- NVIDIA final engine 在缺少 valid_source_mask 时直接报错，再将其传给上述函数。

本轮对两条生产分支分别执行同一合成输入：640×400平面，左侧80列为padding且全部预测为瞳孔，有效区内有400个瞳孔像素和9600个虹膜像素。

| 结果 | NVIDIA | AMD |
|---|---:|---:|
| 分母 analysis_valid_pixel_count | 224000 | 224000 |
| 科学计数 hard_pupil_pixels | 400 | 400 |
| 科学计数 hard_iris_pixels | 9600 | 9600 |
| padding中的瞳孔预测QC计数 | 32000 | 32000 |

这直接反驳了对上述生产实现“没有 hard_*、padding从未排除”的断言。因此不要按6系列建议，把 fullclass-final 的 hard_* 映射回旧 pupil_fraction，或针对错误版本修分母。应先由真实批次 manifest 指向生产提交和 schema，再锁定该批次实际路径；当前生产代码正确也不能反向证明所有历史CSV已使用此版本。

还需纠正代数解释：当共同分母为D，(P/D)/[(P+I)/D]=P/(P+I) 的约分是精确的，不是“近似依赖padding比例一致”。真正风险是padding误预测进入P/I、真实裁切/遮挡、分割边界变化，而不只是共同分母数值变化。

纯虹膜类 I 与“虹膜+瞳孔”区域 P+I 要明确；使用 iris_outer_fraction 时分母已经包含 pupil，不能再加一遍。当前计划公式本来明确 hard_iris_fraction 为类别比例，不必把“虹膜该取哪一种”重新变成无依据的候选竞争。

证据：[NVIDIA生产指标](https://github.com/kyandi233-dev/Attention-Analysis/blob/ef24d5762fc8dd66bc570f833a0d48e775240483/runtime/nir-formal/ritnet_fullclass_metric_adapter.py)、[调用与mask门控](https://github.com/kyandi233-dev/Attention-Analysis/blob/ef24d5762fc8dd66bc570f833a0d48e775240483/runtime/nir-formal/ritnet_fullclass_final_engine.py)、[AMD生产指标](https://github.com/kyandi233-dev/Attention-Analysis/blob/dd56f7fc9faccee4d06bb356e9d2df91088f38d3/runtime/nir-formal/ritnet_fullclass_metric_adapter.py)、[既有padding回归测试](https://github.com/kyandi233-dev/Attention-Analysis/blob/ef24d5762fc8dd66bc570f833a0d48e775240483/runtime/nir-formal/tests/test_ritnet_fullclass_metric_adapter.py)。

## 四、RGB眨眼方案需要纠正的逻辑

### 4.1 事件表可以标记帧，逐帧表用于补足可观测性与边界

“事件表不能判断NIR帧是否落在眨眼区间”是明确错误。给定start/end，可以对每个NIR时间t做区间包含判断。本轮由真实_event_table得到事件1033—1066ms，NIR帧1040ms显然位于其中。

但当前end_unix_ms是最后一个闭合候选帧的采样时刻，duration_ms还加了nominal帧间隔。本例duration=66ms，end−start=33ms。因此不能未说明就把end当准确生理开眼时刻或排他终点。应预先定义区间端点、采样支持和缓冲，且不跨session、phase、跟踪/采集缺口扩展。

逐帧表仍重要：它提供可观测性、双眼一致性、跟踪重置与缺口。正确设计是“事件区间 + 逐帧可观测性支持”，而不是二选一。

### 4.2 闭眼候选帧不等于通过时长条件的眨眼事件

本轮一帧33ms闭合候选检查得到 closed_frame_count=1、accepted_event_count=0。说明 blink_closed_bilateral_candidate 可为真，而事件未满足50—1000ms时长条件。

若遮罩所有闭合候选帧，它是更宽的“闭合/遮挡候选敏感性”，不能声称严格使用已筛眨眼事件。长闭眼也可能没有被该blink事件表接纳，却对瞳孔观测重要。需要区分事件类型与遮罩目的。

另外布尔closed=False不等于有效睁眼：该字段由可观测性与一致性条件共同生成，观测无效时也可为False。遮罩应至少有候选闭合、有效非闭合、未知三态。

### 4.3 两边都有unix_ms，不足以证明已同步

相同单位使比较成为可能，不证明设备时钟偏移、漂移和采样相位已经校正。逐帧毫秒完全相等的join会把大量合法观测判成未匹配；需要基于时钟校验和采样间隔确定区间/近邻容差。

6系列建议“未匹配NIR帧直接剔除”，会同时改变观测支持和样本选择。保留未知状态正确，但主轨与遮罩轨的差异可能主要来自RGB可观测性，而非眨眼剔除。建议至少分别报告：
- 原NIR全可用主轨；
- 同一RGB可观测支持内、尚未删候选眨眼的对照；
- 在同一支持内再应用候选遮罩的敏感性轨。

### 4.4 全场参考回退可能破坏零校准/无未来信息要求

_reference 的 all_valid_top30_median_fallback_not_resting_baseline 会使用所输入完整序列。若用完整测试session求参考后生成当前probe遮罩，未来数据可影响当前特征；仅携带fallback标志不解决这个问题。

用于解释性离线敏感性时可显式承认使用整场信息。用于零校准前瞻预测时，则应采用事先冻结的独立参考、合法过去信息，或单独命名为个体校准方案。baseline本身也要核实是否位于预测之前、是否允许作为该任务输入；不能只靠字段名作保证。

SD/MAD/IQR一致性最多减弱少数异常点主导的解释；6系列再次写“支持真实瞳孔变异”仍偏强，不能替代盲于Q1的图像/事件验证。

依据：[RGB候选与事件函数](https://github.com/kyandi233-dev/Attention-Analysis/blob/a3c6e4893e64ebeb5098f4aeff1f7cdd8697bef6/src/attention_pipeline/rgb_formal/blink_candidates.py)。以上并不要求先完成完整眨眼检测器才能开展NIR主研究，但不宜直接照搬6系列的遮罩指令。

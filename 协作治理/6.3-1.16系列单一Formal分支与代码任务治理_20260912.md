# 6.3 1.16 系列单一 Formal 分支与代码任务治理

> 日期：2026-09-12

为避免 1.16 系列随着专题增加不断产生独立 Formal 分支，当前治理规则冻结如下。

1. `FocusWave-Formal-Analysis` 的 1.16 系列唯一权威工作分支为 `codex/code-fix-ledger`。
2. `1.16.1`、`1.16.2` 及后续 `1.16.x` 方法、决策、实施计划均直接维护在该分支，不再为每个专题创建独立 Formal 分支。
3. 已完成专题分支只作为 Git 历史，不再继续提交新内容；当前 `codex/1.16.1-supervised-interpretation-review` 已与 `codex/code-fix-ledger` 同步到同一提交，不再作为独立工作入口。
4. Formal 仓库负责研究问题、统计合同、参数冻结、代码修改计划和最终方法证据；实际代码实现、测试、CI（持续集成）和运行回报进入对应代码仓库 issue（议题）和实现分支。
5. 代码任务原则上采用“一个明确 issue 对应一个实现分支”，不得为了同一方法修改再拆出多个平行小分支，除非存在真实的互斥开发需求且在协作治理中预先登记。
6. 新 issue 可以先建立而不立即开分支。方法合同尚未审阅或实现基线尚未确定时，先保持 issue-only（仅议题）状态，避免产生空分支和废弃分支。
7. 任何实现发现需要修改科学规则时，先回到 `codex/code-fix-ledger` 更新相应 `1.16.x` 文档，再继续代码；不得让临时代码实现反向覆盖 Formal 方法合同。

当前瞳孔/眨眼后续执行入口见：`分析设计/1.16.3-瞳孔与眨眼测量审计及代码修改实施计划_20260912.md`。

## L05：源证据缺失的处理

### 已修复的部分

`quality_admission.py::_source_state()` 在源证据列缺失时，由原来的默认放行改为返回失败态：

```
缺失 source_present / source_readable  ->  (False, False, "source_evidence_missing")
```

配套测试 `test_finite_value_does_not_prove_unverified_source` 验证：删掉 `source_present` / `source_readable` 两列后，该模态全部 `feature_computable == False`，`missing_kind == "structural_source_missing"`，`modality_availability_rate == 0`。

**"数值有限即视为可用"这条最危险的通路被堵住了。**

### 仍未修复的部分

审计的反例 (a) 说的是：**存在键、`source_present`、有限数值，但缺少时间/QC/支撑证据时，仍会判 True**。当前代码中时间与 QC 是**独立列**（`native_qc_valid`、`window_name`），只有显式提供时才会被检查；源证据不缺失 ≠ 时间证据存在。测试里 `window_name` 与 `native_qc_valid` 都是**测试自己补上去的**，`audit_quality` 并不强制要求模态表必须携带时间可用性列。

时间证据是否强制，取决于上游表是否真的带这些列；代码本身**没有**"缺列即失败"的守卫。

**需要的动作**：对预声明的必检证据列（时间对齐证据、原生命名 QC 证据），缺失时应等同于 `source_evidence_missing` 处理，而不是静默跳过。

## L06：是否读取 C/D 的显式 not_estimable

**未修复，且已定位到确切函数。**

`quality_admission.py::_feature_support_state()` 对 NIR `pupil_*` 特征采用**列名规则 + `n_pupil_valid` 阈值**判定支撑：

| 特征名模式 | 最小 `n_pupil_valid` |
|---|---|
| `pupil_diff_mad` / `pupil_diff_rate_mad_per_sec` / `pupil_peak_to_trough` | 2 |
| `pupil_slope_per_sec` | 3 |
| 其余 `pupil_*` | 1 |

测试 `test_nir_no_valid_pupil_samples_are_explicit_support_failure` 验证 `n_pupil_valid == 0` 时判为 `feature_support_invalid`，证据串为 `n_pupil_valid>=1:producer_math_support`。

**问题**：C/D 分支已经产出显式的 `not_estimable` 状态字段（D 分支中 n_valid < 2 时标记 `not_estimable_low_valid_samples`），但 B **完全不读这些状态字段**，而是用自己的一套阈值重新推断。

后果有两个：
1. **同一窗口可能出现两种相反判定**：D 说 `not_estimable`，B 因为 `n_pupil_valid >= 1` 说是可算 → 直接落进 missing-aware 集，把"数学上不可估计"当成"少量缺失"。
2. **阈值来源不唯一**：D 的 `TREND_CANDIDATES` 是 `robust_binned_slope_per_sec`，B 用的是 `pupil_slope_per_sec` 名称模式。B 在第 244 行以 `pupil_slope_per_sec` 与传入的 `feature`（来自第 320 行 `for feature in cols`，即输入表列名）比对；D 对该数值的输出列名是 `pupil_trend_robust_binned_slope_per_sec`（`supervised_features2.py:356`），取值来自 D 内部的 `generic["pupil_slope_per_sec"]`。该名称在 D 内部存在，但未成为输出列名。因此 B 的 3 帧门槛不可达：B 侧比对名与 D 输出列名不对齐，门槛维持默认值，修复点是两侧名对齐，不是补列。

行为侧部分修复：B 对 d'/c/β 会读 `sdt_status == "estimable"`，测试 `test_behavior_explicit_nonestimable_sdt_is_not_residual_missingness` 覆盖了这一条。**NIR 侧没有对应的显式状态读取。**

**需要的动作**：B 对 NIR 也必须优先读 producer 的显式状态字段，仅在状态字段缺失时才回退到 `n_pupil_valid` 规则；并把回退行为标注为降级判定。

## L07：missing-aware 集是否限制"少量"

**未修复。**

`analysis_sets.py::build_analysis_sets()` 的准入逻辑为：

```
feature_complete     = all(feature_computable)
feature_missing_aware = all(eligible_for_missing_strategy)
```

`included_missing_aware` 是**布尔合取**，没有任何数量上限。只要每个必需特征都"有一个有效测量机会"，哪怕整列全部缺失（只要被判为 `single_feature_missing` 而非 `record_missing`），也会进入 missing-aware 集。

测试 `test_analysis_set_is_comparison_specific_and_ignores_unrequested_modality` 正好演示了这一点：`nir_set.included_complete == 3`，但 `nir_set.included_missing_aware == 4`——**多出来的那 1 行正是在 `n` 列上为 NaN 的行**，被整行接受。同测试中 `rgb_set.included_complete == 1`（rgb 表被裁剪到只剩 1 行）。

审计的反例 (b)(e) 描述的"两列全 NaN 仍进 missing-aware、并在线性模型里被训练集中位数填补后标准化为 0"的路径**依然存在**。

**需要的动作**：给 missing-aware 集加显式的缺失比例上限（按"必需特征数"和"参与样本数"两个维度），并把上限值在看过正式结果前冻结。

## L08：分析集标识与键的一致性

**未修复，且已定位到确切位置。**

### 三方键定义对照（实测）

| 分支 | 主键定义 |
|---|---|
| B（`multimodal_formal/alignment.py`） | `KEY_COLUMNS = ("session_id", "block_id", "probe_index_in_block")` |
| D（`nir_formal_analysis/supervised_probe_table.py`） | `PROBE_ID_COLUMNS = ("participant_group_id", "session_id", "block_num", "probe_index_global")` |
| A（prediction_archive 适配器） | 通过 `probe_order_in_block` / `probe_index_in_block` / `probe_event_id` 三选一解析 |

### B 的别名兜底覆盖范围

B 对键名做了别名适配：

```
_PROBE_INDEX_ALIASES = {
    "behavior": "probe_order_in_block",
    "nir":      "probe_index_in_block",
    "mmwave":   "probe_index_in_block",
    "rgb":      "probe_order_in_block",
}
```

并允许 NIR 用 `block_num` 经 `normalize_block()` 映射为 `block_id`。

### 缺口

**`probe_index_global` 在 B 分支四个文件中出现次数为零；`probe_event_id` 仅作为可选字段出现在 `prediction_archive.py` 的正则解析与 `quality_admission.py` 的列名清单里，不是主键路径。**

因此：**D 分支按自己的合同输出 `block_num` + `probe_index_global`，若该表落盘后供 B 读取，B 的别名表不含 `probe_index_global`，会直接报 `nir_missing_probe_index_column` 并返回空表。**

更根本的问题是 `probe_index_in_block`（块内序号）与 `probe_index_global`（全局序号）**语义不同**，不是改名就能对齐。审计原先担心的"`analysis_set_id` 同名不能保证同样本"在此之上还叠了一层：A 的预测归档用 `probe_event_id` 解析出块内序号，D 用全局序号，B 用块内序号——**三条路径的"同一个 probe"定义不统一**。

### 测试为何没发现

`tests/test_task_b_analysis_set_audit.py` 全部数据由 `_tables()` 手工构造，行为表、NIR 表、RGB 表**共用同一份键**（都从 behavior 取 `session_id` / `participant_group_id` / `block_id` / `probe_index_in_block`）。测试从未引入 D 分支真实列名，所以键缺口不可能被这个测试发现。

**需要的动作**：
1. 冻结一套跨分支统一的 probe 键，明确 `block_num` ↔ `block_id`、`probe_index_global` ↔ `probe_index_in_block` 的映射规则或改用统一全局键；
2. 在 B 的输入适配层增加**真实 D 输出列名的契约测试**（用 D 的 `PROBE_ID_COLUMNS` 构造输入）；
3. `analysis_set_id` 的成员校验必须基于键的完全匹配，而非集合名相同。

## L09：预测归档是否核验真实标签

**未修复，且已定位到确切位置。**

`prediction_archive.py::validate_prediction_archive()` 校验了：

- 必需列存在、无空值；
- 预测键唯一；
- `outer_fold_group == participant_group_id`（LOSO 归属）；
- `y_true ∈ {0,1}`，`y_pred ∈ {0,1}`，`probability_positive ∈ [0,1]`；
- 失败行不得伪造预测值与概率，且必须有 `failure_reason`；
- `model_id` 已在 `analysis_sets` 的 `comparison_models` 中声明；
- 预测行必须落在对应分析集成员内；
- 每个 `set/outcome/model` 组合的行覆盖完整。

**但从未把 `y_true` 与 `analysis_sets` / `formal_identity` 里的权威标签做比对。**

测试直接印证了这一点：`_prediction_rows()` 把所有行的 `y_true` 写成常数 `1`，与 `_prediction_sets()` 中的真实标签毫无关系，`validate_prediction_archive` 仍返回 `PASS_PREDICTION_ARCHIVE`。

这正是审计反例 (f) 的情形：**"正式 Q1=1，归档 y_true=0" 仍会 PASS。** 同一个反例还指出：期望两个分析集、实际只输出一个，也会 PASS（当前代码的覆盖检查以 `predictions.groupby("analysis_set_id")` 的实际取值为循环起点，未与期望全集对照）。

**需要的动作**：
1. 归档校验必须把 `y_true` 回联权威标签来源并逐行比对，不一致即报错；
2. 覆盖检查的循环起点应改为 **期望分析集全集**，而非实际出现的集合；
3. 应校验标签来源的 `analysis_set_id` 与预测行一致。

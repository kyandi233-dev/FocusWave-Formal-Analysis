# 代码修复任务台账

本台账是可直接交给网页代码修复任务的缺陷清单与验收合同。它不是正式科学报告，不保存真实结果，不替代各权威代码仓库的 README、配置和测试。所有条目都必须先经过网页代码修复、独立分支/PR 审阅，再由本地任务 fetch 精确提交并在监督放行后运行真实数据。

## 1. 当前事实与仓库边界

FocusWave-Formal-Analysis 是分析证据和跨任务治理仓库，不是 NIR、RGB 或融合算法的权威代码仓库。NIR/RGB/融合唯一代码仓库是 `kyandi233-dev/Attention-Analysis` 的 `analysis/multimodal-integration` 分支，当前已核验基线为 `b2a96c0df6e6db88c599332815fb24cc93c07fe0`。FocusWave 仓库只保存中央契约、分析入口、QC/聚合证据、跨仓库 provenance 和验收记录。

毫米波中央分析代码仍在 `greenboo26/focuswave-multimodal-attention-analysis`；代码修复必须从该仓库的独立分支和 PR 进入，不能把行为或 NIR 临时脚本复制到这里冒充权威实现。

当前队列口径固定为：行为与中央身份分析使用 44 个 session、38 个当前匿名分析组、6 个双场重复组；毫米波当前预检口径为 39 个可加载 session、33 个重复组和 5 个缺失/不可加载 session。具体匿名组键只留在受控数据区，不写入本台账、fixture、聚合表或 Git commit。

## 2. 已发现的工程失败证据

下面全部是工程失败或设计未满足证据，不是科学结论，不得写成“效应不存在”“传感器无效”或任何心理学解释。

### 2.1 NIR 临时运行不完整且模型拟合失败

- 事实：错误的临时 NIR 运行只产生 4 张图；5 项混合模型均出现 `LinAlgError: Singular matrix`。
- 权威修改位置：`Attention-Analysis@analysis/multimodal-integration` 的 `scripts/nir_formal_pipeline.py`（`main`）、`src/attention_pipeline/nir_formal_analysis/cohort.py`（`run_cohort`）、`src/attention_pipeline/nir_formal_analysis/tables.py`（`run_cohort`、`run_subject`、`build_probe_windows`、`build_time_on_task`）。
- 输入契约：先读取既有 `10_analysis_ready` 的受控派生表，再生成 `11_analysis_tables`；输入必须携带 session、probe、时间、左右眼来源和有效性字段，且每一步有完成标记与配置/提交 provenance。
- 输出契约：必须按既有 `analysis-ready → analysis tables → formal pipeline → validation` 顺序生成完整清单、失败清单、QC 和 Figure 01–10 所需数据；单个模型不可估计时必须输出结构化 `not_estimable`/失败原因，不得用空值、降级模型或“成功”状态掩盖。
- 最小合成失败样例：两名合成参与者各一场、所有 probe 的结果完全相同，或设计矩阵只有截距列；期望模型状态为不可估计并保留错误类别，而不是伪造系数。
- 必须新增/修复测试：`Attention-Analysis/tests/test_nir_formal_failure_gates.py`；扩展 `tests/test_nir_formal_analysis.py` 和 `tests/test_nir_pipeline_validation.py`，覆盖完整图清单、奇异矩阵结构失败和 `not_estimable` 传播。
- 验收命令：`python -m pytest tests/test_nir_formal_analysis.py tests/test_nir_pipeline_validation.py tests/test_nir_formal_failure_gates.py -q`；再运行既有 validation 与 Figure 01–10 的合成 smoke。
- 放行门：图清单不完整、任一模型失败被标成成功、或未保留失败原因时，不得进入正式 NIR 分析，也不得写入正式报告。

### 2.2 NIR 把当前亮度用于解释刺激前窗口

- 事实：当前亮度字段被用于解释刺激前窗口；这会把窗口外或刺激后的状态错误连接到刺激前测量。
- 权威修改位置：`Attention-Analysis@analysis/multimodal-integration` 的 `src/attention_pipeline/nir_formal_analysis/tables.py`（`_add_trial_track_linkage`、`build_trial_windows`、`build_probe_windows`、`build_time_on_task`）及 `scripts/nir_pipeline_validation.py` 的时间/亮度验证入口。
- 输入契约：亮度必须带明确时间戳、phase、window 起止和来源；刺激前窗口只能连接窗口边界内或预先定义容差内的亮度，禁止用当前帧或未来状态回填。
- 输出契约：每个连接记录保存时间方向、容差、匹配状态和缺失原因；亮度未通过时间门时只能为缺失/拒绝，不能进入解释变量。
- 最小合成失败样例：刺激前窗口为 `0–1000 ms`，亮度观测为 `1500 ms`，若程序仍得到 `brightness_linked=true` 即失败。
- 必须新增/修复测试：新增时间方向、未来值拒绝、容差边界和亮度缺失传播测试；覆盖 `merge_asof`/窗口连接后的行数与时间顺序。
- 验收命令：`python -m pytest tests/test_nir_formal_analysis.py tests/test_nir_pipeline_validation.py tests/test_nir_temporal_brightness_gate.py -q`。
- 放行门：任何刺激前窗口使用当前或未来亮度、或未记录匹配时间和容差时，禁止进入正式统计。

### 2.3 NIR 不能绕过既有分析层和 Figure 01–10

- 事实：本地 `run_nir_formal_analysis.py` 只保留为失败运行证据，不能作为 NIR 基线、权威入口或上传对象。NIR 正式路线必须回到既有 `analysis-ready → analysis tables → formal pipeline → validation` 和 Figure 01–10。
- 权威修改位置：`Attention-Analysis@analysis/multimodal-integration` 的 `scripts/nir_materialize_analysis_ready.py`、`scripts/nir_formal_pipeline.py`、`scripts/nir_build_analysis_tables.py`、`scripts/nir_pipeline_validation.py`，以及 `src/attention_pipeline/nir_analysis_ready/`、`src/attention_pipeline/nir_formal_analysis/`、`src/attention_pipeline/nir_pipeline_validation/`。
- 输入/输出契约：上一阶段的完成 manifest、配置哈希、代码提交、schema 版本和来源清单必须成为下一阶段输入；验证阶段不得直接读取 production 原始输出绕过 analysis-ready。
- 最小合成失败样例：只提供一张 NIR 图或一张临时结果表，没有 analysis-ready manifest，程序必须拒绝运行。
- 必须新增/修复测试：阶段顺序、manifest 身份、图清单和临时脚本拒绝测试；Figure 01–10 每张图必须有对应数据表、状态和缺失说明。
- 验收命令：`python -m pytest tests/test_nir_analysis_ready.py tests/test_nir_formal_analysis.py tests/test_nir_publication_suite.py -q`。
- 放行门：缺少完整阶段 provenance、只生成部分图、或调用临时脚本时，禁止本地真实运行和正式报告引用。

### 2.4 行为正确率混合 Go 遗漏与 No-Go 误按

- 事实：行为正确率把 Go 遗漏和 No-Go 误按混在一起，分母和错误类型不对应任务设计。
- 权威修改位置：`Attention-Analysis@analysis/multimodal-integration` 的 `scripts/sart_formal_analysis.py`（`stage_extract`、`stage_metrics`、`stage_stats`）以及 `src/attention_pipeline/behavior_formal/extract.py`（`_add_derived`、`validate_formal`）、`src/attention_pipeline/behavior_formal/metrics.py`（`formal_block_metrics`、`cycle_bin_metrics`、`probe_behaviour_link`）。
- 输入契约：每行保留 trial type（Go/No-Go）、刺激结果、反应、RT、block、cycle、session 和 participant cluster；Go omission、Go commission、No-Go commission 和 No-Go correct 必须分开计数。
- 输出契约：分别输出 Go 命中/遗漏、No-Go 正确抑制/误按、各自分母和缺失；总体指标只能由预先定义的公式组合，不能把不同机会数直接相加。
- 最小合成失败样例：1 个 Go 正确、1 个 Go 遗漏、1 个 No-Go 正确、1 个 No-Go 误按。任何把 2 个错误写成一个不带类型的 `error_rate` 或把 4 行当作同一分母的结果均为失败。
- 必须新增/修复测试：新增 Go/No-Go confusion matrix、机会数分母和边界缺失测试；覆盖 block/cycle/session 聚合。
- 验收命令：`python -m pytest tests/test_behavior_formal.py tests/test_behavior_science_v3_contract.py -q`（权威代码仓库）；中央仅做契约/路径 smoke。
- 放行门：错误类型、机会数或分母不透明时，不得进入 d′、c、β、正确率或正式报告。

### 2.5 行为多尺度指标与重复层级不足

- 事实：行为修复必须覆盖探针窗口、区块、场次三个尺度的 RT 水平、SD、MAD、IQR、RT 变异系数、RT 斜率、遗漏/误按、d′、c、β、Q1 和 Q2；当前基线不足以证明这些指标在正确层级计算。
- 权威修改位置：`Attention-Analysis@analysis/multimodal-integration` 的 `src/attention_pipeline/behavior_formal/metrics.py`（`formal_block_metrics`、`cycle_bin_metrics`、`probe_behaviour_link`）和 `stats.py`（`paired_block_effects`、`block_bin_anova`、`rt_drift_mixedlm`、`pre_nogo_stats`、`probe_associations`），入口为 `scripts/sart_formal_analysis.py`。
- 输入契约：主 probe 每事件一行；窗口 10/20/30 秒作为分离敏感性层；层级必须保留 cycle 嵌套 block、block 嵌套 session、session 嵌套 participant cluster；所有重复组使用 44 session/38 group/6 双场口径。
- 输出契约：每一行明确 `unit`、`probe_n`、`session_n`、`participant_group_n`；RT 变异指标只能在有足够有效 RT 的层级计算；斜率必须带拟合范围和有效点数；d′、c、β 必须带 Go/No-Go 机会数和校正方式。
- 最小合成失败样例：同一事件复制为 10/20/30 秒三行并共享同一 session；若被计为 3 个独立 probe，或同一 participant 的两场被拆成独立 participant，均为失败。
- 必须新增/修复测试：多尺度唯一键、窗口分离、RT robust statistics、斜率最小点数、信号检测指标边界、44/38/6 聚合门和 participant-disjoint 切分测试。
- 验收命令：`python -m pytest tests/test_behavior_science_v3_contract.py tests/test_behavior_formal.py tests/test_behavior_formal_stats.py -q`。
- 放行门：层级、窗口单位或重复组分母不明确，或任一要求指标缺少有效样本标记时，禁止正式分析。

### 2.6 Q1/Q2 模型没有正确处理重复测量

- 事实：Q1 名义类别不能画成名义类别的有序折线；Q2 使用 `OrderedModel` 时未处理重复测量层级或合理 cluster。
- 权威修改位置：`Attention-Analysis@analysis/multimodal-integration` 的 `src/attention_pipeline/behavior_formal/stats.py`（`probe_associations`、`rt_drift_mixedlm`）和 `scripts/sart_formal_analysis.py`（`stage_stats`）。
- 输入契约：Q1 明确为四类名义结局；Q2 明确为四级有序结局；模型输入保留 probe、session、participant cluster、block、cycle 和窗口单位。
- 输出契约：Q1 使用名义模型并声明参考类别；Q2 使用重复测量有序模型，或使用预先规定且验证的 cluster 方法；模型记录固定效应、聚类层级、有效样本和失败状态。
- 最小合成失败样例：两名合成参与者各两场、每场多个 probe；若 Q1 仅按 1<2<3<4 的折线拟合，或 Q2 `OrderedModel` 未带 cluster/重复结构，均为失败。
- 必须新增/修复测试：Q1 名义类别不排序测试、Q2 无 cluster 拒绝测试、participant/session 嵌套和参考类别稳定性测试。
- 验收命令：`python -m pytest tests/test_behavior_formal_stats.py tests/test_behavior_model_contract.py -q`。
- 放行门：Q1 被当成有序/连续结果、Q2 没有重复层级、或模型失败被静默丢弃时，禁止正式分析。

### 2.7 B1–B2、错误轨迹和重复组关联混淆

- 事实：B1–B2 的 session 内配对与 participant 重复层级混淆；错误轨迹未做被试内中心化或事件聚类；重复组相关只有两个窗口，可靠性不足。
- 权威修改位置：`Attention-Analysis@analysis/multimodal-integration` 的 `src/attention_pipeline/behavior_formal/stats.py`（`paired_block_effects`、`pre_nogo_stats`、`probe_associations`），以及 `metrics.py` 的 cycle/block 聚合函数。
- 输入契约：B1–B2 先在同一 participant cluster 内形成 session 差值，再以 participant cluster 作为不确定性/重抽样单位；错误事件保留 event、session、block、cycle 和 trial offset，并在 participant 内中心化后再建模。
- 输出契约：配对差值、参与者聚类、窗口数、有效 session 数和有效 group 数分别记录；只有预先定义的多个窗口和足够重复结构才可输出相关，两个窗口只能标记为不可可靠估计。
- 最小合成失败样例：一个合成 cluster 的两场 session 只各有一个窗口；若输出相关系数或把两场当作两名独立 participant，均为失败。错误轨迹若所有事件只减总体均值而未减 participant 均值，也为失败。
- 必须新增/修复测试：session 内配对、participant cluster bootstrap/cluster covariance、participant 内中心化、事件聚类和少窗口 `not_estimable` 测试。
- 验收命令：`python -m pytest tests/test_behavior_formal_stats.py tests/test_behavior_repeat_structure.py -q`。
- 放行门：重复层级被混合、少于预定窗口仍给出相关推断、或错误轨迹未中心化/聚类时，禁止正式分析。

### 2.8 准确率基线、森林图、QC 和报告单位混乱

- 事实：预测准确率未与多数类基线比较；森林图混合单位和重复对比标签；QC 混合不可比计数；session/block 箱线图形成伪比较；数学依赖相关被误作心理关系；候选 0/1 矩阵没有证据权重；报告逐图复述而缺少统一论证。
- 权威修改位置：行为代码仓库的 `src/attention_pipeline/behavior_formal/report.py`（`generate_report`）、`figures.py`（`generate_all`）、`stats.py`（`probe_associations`）；中央现有评估入口 `scripts/evaluate_behavior_supervised_lopo.py` 和 `scripts/plot_formal_behavior.R` 只作为交接索引，不得绕过行为权威仓库改统计实现。
- 输入契约：每个结果带 `unit`、模型/对比标签、重复结构、`probe_n`/`session_n`/`participant_group_n`、基线定义和证据等级；数学依赖相关必须标为测量/工程关系，不能命名为心理关系。
- 输出契约：分类结果同时输出多数类、平衡准确率、ROC-AUC/PR-AUC（适用时）和 participant-disjoint 验证；森林图按单位分面；QC 每个计数附分母；候选矩阵保存候选来源、证据权重、预定义选择规则和状态；正式报告引用过程报告中的已验收结果，而不是逐图复制说明。
- 最小合成失败样例：9 个负类、1 个正类的分类器准确率为 0.90；若没有输出多数类基线 0.90 和类别不平衡警告即失败。一个 probe 结果和一个 session 结果混入同一森林图也必须被测试拒绝。
- 必须新增/修复测试：多数类基线、单位标签/分面、QC 分母、候选权重、依赖相关标签、报告与图清单分离测试。
- 验收命令：`python -m pytest tests/test_behavior_reporting_contract.py tests/test_behavior_model_contract.py -q`，并运行无真实数据的 fixture 图表 smoke。
- 放行门：没有基线、单位混合、QC 分母缺失、候选规则无证据或过程/正式报告混写时，禁止正式分析和发布。

### 2.9 毫米波加载和缺失样本边界

- 事实：毫米波当前只按 39 个可加载 session、33 个重复组和 5 个缺失/不可加载 session 进入预检；缺失 session 不能被当作零值、成功加载或隐式删除。
- 权威修改位置：FocusWave 中央仓库 `greenboo26/focuswave-multimodal-attention-analysis` 的 `scripts/behavior_time_gate.py`（`find_timestamp_path`、`find_mmwave_dir`、`find_timeline_path`、`load_radar_timestamps_ms`、`load_timeline_rows`、`build_record`、`discover_records`）、`scripts/run_timeline_gated_mmwave_quality.py`（`write_manifest`、`run_analysis`），以及 `pipelines/mmwave/run_beijing_sensor_increment_v1.py`（`grouped_oof_auc`、`sensor_state_summary`）。
- 输入契约：每个 session 先由 `master_timeline.csv` 确定 baseline/block/phase，再核验雷达目录、bin/timestamp、采样长度和时间单调性；重复组只用于聚类/participant-disjoint 分析，不用于把缺失补成有效数据。
- 输出契约：manifest 必须分列记录 `n_loadable_session=39`、`n_repeat_group=33`、`n_missing_session=5`、缺失原因和有效输入；所有特征输出附 session、group、窗口和质量状态。
- 最小合成失败样例：合成 session 缺 timestamp、bin 长度为零或 timeline 无对应 marker；期望状态为缺失/不可加载并进入 5 类缺失清单，不能输出全 NaN 的“有效”特征行。
- 必须新增/修复测试：文件字段契约、空/全 NaN、时间长度、严格 JSON、缺失清单、39/33/5 聚合和 participant-disjoint 分割测试。
- 验收命令：`python -m pytest tests/test_mmwave_benchmark_contract_v1.py tests/test_mmwave_production_contract_v1.py -q`，再运行无真实数据的 timeline/manifest smoke。
- 放行门：39/33/5 口径无法复现、缺失原因被吞掉、全 NaN 被当作成功、或未通过依赖预检时，禁止毫米波正式分析。

## 3. 三个既有任务对话的事实整合

本节把已读取的三个任务对话中的可复用事实纳入台账，作为后续网页修复和本地验收的共同输入。它们仍然是工程过程证据，不把失败运行转换成科学结论。

### 3.1 NIR 任务对话补充

- PR27 的隔离最小真实复跑曾覆盖四个场次级标识：031（schema v7、topology 主来源）、032/033（特殊当前来源、schema v6）和 035（历史 YOLO b8/RITnet b16、schema v6）。结构和 QC 可通过，但扩大到正式 44 场不通过。
- 失败/阻塞事实包括：输出 manifest 的 `formal_evidence_commit` 硬编码为旧证据提交，未忠实记录实际代码提交；`phase_segment`、`unix_ms`、`absolute_onset_time`、`next_trial_onset_time` 等跨表连接键 dtype 未统一，真实首次连接出现 `merge_asof` 类型错误；正式行为路径未冻结；baseline/instructions/practice 没有对应行为 trial 组；来源等价性、artifact/hash、schema、模型、ROI/padding、quality track、插值和窗口规则尚未全部冻结。

### 3.3 行为 v3 任务对话补充

行为科学 v3 的分析链固定为：A 样本身份/QC 与有效分析单位；B 整体行为表现画像；C 初始指标与二级指标的内部结构、数学依赖和非冗余；D B1–B2 与 time-on-task 变化；E probe 前局部状态与 Q1/Q2；F 错误前后局部动力学；G 重复 session 稳定性边界；H 候选行为结局多标准筛选；I 可进入报告的结果与不可进入的过程证据。显著性不是唯一筛选标准。

- 主要 probe 模型每个事件只允许一个预先冻结的主窗口或试次数窗口；10/20/30 秒只能是分离的敏感性分析，不能合并成独立 probe。
- Q1 是四类名义结局，不能用连接四类别的折线暗示顺序；Q1 对比必须明确 2/3/4 相对 1。Q2 是四级有序结局；无重复层级的 `OrderedModel` 只能作为受限敏感性，不能进入主图或主结论。
- B1–B2 必须先做 session 内配对差值，再以 participant group 做 cluster bootstrap/混合模型；6 个双场重复组不是 6 个独立 session。cycle 必须嵌套 block/session/participant，并有 block×cycle 和合理相关结构。
- 错误轨迹须按事件、session 和 participant 聚类，至少对 RT 做被试内中心化或相对基线变化；commission 与 omission 分面，不能把绝对 RT 差解释为心理机制。
- session 相关矩阵只能作描述，必须剔除数学同义/互补指标；两个窗口不足以支持稳定重复组相关。候选 0/1 矩阵必须改为有来源的多标准证据权重，不强制生成单一专注分数。
- 所有图按单位/构念分面，不能把毫秒、比例和有序模型系数共用一条横轴；过程报告、正式报告章节、主图和补充图必须分离。网页代码修复未形成合格 PR 前，本地任务不得自行改统计脚本或运行正式全量。

行为 v3 修复不能只修一张图或一个模型。网页任务提交的 PR 必须同时说明并测试以下范围：

- 探针窗口、区块、场次三种尺度的 RT 水平、SD、MAD、IQR、RT 变异系数和 RT 斜率；
- Go 遗漏、Go 误按、No-Go 正确抑制、No-Go 误按，以及带机会数的 d′、c、β；
- Q1 四类名义模型和 Q2 四级有序重复测量模型；
- cycle 嵌套 block、block 嵌套 session、session 嵌套 participant cluster，并明确 block×cycle；
- B1–B2 session 内配对、participant cluster 不确定性、错误事件嵌套和被试内中心化；
- 所有图和表显式区分 probe、session、participant group 的 `n`；10/20/30 秒只作为分离敏感性，不得用重复窗口行数伪造独立样本量；
- 44 session、38 当前匿名组、6 双场重复组只作为聚合口径，具体映射不进入 Git。

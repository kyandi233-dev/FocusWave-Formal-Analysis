## 2. 关键澄清：participant identity 与 modality availability 分开

本项目当前实际风险不是“制造伪参与者”，而是同一个已知 participant/session 可能由于设备、录制或文件问题没有某个模态，例如 RGB 或 mmWave 未录上。

因此正式合同冻结为：

```text
governed cohort / participant identity
  与
per-modality availability / QC
是两个正交层
```

具体规则：

1. 某个已知 participant/session 缺 RGB、mmWave 或 NIR，只能改变该模态的 `source_missing` / `structurally_invalid` / `not_estimable` 等状态；
2. 缺某模态不能删除 Behavior 或其他模态中的该 session；
3. 缺某模态不能改变 participant identity/group；
4. 缺失不能填 0、不能伪装 success；
5. 某一模态 source manifest 只能定义该模态 availability，不能反向定义整个项目 cohort；
6. future paired multimodal analysis 可以显式建立 common-available subset，但必须同时报告原 governed cohort 与各模态覆盖率，不能把 complete-case subset 永久替代整个研究样本。

当前 44 sessions / 38 participant groups / 6 个双场重复组是当前 governed queue 快照，不等于要求每个模态都达到 44/44，也不是永久 study total。

## 3. 本轮实际代码与配置修复

### 3.1 NIR PIR / OAR 语义拆分

用户提供的权威 NIR 说明明确：`fullclass_ocular_aperture_ratio_median/p90` 是 visible ocular mask（sclera + iris + pupil）height/width，可作为 eye-opening QC candidate；它们不是 PIR、iris diameter、MediaPipe EAR、blink 或 PERCLOS。

此前 staged NIR 虽已保存 OAR 数据，但 authoritative analysis-ready manifest 仍存在 `pir_oar_refused` 这类把 PIR 与 OAR 混在一起的历史字段。本轮已修复：

```text
PIR / iris geometry refused = true
ocular-aperture QC preserved = true
ocular-aperture formal endpoint = false
```

当前 authoritative package wrapper 会规范化返回 summary 与 persisted manifest，移除旧 `pir_oar_allowed` / `pir_oar_refused` 混合键。历史 materializer 中旧字段可继续为 provenance/legacy test 保留，但不得定义当前正式科学合同。

同时 `configs/nir_formal_analysis.yaml` 已拆分为：

```text
pir_candidate_allowed = false
iris_geometry_candidate_allowed = false
ocular_aperture_qc_allowed = true
ocular_aperture_formal_endpoint = false
```

### 3.2 公共模态可用性合同

`configs/formal_multimodal_v2.yaml` 已新增/明确 modality availability 合同：

- cohort 独立于单个模态 availability；
- missing modality 不缩减其他模态；
- missing modality 不改变 participant identity；
- 不做 zero imputation；
- 每个模态单独报告 coverage/denominator；
- future fusion 必须显式使用 availability mask。

RGB 当前 runner 已符合这一逻辑：整场 RGB source directory 缺失时保留 governed session，组件状态为 `not_estimable` / `rgb_source_absent`；某一个 component 缺文件只阻断该 component，不反向作废其他已完成 component。

mmWave 继续由外部正式仓库维护，本仓库只冻结跨模态边界：结构性缺失必须 explicit missing/invalid，不能填 0、不能缩减 Behavior/NIR/RGB cohort。

### 3.3 环境 bootstrap

`setup_formal_environment.py` 的 NIR 环境自检新增 `pyarrow` import。由于当前正式 NIR/RGB 下游读取 Parquet/Arrow 资产，若 editable install 或依赖解析不完整，应在环境 bootstrap 阶段就失败，而不是进入真实数据读取后才暴露。

## 6. 新电脑需要优先检查的报错点

### 6.1 环境/Conda

- PowerShell 未 `conda init`，`conda` 不可调用；
- 激活了错误环境；
- editable install 指向旧 clone；
- `ModuleNotFoundError: attention_pipeline`；
- `pyarrow` / Parquet engine 缺失。

### 6.2 路径注册表

- `configs/paths.local.yaml` 未创建；
- `ATTENTION_ANALYSIS_PATHS_CONFIG` 未设置或指错文件；
- 从旧电脑复制了旧盘符；
- `${ENV_VAR}` 没有在新电脑设置；
- path registry 缺新逻辑键；
- 使用未知未来 registry version；
- 外接数据盘未挂载；
- 输出目录不可写。

当前模板 version 3，新电脑推荐直接按 version 3 重建，不要复用缺键旧版本。

### 6.3 NIR manifest 接口

最容易串线的是：

```text
nir_analysis_ready_source_manifest_json
-> current staged JSON

nir_source_manifest
-> legacy CSV adapter
```

两者不能指向同一个文件。出现 `JSONDecodeError`、manifest root 类型错误、`sessions[]` 缺失时先查这里。

### 6.4 modality availability

出现以下现象不应直接判成 participant/cohort 错误：

- RGB 某 session 目录不存在；
- RGB 某 component parquet 缺失；
- mmWave 某场结构性无效；
- NIR 某场未来未列入 NIR source manifest。

应先判断是不是合法 source missing / structurally invalid，并确认其他模态没有被一起缩减。

### 6.5 session/interface key

- 目录名、文件名和表内 `session_id` 不一致；
- cohort/repeat registry/questionnaire 不是同一整理版本；
- `participant_key` 或 repeat mapping 冲突；
- 用 `sub-XXX` 编号猜 participant；
- legacy alias 与 canonical participant grouping 不一致。

### 6.6 Windows 文件系统

- Excel、Python、同步软件占用 CSV/Parquet，导致 `PermissionError` / WinError 32；
- 路径过长；
- 某些外部 executable 对中文/Unicode 路径支持不好；
- 输出盘空间不足。

这些都需要真实新电脑 smoke，GitHub CI 无法证明。

## 10. 后续新电脑最低验收建议

建议不要直接全量。最低顺序：

```text
pull final branch
-> create/verify formal env
-> paths.local.yaml v3
-> portable pytest
-> one known available Behavior session
-> one known available NIR session
-> one known available RGB session
-> one known missing-modality session
-> inspect QC/failure/availability manifests
-> then decide full run
```

特别应保留一个“participant/session 已知，但某个模态确实缺失”的 representative smoke，用来验证缺模态不会错误缩减其他模态 cohort。

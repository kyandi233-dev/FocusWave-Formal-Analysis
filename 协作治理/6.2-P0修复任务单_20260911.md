## P0-1（L06）：B 必须读取 NIR 生产端的显式状态字段

**缺陷位置**

| 角色 | 仓库分支 | 文件 | 函数 | 行号 |

| 消费端 | Attention-Analysis（B） | `src/attention_pipeline/multimodal_formal/quality_admission.py` | `_feature_support_state` | 184, 235–247 |

**判定依据**

D 已经产出完整的 NIR 状态字段族，取值域为闭集：

```python
# supervised_features.py:359-379
level_status       = "computable" | "not_estimable_no_valid_samples"

                                  | "not_estimable_no_valid_samples"
trend_status       = "computable" | "not_estimable_no_valid_samples"
                                  | "not_estimable_low_valid_samples"
                                  | "not_estimable_time_support"

for candidate in LEVEL_CANDIDATES:
    result[f"pupil_level_{candidate}_status"] = level_status
for candidate in VARIABILITY_CANDIDATES:
    result[f"pupil_variability_{candidate}_status"] = variability_status
result["pupil_trend_robust_binned_slope_per_sec_status"] = trend_status
```

B 对 NIR 的支撑判定完全绕开这些字段，只按列名前缀加 `n_pupil_valid` 阈值：

```python
# quality_admission.py:235-247
if modality == "nir" and feature.startswith("pupil_") and "n_pupil_valid" in frame.columns:
    n_valid = pd.to_numeric(frame["n_pupil_valid"], errors="coerce")
    minimum = 1
    if feature in {"pupil_diff_mad", "pupil_diff_rate_mad_per_sec", "pupil_peak_to_trough"}:
        minimum = 2
    elif feature == "pupil_slope_per_sec":
        minimum = 3
    valid &= n_valid.ge(minimum)
    evidence.append(f"n_pupil_valid>={minimum}:producer_math_support")
```

穷尽检索 B 分支全部文件，对任何 NIR `*_status` 字段零次读取。作为对照，同一函数对行为特征读 `sdt_status == "estimable"`，并有测试 `test_behavior_explicit_nonestimable_sdt_is_not_residual_missingness` 覆盖。NIR 侧缺同一逻辑，属同一设计的不对称实现。

**当前行为**

1. D 的 `not_estimable_time_support` 被完全忽略。D 判定某窗口趋势因时间支撑不足不可估计，B 只要 `n_pupil_valid >= 1` 就判为可算，该行进入 missing-aware 集参与建模。
2. B 的斜率门槛作用在不存在的列名上。B 为 `pupil_slope_per_sec` 设 3 帧门槛（第 244–245 行），而 D 实际产出的列名是 `pupil_trend_robust_binned_slope_per_sec`。名称不匹配导致该门槛无法命中，实际按第 237 行 `minimum = 1` 生效。

**期望行为**

B 对 NIR 先读 D 的 `*_status` 字段；仅在状态字段缺失时回退到 `n_pupil_valid` 阈值规则，且回退须在 `feature_support_evidence` 中标记为降级判定。B 的特征名清单须与 D 实际产出的列名一致。

**验收条件**

1. 构造 `n_pupil_valid` 充足但状态为 `not_estimable_time_support` 的输入，B 必须判为 `feature_support_invalid` 且 `eligible_for_missing_strategy == False`；
2. B 的特征名清单与 D 的 `*_status` 字段命名一一对应，可通过静态比对校验；
3. 状态字段缺失时回退到阈值规则，且 `feature_support_evidence` 含降级标记。

**测试用例（含负向）**

| 编号 | 输入 | 期望 |
|---|---|---|
| T1.1（正向） | `n_pupil_valid = 40`，`pupil_trend_robust_binned_slope_per_sec_status = "computable"` | 支撑通过，`eligible_for_missing_strategy` 由缺失策略决定 |
| T1.2（负向，核心） | `n_pupil_valid = 40`，趋势状态 = `"not_estimable_time_support"` | `feature_support_invalid`，`eligible_for_missing_strategy == False` |
| T1.3（负向） | `n_pupil_valid = 40`，波动状态 = `"not_estimable_low_valid_samples"` | 波动特征判为支撑无效 |
| T1.4（降级） | 输入表无任何 `*_status` 列，仅有 `n_pupil_valid` | 仍按阈值判定，`feature_support_evidence` 含降级标记 |
| T1.5（静态） | 比对 B 的特征名集合与 D 的状态字段名集合 | 一一对应，无孤立名（现 `pupil_slope_per_sec` 须被修正） |

**影响范围**

产生"数学上不可估计却进入建模样本"的实质错误，直接污染模型结果。趋势特征尤重：D 因时间支撑不足拒绝估计的窗口，会以 `n_pupil_valid` 充足为由被 B 判为有效并参与训练。

**修复涉及文件**：`multimodal_formal/quality_admission.py`；如采用集中式常量，另需在 B 侧新增与 D 对齐的状态字段映射表。

if index_col not in frame.columns:

## P0-4（L02）：冻结参与者级计分、加权与不确定性

**缺陷位置**

`src/attention_pipeline/supervised_learning/runner.py::run_nested_loso`，行 110–268；元数据段 251–267（校验点 263–266）。

**已正确实现的部分（修复时不得回退）**

`metadata` 显式声明：

```python
# runner.py:263-266
"outer_method": "leave_one_participant_out",
"zero_individual_calibration": True,
"outer_test_outcomes_passed_to_model": False,
"upstream_analysis_set_generation_in_task_a": False,
```

并在三处校验训练/测试参与者不相交：行 145（外层划分）、行 147（外层测试集恰好含被留出参与者）、行 183（最终重拟合后复核）。`models.py` 的嵌套选择只使用外层训练行，评分标准为 `mean_inner_log_loss`，`outer_test` 仅在最终 `refit_logistic_and_predict` 时接触。

**判定依据**

产出终止于逐 probe 的预测行（一行一个 held-out probe × model），缺失三件事：

1. 参与者级计分规则：一个参与者有多个 probe，如何合成参与者得分未定义。可选方案至少包括 probe 概率平均、多数投票、加权平均，三者在类别不均衡下结论可能不同；
2. 参与者级加权规则：不同参与者的 probe 数不同时，参与者级汇总是否等权未定义；
3. 不确定性估计：`fold_audits` 记录每折的 `n_outer_train_rows` / `n_outer_test_rows` / `selection.selected_c` / `mean_inner_log_loss`，但没有任何置信区间、bootstrap 或簇稳健标准误。跨参与者的性能变异性无法从当前输出得到。

`reporting.py` 的校验覆盖行数一致、折审计条数一致、失败键一致，属归档完整性校验，不涉及计分与不确定性。

**期望行为**

在正式出结果前冻结：参与者级计分规则、参与者级加权规则、不确定性方法（建议参与者级 bootstrap 或簇稳健区间）。三者写入 `分析设计/1.15.5` 的正式口径，并在看过结果前定稿。

**验收条件**

1. 参与者级计分与加权规则在正式口径文档中显式冻结；
2. 不确定性方法选定并实现，输出含区间估计；
3. 增加测试：给定已知逐 probe 预测与参与者归属，参与者级得分与区间可复现（固定随机种子）。

**测试用例（含负向）**

| 编号 | 输入 | 期望 |
|---|---|---|
| T4.1（可复现） | 固定逐 probe 预测与参与者归属，固定种子 | 参与者级得分与区间逐位复现 |
| T4.2（加权） | 参与者 A 有 3 个 probe、参与者 B 有 9 个 probe | 输出同时给出等权与按 probe 数加权两种结果，且文档标明主口径 |
| T4.3（区间） | 参与者数 N ≥ 2 | 输出含区间估计（bootstrap 或簇稳健），不得仅为点估计 |
| T4.4（负向，泄漏） | 参与者级汇总中出现该参与者的外层测试预测 | 必须报错——汇总不得反向进入模型 |
| T4.5（负向，退化） | 参与者级计分规则未在口径文档中声明 | 正式运行入口拒绝出结果，而非默认某种规则 |

**影响范围**

参与者级推断无法进行。以参与者为单位的效应量与区间估计缺乏定义，跨参与者的性能差异无法量化。

**修复涉及文件**：`supervised_learning/runner.py`（新增参与者级汇总与区间输出）、`supervised_learning/reporting.py`（新增汇总校验）、`分析设计/1.15.5`（口径冻结）、新增测试文件。

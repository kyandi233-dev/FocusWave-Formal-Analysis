# 静息期眼部可观测性探索与网页优先流程（2026-08-30）

## 1. 用户确认的协作优先顺序

后续管线治理固定为：

1. 监督任务直接进入已有网页版完整管线治理对话；
2. 监督任务与网页版逐问逐答，把科学定义、权威仓库/分支、修改位置、输入输出、测试与验收问清；
3. 网页版提交后，由专门 Git 同步任务核验远端、完整提交和干净工作树；
4. 监督任务基于同步后的代码与资料形成完整任务包；
5. 最后才向本地具体执行任务下发。

不得让本地子任务代为操控网页版，也不得把网页版尚未澄清的要求交给本地子任务自行解释。默认不开多个同类网页对话；已有完整管线对话优先闭环。

## 2. 三分钟静息段的事实边界

正式程序有约 3 分钟静息采集，但很多参与者可能闭眼。因而：

- 不能假定所有场次都有可用的瞳孔静息基线；
- “没有探测到眼睛”可能来自闭眼，也可能来自遮挡、姿态、光照、画面或算法质量失败，代码和报告不得自动把所有不可探测状态都命名为闭眼；
- 静息段可用于探索“静息期眼部可观测性不同的场次，在后续任务期表现、瞳孔质量或候选指标上是否存在描述性差异”；
- 这种比较存在非随机选择与可观测性偏倚，不能解释为静息瞳孔水平导致后续注意表现差异。

## 3. 网页版下一轮应先澄清和实现的内容

该支线只交给网页版完整管线对话设计和修改权威代码，当前不下发本地真实数据执行。网页版任务必须在 `kyandi233-dev/Attention-Analysis@codex/formal-analysis-v2-portable` 上完成，并先逐项回答：

1. 正式程序中三分钟静息段的权威起止事件如何定位，是否存在跨版本差异；
2. 现有 NIR producer 哪些字段能区分眼部被检测、瞳孔几何有效、遮挡/边界/时间缺口和其他质量失败；
3. 哪些状态可以由数据事实支持，哪些只能写成“不可探测”而不能写成“闭眼”；
4. 眼部可观测性门槛如何在不查看后续行为结果的情况下预先冻结；
5. 对可观测场次计算哪些静息候选指标，对不可观测场次保留哪些缺失原因；
6. 如何用参与者安全的描述和模型比较后续差异，同时报告重复场次与选择偏倚；
7. 需要增加哪些合成测试、输出表、失败表、图表覆盖项和中文题注。

## 4. 预期代码与输出合同

在网页版完成上述澄清前，不指定临时脚本。若决定实现，应接入现有 NIR 正式入口、配置、manifest 和测试体系，至少输出：

- 静息段定位审计；
- 每场静息期眼部可观测性状态与原因；
- 可观测覆盖率、连续有效时长和质量分量；
- 对合格场次的静息瞳孔水平、稳健离散、时间趋势和动态候选；
- 可观测与不可观测场次在后续任务期行为、NIR质量和候选指标上的描述性比较；
- 参与者数量、场次数量、重复参与者结构、缺失和不可评估状态；
- 图内无标题的图表、外置中文题注、机器可读图表覆盖与来源 manifest。

该探索不进入所有主模型的强制调整层，也不能用结果显著性反向选择可观测性阈值。

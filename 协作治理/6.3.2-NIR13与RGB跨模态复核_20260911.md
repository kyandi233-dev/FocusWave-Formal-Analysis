## 一、生产端分母核验（《NIR问题.txt》要求的第一项）

### 1.1 已核验的代码位置

| 文件 | 作用 |
|---|---|
| `runtime/nir-formal/ritnet_fullclass_metrics.py` | 四类分割分数的实际计算处 |
| `runtime/nir-formal/ritnet_fullclass_contract.py` | 冻结的类别映射与版本号 |
| `runtime/nir-formal/run_pipeline.py` | 单被试运行入口（YOLO 跟踪 + RITnet 调用） |
| `src/attention_pipeline/nir_pupil_only/adapter.py` | NIR 消费端适配器 |

### 1.2 分母结论

`ritnet_fullclass_metrics.py::_assemble_result` 中：

```
total_pixels = analysis_w * analysis_h          # 默认 320 × 160 = 51200
background_fraction   = counts[0] / total_pixels
sclera_fraction       = counts[1] / total_pixels
iris_fraction         = counts[2] / total_pixels
pupil_fraction        = counts[3] / total_pixels
iris_outer_fraction   = (counts[2] + counts[3]) / total_pixels
```

并在函数末尾强制断言：

```
counts[0] + counts[1] + counts[2] + counts[3] == total_pixels
```

**判定：`pupil_fraction` 与 `iris_fraction` 来自同一帧、同一眼、同一 analysis domain、同一分母 `total_pixels`，且四类互斥不重复计数。**
→ NIR 1.3 放行条件 1「producer 代码确认 pupil/iris fraction 使用同一分析分母」**在字面上成立**。

### 1.3 但存在两处文档未覆盖的缺陷

**缺陷 A：分母未排除复制填充（padding）**

`analysis_valid_pixel_fraction` 与 `predicted_in_padding_fraction` 是**并行独立的 QC 字段**，从未参与分母构造。若 RITnet 输入做了 letterbox 填充，填充像素计入 `total_pixels`，会同时压低 `pupil_fraction` 与 `iris_fraction` 的绝对值。

对 `seg_pupil_fraction_within_pupil_iris` 而言，由于分子分母同乘一个公共因子，**该比值对 padding 近似不变**——但这个"近似"依赖填充比例在 pupil 与 iris 上完全一致。在 `roi_clipped` / `touches_roi_edge` 为真的帧上，填充会不均匀地吃掉 iris 类像素，此时比值会被系统性抬高。`normalization_valid` 字段虽然检查了 `touches_roi_edge`，但**它保护的是几何归一化路径，不保护 fraction 比值路径**。

**缺陷 B：字段命名存在生产版本断裂**

- `hard_pupil_fraction` / `hard_iris_fraction` 属于 **fullclass-final** 阶段命名。
- 当前 `ritnet_fullclass_contract.py` 声明 `EXTENSION_VERSION = "ritnet-fullclass-v1.2-fast-qc"`。
- `run_pipeline.py` 全文**不含** `hard_*` 任何字段；当前输出的是 `pupil_fraction` / `iris_fraction` / `iris_outer_fraction`。
- `nir_pupil_only/adapter.py` 的 `SOURCE_NUMERIC_FIELDS` 里 `hard_pupil_fraction` / `hard_iris_fraction` 与 `soft_pupil_fraction` / `soft_iris_fraction` 并列声明为透传字段。

**仓库中没有 `hard_*` → `pupil_fraction` / `iris_fraction` 的显式兼容层或映射表。**

这意味着：NIR 1.3 计划书里写的公式用旧名，当前生产管线吐新名，两者之间缺少书面映射。若直接按文档公式实现，消费端存在读到全空列的风险。
另外语义上也需注意：生产端 `iris_fraction` 是**纯虹膜类比例**，而 `iris_outer_fraction` 才是虹膜+瞳孔。NIR 1.3 需要的"虹膜"若指外虹膜环，则应取 `iris_outer_fraction` 再减去 pupil，语义需明确。

### 1.4 结论与需要回填的验收条件

| 项 | 状态 | 需要的动作 |
|---|---|---|
| 同分母 | 成立 | 无 |
| padding 排除 | 未处理 | 明确 `seg_*` 是否排除 padding；若不排除，需给出 `roi_clipped`/`touches_roi_edge` 帧的排除或分层规则 |
| 字段名映射 | 缺失 | 在 1.3 中补一张 `hard_*` → 当前字段 的映射表，并指明取自哪个 `EXTENSION_VERSION` |
| `iris_fraction` 语义 | 待明确 | 明确公式中"虹膜"是 `iris_fraction`（纯虹膜）还是 `iris_outer_fraction - pupil_fraction`（环） |

## 二、RGB 眨眼输出的时间戳契约（《NIR问题.txt》要求的第二项）

### 2.1 已核验的代码位置

`src/attention_pipeline/rgb_formal/blink_candidates.py`（14373 bytes）

### 2.2 输出结构

`derive_blink_candidates()` 返回三元组 `(per_frame_df, events_df, status_dict)`，落盘为：

| 产物 | 粒度 | 关键字段 |
|---|---|---|
| `{session}_blink_candidate_frames.parquet` | **每帧一行** | `unix_ms`、`blink_closed_bilateral_candidate`、`blink_bilateral_observable`、`blink_bilateral_valid_for_event`、`bilateral_eye_consistent`、`blink_event_id`、`blink_segment_break` |
| `{session}_blink_candidate_events.parquet` | **每事件一行** | `blink_event_id`、`start_unix_ms`、`end_unix_ms`、`duration_ms`、`frame_n`、`event_type = "algorithm_defined_blink_candidate"` |

### 2.3 时间单位与对齐可行性

- **单位：Unix 毫秒（`unix_ms`）**，逐帧表与事件表同一基准。
- **NIR 侧同样具备 `unix_ms`**：`nir_pupil_only/adapter.py` 的 `SOURCE_TIME_FIELDS` 含 `unix_ms` / `video_time_ms` / `phase_time_ms`，且校验组内 `unix_ms` 严格单调。
- **两侧可直接按时间戳匹配，无需额外换算。**

### 2.4 跨模态打标必须使用逐帧表而非事件表

事件表只给出区间端点 `start_unix_ms` / `end_unix_ms`，无法回答"NIR 的第 k 帧是否落在眨眼区间内"这种逐帧问题。若要在 NIR 帧上打眨眼标记，**必须使用逐帧表的 `unix_ms` 与 `blink_closed_bilateral_candidate`**，事件表仅用于汇总与人工核对。

### 2.5 已知限制（必须写进敏感性轨道的说明）

1. **不是真值标注**：`event_type` 明确为 `algorithm_defined_blink_candidate`，`manual_visual_validation_performed: False`。它是算法定义的候选，不能声称识别了每一次眨眼。
2. **阈值依赖基线期**：开眼参考取 `baseline` phase 的 top30 median，不足 `minimum_valid_frames=30` 时回退到 `all_valid_top30_median_fallback_not_resting_baseline`。若基线不足，参考值不是静息基线，闭眼判定阈值会偏移。回退发生时 `reference_fallback_not_resting_baseline` 为真，**该标记必须随轨道一并传递**。
3. **PERCLOS 被显式禁用**：`perclos` 状态为 `disabled_deferred`，不可用于本轮。

## 三、双轨设计（原始 NIR 质量轨 + RGB 眨眼掩蔽敏感性轨）

《NIR问题.txt》要求保留**两条轨**，而不是用 RGB 掩蔽替换 NIR 质量轨。落成可执行规则如下：

### 轨 1：原始 NIR 质量轨（主轨，不变）

- 输入：全部 NIR 有效帧，不做眨眼剔除。
- 主信号：`pupil_geom_mean_diameter`。
- 窗口：probe 前 30 s（严格 `[probe-30s, probe)`）。
- 特征：level（mean/median）+ variability（sd / mad / iqr）+ trend（`robust_binned_slope_per_sec`）。
- 该轨**保持不变**，是当前正式主线的唯一载体。

### 轨 2：RGB 眨眼掩蔽敏感性轨（附加轨，仅作敏感性）

- 输入：NIR 帧按 `unix_ms` 与 RGB 逐帧表的 `unix_ms` 匹配，剔除 `blink_closed_bilateral_candidate == True` 的帧，**以及**匹配不到 RGB 帧的 NIR 帧（标记为不可判定，不默认为睁眼）。
- 窗口：与轨 1 完全相同的 30 s probe 前窗口。
- 特征：用**同一套** level/variability/trend **重新计算**瞳孔摘要。
- 变异指标必须同时给出 SD、MAD、IQR 三者，并按 1.3 §4.2 的判断逻辑判定：
  - 若 SD、MAD、IQR 方向一致且轨道 1/轨 2 结论不依赖高 QC 帧窗口 → 支持真实瞳孔变异解释。
  - 若仅 SD 显示效应、MAD/IQR 不支持，且 SD 与异常帧比例或瞬时跳变高度相关 → 优先解释为眨眼/遮挡/分割敏感性，不解释为生理性瞳孔波动。

### 关键约束

1. **两轨都保留、都输出**。不得以"已掩蔽眨眼"为由删掉原始轨，也不得以"原始轨已够用"为由不跑敏感性轨。
2. **掩蔽后的帧数必须随结果输出**（每题每窗的有效帧数、被掩蔽帧数、未匹配帧数），供事后判断窗口是否被过度稀疏化。
3. **不因敏感性轨结果反向调整轨 1**。轨 2 是审计工具，不是新主指标来源。
4. **阈值不得事后调**：`relative_openness_threshold=0.20`、`minimum_closed_duration_ms=50`、`maximum_closed_duration_ms=1000`、`gap_reset_ms=250`、`maximum_bilateral_relative_difference=0.35` 若要改动，需在看过正式结果**之前**冻结。

## 四、R_seg 的方法学定位

`seg_pupil_fraction_within_pupil_iris` 的定位必须写成一条明确表述，避免被误读：

1. 它是 **segmentation-normalized relative indicator（分割归一化相对指标）**，**不是** PIR（pupil-to-iris ratio，瞳孔-虹膜直径比）。
2. **不做平方根变换**。平方根变换是传统 PIR 为把面积比拉回直径尺度而设，本指标没有独立验证过的虹膜几何直径，套用平方根变换会制造一个无物理意义的量。
3. 它**不能**取代 `pupil_geom_mean_diameter` 成为 NIR 主信号，只能作为独立敏感性指标。
4. 它**不得并入 Task D 的 `feature_schemes`**。已核验 D 分支的 `D_nir_supervised_features_v1.yaml` 中：
   - `pupil_iris_ratio_allowed: false`
   - `iris_fraction_as_scale_allowed: false`
   即任务 D 当前配置已明文禁止把虹膜分数或 pupil/iris 比值纳入候选。**该配置与《NIR问题.txt》的边界要求一致，无需修改。**
5. 它的规模不变性（scale invariance）只在有限条件下成立：**分母共同尺度可约，但眼睑遮挡导致可见虹膜面积减少、瞳孔面积相对保留时，比值会被抬高，且这个抬升不会被共同尺度归一化自动消除。** 这正是 1.3 §4 专项验证要检查的现象。

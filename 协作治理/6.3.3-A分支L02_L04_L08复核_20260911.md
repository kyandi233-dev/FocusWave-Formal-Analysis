## L02：参与者加权/计分/不确定性

### 设计上做对的部分

`runner.py::run_nested_loso()` 的 `metadata` 显式声明了三项关键约束：

```
"outer_method": "leave_one_participant_out"
"zero_individual_calibration": True
"outer_test_outcomes_passed_to_model": False
```

并且有对应的强制校验：
- `REQUIRED_PROBE_LOCATORS = ("session_id", "block_id", "probe_event_id")` 为必需列；
- `outer_train` / `outer_test` 参与者在 `_validate_frame` 与主循环中两次校验不相交；
- `outer_test` 必须恰好只含被留出的那个参与者；
- 最终重拟合后再次检查 `train_group_ids` 与 `test_group_ids` 无交集。

`models.py` 的模型选择只用外层训练行，内层用 `GroupKFold` 做参与者分组交叉验证，评分标准为 `mean_inner_log_loss`，`outer_test` 只在最终 `refit_logistic_and_predict` 时接触。**外层测试结果不参与模型选择，这一点是干净的。**

### 仍未解决的部分

**审计说的"参与者加权/计分/不确定性未冻结"在当前代码中依然成立。**

`runner.py` 的产出终止于**逐 probe 的预测行**（一行一个 held-out probe × model），没有：

1. **参与者层面的计分规则**：一个参与者有多个 probe，如何合成一个参与者得分？未定义。可选方案至少包括 probe 概率平均、多数投票、probe 加权平均，三者在类别不均衡下结论可能不同。
2. **参与者层面的权重规则**：不同参与者的 probe 数不同时，参与者级汇总是否等权？未定义。
3. **不确定性估计**：`fold_audits` 记录了每折的 `n_outer_train_rows` / `n_outer_test_rows` / `selected_c` / `mean_inner_log_loss`，但**没有任何置信区间、bootstrap 或簇稳健标准误**。跨参与者的性能变异性无法从当前输出得到。

`reporting.py` 的校验只覆盖行数一致、折审计条数一致、失败键一致，属于**归档完整性**校验，不涉及计分与不确定性。

**需要的动作**：在正式出结果前冻结（a）参与者级计分规则、（b）参与者级加权规则、（c）不确定性方法（推荐参与者级 bootstrap 或簇稳健区间）。三者都必须写进 1.15.5 的正式口径，并在看过结果前定稿。

## L04：特征族约束能否保证科学角色与模态构成

### 已实现的三层黑名单

`feature_schemes.py::validate_mainline_feature_scheme()` 会拒绝：

1. **标签泄漏**：`Q1_BINARY_SPEC.source_column`、`q1_binary`、`p_q1_equals_1`、`predicted_q1_binary`；
2. **构造混淆**：`q2_ordinal_4level`（明确标注为"解释/构念验证，非首轮 Q1 预测变量"）、`omission_rate`（历史别名）、`clean_go_omission_rate` 与 `timing_ambiguous_go_omission_rate`（标注为描述性/QC）；
3. **历史与身份字段**：`hard_pupil_fraction`（标注为"首轮 NIR 主线之外的历史已验证字段"）、`participant_group_id`、`repeat_participant_id`、全部 locator 与 window 字段、`analysis_set_id` / `run_id` / `model_id` / `outer_fold_group`。

另有 `_FORBIDDEN_SUFFIXES = ("_within", "_between")`，拒绝一切人内/人际分解特征，与零个体校准路线一致。

**这三层黑名单是有效的，且 `hard_pupil_fraction` 被明确挡在预测变量之外——与《NIR问题.txt》要求的 Task D 边界一致。**

### 核心缺口仍然存在

`FeatureScheme` 有 `modality_blocks: tuple[str, ...]` 字段，但**它只被校验"非空"和"无重复"，从不与 `columns` 里实际使用的列做交叉验证**。

穷尽检索 A 分支全部文件，`modality_blocks` 出现在 13 处，其中 12 处在 `feature_schemes.py`（定义与格式校验）、1 处在 `entrypoint.py`：

```
entrypoint.py:116    expected_blocks = frozenset(schemes[0].modality_blocks)
entrypoint.py:118    if frozenset(scheme.modality_blocks) != expected_blocks:
entrypoint.py:120        raise ... "all candidates within model family {name} must use the same modality_blocks"
```

`entrypoint.py` 只要求**同一 model family 内各候选声明的模态块相同**，不要求声明的模态块与列的实际归属相符。

**后果**：一个 scheme 可以声明 `modality_blocks=("nir",)` 而 `columns` 里放入行为列，或声明 `("behavior", "nir")` 而实际只用了行为列，校验全部通过。审计所说的"特征族约束不能保证科学角色/模态构成"在此没有任何改善。

这直接影响 M0–M7 的可比性：如果模态构成只能靠声明而不能核验，那么"M0 纯行为"与"M1 行为+NIR"的区分就依赖人工填写的元数据，而不是代码保证。

**需要的动作**：
1. 建立**列 → 模态块**的映射来源（例如由上游表在落盘时标注每个特征列所属模态，或由已冻结的列名前缀规则生成）；
2. 在 `validate_mainline_feature_scheme` 中加一致性校验：`columns` 的实际模态集合必须等于 `modality_blocks` 声明的集合；
3. 增加负向测试：故意声明错误的 `modality_blocks`，必须报错。

## L08：A 侧的键契约

### A 的必需定位键

```
REQUIRED_PROBE_LOCATORS = ("session_id", "block_id", "probe_event_id")
```

`probe_event_id` 是**必需列**，而 `probe_index_global`、`probe_index_in_block`、`probe_order_in_block` 都在 `OPTIONAL_PROBE_LOCATORS` 里。

### 与 B、D 的对照

| 分支 | 主键 |
|---|---|
| A | `session_id` + `block_id` + **`probe_event_id`** |
| B | `session_id` + `block_id` + **`probe_index_in_block`** |
| D | `participant_group_id` + `session_id` + **`block_num`** + **`probe_index_global`** |

**A 需要 `probe_event_id` 且它是必需列，但 D 分支的 `PROBE_ID_COLUMNS` 不产出 `probe_event_id`。** B 的预测归档适配器 `normalize_task_a_predictions` 正是从 `probe_event_id` 用正则 `\|probe\|(\d+)$` 反解块内序号——也就是说，这条链路的可用性**完全依赖 `probe_event_id` 的存在**，而 D 不提供它。

**键不一致的链路后果**：
- D 按自己的合同输出 `block_num` + `probe_index_global`；
- A 要求 `block_id` + `probe_event_id`；
- B 要求 `block_id` + `probe_index_in_block`，且别名表里没有 `probe_index_global`。

三方需要各自做一次转换才能串联，而**没有任何一处代码或文档定义了这些转换**。

**需要的动作**：冻结一套跨分支统一的 probe 键，并在 D 的输出层增加 `block_id` 与 `probe_event_id` 的生成（或明确由哪一层的适配器负责）。

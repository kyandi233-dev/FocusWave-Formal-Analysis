## 二、P0 问题详述

### L06：B 不读取 producer 的显式状态字段

**证据链（双向闭合）：**

D 分支 `supervised_features.py::summarize_supervised_window()` 产出：

```
pupil_level_{mean,median}_status          -> computable | not_estimable_no_valid_samples
pupil_variability_{sd,mad,iqr}_status     -> computable | not_estimable_low_valid_samples | not_estimable_no_valid_samples
pupil_trend_robust_binned_slope_per_sec_status
                                          -> computable | not_estimable_no_valid_samples
                                             | not_estimable_low_valid_samples | not_estimable_time_support
```

B 分支 `quality_admission.py`：对任何 pupil/NIR `*_status` 字段**零次读取**，改用列名模式 + `n_pupil_valid` 阈值：

```
pupil_diff_mad / pupil_diff_rate_mad_per_sec / pupil_peak_to_trough  -> 最小 2
pupil_slope_per_sec                                                  -> 最小 3
其余 pupil_*                                                          -> 最小 1
```

**两处具体缺陷：**

1. **D 的 `not_estimable_time_support` 被完全忽略**：D 判定某窗口趋势因时间支撑不足不可估计，B 只要 `n_pupil_valid >= 1` 就判为可算，该行进入 missing-aware 集参与建模。
2. **B 的斜率门槛作用在不存在的列名上**：B 为 `pupil_slope_per_sec` 设了 3 帧门槛，而 D 实际产出 `pupil_trend_robust_binned_slope_per_sec`。名称不匹配导致该门槛实际按"其余 pupil_* → 1"生效。

**行为侧的处理是正确的**（读 `sdt_status == "estimable"`，有测试覆盖）。**NIR 侧缺少对应的读取逻辑，是同一设计的不对称实现。**

**修复要求：**
1. B 对 NIR 优先读 D 的 `*_status`，仅在状态字段缺失时回退阈值规则，且回退须标记为降级判定；
2. 修正 B 的特征名清单，与 D 实际列名对齐；
3. 增加测试：`n_pupil_valid` 充足但状态为 `not_estimable_time_support` 时，B 必须判为 `feature_support_invalid`。

### L08：三方 probe 键不一致且无转换层

**证据：**

| 分支 | 主键定义 | 位置 |
|---|---|---|
| A | `("session_id", "block_id", "probe_event_id")`，其中 `probe_event_id` 为**必需列** | `supervised_learning/runner.py` `REQUIRED_PROBE_LOCATORS` |
| B | `("session_id", "block_id", "probe_index_in_block")` | `multimodal_formal/alignment.py` `KEY_COLUMNS` |
| D | `("participant_group_id", "session_id", "block_num", "probe_index_global")` | `nir_formal_analysis/supervised_probe_table.py` `PROBE_ID_COLUMNS` |

B 的别名表 `_PROBE_INDEX_ALIASES` 覆盖 behavior/nir/mmwave/rgb 四个模态，并允许 NIR 用 `block_num` 经 `normalize_block()` → `block_id`。**但 `probe_index_global` 在 B 分支全部文件中出现次数为零。**

**链路后果：**
- D 输出 `block_num` + `probe_index_global`；
- B 需要 `block_id` + `probe_index_in_block`，别名表无 `probe_index_global` → 直接报 `nir_missing_probe_index_column`，返回空表；
- A 需要 `probe_event_id`，而 D 的 `PROBE_ID_COLUMNS` 不产出该列；
- B 的预测归档适配器 `normalize_task_a_predictions` 靠正则 `\|probe\|(\d+)$` 从 `probe_event_id` 反解块内序号，该通路完全依赖 `probe_event_id` 存在。

**此外 `probe_index_in_block`（块内序号）与 `probe_index_global`（全局序号）语义不同，改名无法对齐。**

**测试为何未发现**：`tests/test_task_b_analysis_set_audit.py` 全部数据由 `_tables()` 手工构造，三个模态共用同一份键，从未使用 D 的真实列名。

**修复要求：**
1. 冻结跨分支统一的 probe 键，明确映射规则；
2. 在 D 的输出层补齐 `block_id` 与 `probe_event_id`，或明确由哪层适配器负责；
3. 在 B 增加使用 D 真实 `PROBE_ID_COLUMNS` 构造输入的契约测试。

### L09：预测归档不核验真实标签

**证据：**

`prediction_archive.py::validate_prediction_archive()` 校验了必需列、键唯一、LOSO 归属、取值域、失败行不伪造、model_id 已声明、行落在分析集内、覆盖完整。

**但从未把 `y_true` 与权威标签比对。**

测试直接印证：`tests/test_task_b_analysis_set_audit.py::_prediction_rows()` 把所有行 `y_true` 写成常数 `1`，与 `_prediction_sets()` 的真实标签无关，验证仍返回 `PASS_PREDICTION_ARCHIVE`。

同一问题还有第二面：覆盖检查以 `predictions.groupby("analysis_set_id")` 的**实际出现集合**为循环起点，未与**期望分析集全集**对照，因此"期望两个分析集、实际只输出一个"也会 PASS。

**修复要求：**
1. 归档校验必须把 `y_true` 回联权威标签来源并逐行比对，不一致即报错；
2. 覆盖检查循环起点改为期望分析集全集；
3. 校验标签来源的 `analysis_set_id` 与预测行一致。

## 三、P1 问题要点

### L02：参与者级计分/加权/不确定性未定义

已实现的部分是干净的：`metadata` 显式声明 `outer_method: leave_one_participant_out`、`zero_individual_calibration: True`、`outer_test_outcomes_passed_to_model: False`，并在三处校验训练/测试参与者不相交；`models.py` 只用外层训练行做嵌套选择，评分 `mean_inner_log_loss`，`outer_test` 只在最终重拟合时接触。

**缺口：** 产出终止于逐 probe 预测行，没有 (a) 参与者级计分规则（概率平均/多数投票/加权平均未定）、(b) 参与者级加权规则、(c) 任何置信区间或簇稳健标准误。跨参与者性能变异性无法从当前输出得到。

`reporting.py` 的校验属归档完整性，不涉及计分与不确定性。

**要求**：出结果前冻结计分、加权、不确定性三件事，并写入 1.15.5 正式口径。

---

### L04：`modality_blocks` 与实际列无一致性校验

`feature_schemes.py` 的黑名单是有效的，覆盖三类：标签泄漏、构造混淆（含 Q2 与 omission 变体）、历史与身份字段（**含 `hard_pupil_fraction`，与《NIR问题.txt》的 Task D 边界一致**）。另有 `_FORBIDDEN_SUFFIXES = ("_within", "_between")` 禁止人内/人际分解。

**缺口：** `modality_blocks` 只校验"非空"与"无重复"。`entrypoint.py` 只要求同一 model family 内各候选的声明一致，**从不校验声明与 `columns` 实际归属是否相符**。一个 scheme 可声明 `("nir",)` 而放入行为列且通过校验。

**影响**：M0–M7 的模态构成只能靠人工填写的元数据保证，而非代码保证。

### L05：源证据已修复，时间证据仍未强制

`_source_state()` 在源证据列缺失时返回 `(False, False, "source_evidence_missing")`，配套测试验证覆盖率归零、`missing_kind == "structural_source_missing"`。"数值有限即可用"这条危险通路已堵。

**但仍未强制时间证据**：时间与 QC 是独立列，缺失时静默跳过而非判失败。测试中的 `window_name` 与 `native_qc_valid` 均由测试自行补入。

### L11：支撑链路仍断，双眼切换无处理

**支撑审计函数是完整的**：`audit_supervised_window_support()` 接受 `available_start_ms`/`available_end_ms`，报告截断标记、`available_duration_fraction`、`max_temporal_gap_sec`，且 `automatic_coverage_drop_allowed=False`。

**但 L06 的结论使这条链路失效**：D 算出支撑不足，B 不读 D 状态。函数级实现 ≠ 链路级生效。

**双眼切换问题**：D 的融合规则为 `both → (L+R)/2`、`left_only → L`、`right_only → R`。两眼存在系统性差异，切换点产生约 d/2 的阶跃：

| 特征 | 影响 |
|---|---|
| level | 相对温和 |
| variability（SD/MAD/IQR） | 被直接抬高 |
| trend | 被扭曲，可能造出虚假单调趋势 |

D 记录了 `raw_binocular_source_mode` 但只用于审计输出，不参与特征计算、不分层、不告警。

**要求**：输出逐模式帧数与占比、切换计数；正式分析中作为排除或分层依据需在看过结果前冻结；增加受控合成序列测试。

## 五、NIR 生产端分母核验结论（《NIR问题.txt》要求的第一项）

已在 `runtime/nir-formal/ritnet_fullclass_metrics.py` 确认：

```python
total_pixels = analysis_w * analysis_h            # 默认 320 × 160 = 51200
pupil_fraction      = counts[CLASS_PUPIL] / total_pixels
iris_fraction       = counts[CLASS_IRIS]  / total_pixels
iris_outer_fraction = (counts[CLASS_IRIS] + counts[CLASS_PUPIL]) / total_pixels
# 并断言 counts[0]+counts[1]+counts[2]+counts[3] == total_pixels
```

**判定：`pupil_fraction` 与 `iris_fraction` 来自同一帧、同一眼、同一 analysis domain、同一分母，四类互斥不重复。NIR 1.3 放行条件 1 在字面上成立。**

**但发现两处文档未覆盖的缺陷：**

**缺陷 A — padding 未排除。** `analysis_valid_pixel_fraction` 与 `predicted_in_padding_fraction` 是并行独立 QC 字段，从未参与分母构造。比值对 padding 近似不变，但该近似依赖填充在两类别上一致；在 `roi_clipped` / `touches_roi_edge` 为真的帧上填充会不均匀地吃掉 iris 类像素，比值被系统性抬高。`normalization_valid` 保护的是几何归一化路径，不保护 fraction 比值路径。

**缺陷 B — 字段命名存在生产版本断裂。** `hard_pupil_fraction` / `hard_iris_fraction` 属 fullclass-final 命名；当前 `ritnet_fullclass_contract.py` 声明 `EXTENSION_VERSION = "ritnet-fullclass-v1.2-fast-qc"`，`run_pipeline.py` 全文不含 `hard_*`。适配器把它们列为透传字段，**仓库中没有 `hard_*` → 当前字段的映射表**。

**另需明确语义**：生产端 `iris_fraction` 是纯虹膜类比例，`iris_outer_fraction` 才是虹膜+瞳孔。1.3 公式中"虹膜"指哪一个需写明。

## 七、双轨设计（原始质量轨 + RGB 眨眼掩蔽敏感性轨）

**轨 1（主轨，不变）**：全部 NIR 有效帧，不剔除眨眼；主信号 `pupil_geom_mean_diameter`；30 s probe 前窗口；level + variability + trend。

**轨 2（附加轨，仅敏感性）**：NIR 帧按 `unix_ms` 匹配 RGB 逐帧表，剔除 `blink_closed_bilateral_candidate == True` 的帧，**以及匹配不到 RGB 帧的 NIR 帧（标记不可判定，不默认睁眼）**；同一 30 s 窗口用同一套 level/variability/trend 重算；变异指标同时给 SD/MAD/IQR 三者。

**判定逻辑**（依 1.3 §4.2）：SD、MAD、IQR 方向一致且结论不依赖高 QC 帧窗口 → 支持真实瞳孔变异解释；仅 SD 显效应而 MAD/IQR 不支持且 SD 与异常帧比例相关 → 优先解释为眨眼/遮挡/分割敏感性。

**约束：**
1. 两轨都保留、都输出，不得互替；
2. 掩蔽后必须输出有效帧数、被掩蔽帧数、未匹配帧数；
3. 不因轨 2 结果反向调整轨 1；
4. 阈值 `relative_openness_threshold=0.20`、`minimum_closed_duration_ms=50`、`maximum_closed_duration_ms=1000`、`gap_reset_ms=250`、`maximum_bilateral_relative_difference=0.35` 若要改动须在看过正式结果前冻结。

## 八、R_seg 方法学定位

1. 是 **segmentation-normalized relative indicator（分割归一化相对指标）**，**不是** PIR（pupil-to-iris ratio，瞳孔-虹膜直径比）；
2. **不做平方根变换**——没有独立验证过的虹膜几何直径，套用会制造无物理意义的量；
3. **不得取代** `pupil_geom_mean_diameter` 成为 NIR 主信号；
4. **不得并入 Task D 的 `feature_schemes`**——D 配置已明文禁止，无需修改；
5. 规模不变性只在有限条件下成立：共同尺度可约，但眼睑遮挡使可见虹膜面积减少、瞳孔面积相对保留时比值被抬高，**该抬升不会被共同尺度归一化自动消除**。

| padding 策略 | 明确是否排除；若不排除，给出 `roi_clipped`/`touches_roi_edge` 分层规则 |
| 虹膜语义 | 明确取 `iris_fraction` 还是 `iris_outer_fraction - pupil_fraction` |
| RGB 掩蔽轨 | 按 `unix_ms` 匹配逐帧眨眼候选，输出双轨结果与帧数审计 |
| 审计输出 | 可计算率、分母分布、极端值、与 `pupil_geom_mean_diameter` 的关系、与现有 QC 代理的关系 |
